# iOS 页面优化方案理解稿（架构与UI视角）

## 1. 文档目的
本稿用于将现有《IOS页面优化方案》转换为可执行的产品与技术规范，确保前端、后端、测试对需求理解一致，并为后续开发排期与验收提供依据。

## 2. 核心设计目标

### 2.1 产品目标
1. 重构导航结构：在现有 Tab 架构中新增“照片”模块，形成首页、文件、照片、设置、FRP 等核心入口闭环。
2. 提升关键任务效率：搜索、目录感知、选择/多选、预览、FRP 状态查看等高频操作更直达。
3. 强化管理员能力：用户管理、速率策略、协作空间、日志审计实现管理能力集中化。

### 2.2 视觉与交互目标
1. 统一视觉语言：Toolbar 与 TabBar 风格统一，采用同一代 UI 风格（Liquid Glass）。
2. 强化层次感：大标题（34pt）+ 滚动收缩到导航标题（17pt）的层级过渡。
3. 保持和谐与一致：图标、缩略图、色彩编码、交互反馈在各页面保持统一规则。

### 2.3 性能与可维护性目标
1. 文件列表采用懒加载布局（LazyVStack/LazyHStack）降低渲染压力。
2. 统一使用新的 onChange 闭包形式，规避已弃用 API。
3. 预览能力优先系统原生能力（QuickLook、Live Photo 原生播放链路）。

## 3. 信息架构与导航理解

### 3.1 一级导航（Tab）
1. 首页
2. 文件
3. 照片（新增）
4. 设置
5. FRP（按现有结构保留）

### 3.2 跨模块跳转关系
1. 首页“最近照片-查看全部” -> 照片页
2. 首页“最近文件-查看全部” -> 文件页
3. 设置中的管理员子能力（用户管理、速率高峰时段、协作空间） -> 各自独立子页面
4. 协作空间“文件权限项” -> 指向具体文件权限设置页

## 4. 页面级需求拆解

## 4.1 首页
### Toolbar
1. 左侧大标题“首页”，SF Pro，34pt，粗体，支持动态字体。
2. 上滑后标题平滑收缩并居中（17pt 导航标题形态）。
3. 仅保留搜索按钮（白色），并与文件模块搜索能力对齐。
4. Toolbar 外观与 TabBar 统一为 Liquid Glass 风格。

### Content
1. 存储空间卡片
- 展示真实容量语义：已使用 x / 总容量（后端需提供真实硬盘容量数据）。
- 多色分段进度条表示文件类型占用。
- 底部图例颜色需与进度条严格对应。

2. FRP 概览卡片
- 仅展示：连接状态、FRP 设备。
- 状态枚举：已连接/断开连接。
- 视觉反馈：绿点/红点 + 同步文字颜色变化。
- 右侧文案调整为“FRPC设置”，去掉箭头符号。

3. 功能按钮区
- 删除：上传、新建、分享、智能四个按钮。

4. 最近照片
- “查看全部”跳转到照片模块。
- 缩略图必须限制尺寸，禁止越界或撑破容器。

5. 最近文件
- “查看全部”跳转到文件模块。
- 文件图标/预览按类型映射：图片缩略图、PDF 首页缩略图、电子书/文档使用对应语义图标或首屏预览。

## 4.2 文件
### Toolbar
1. 左侧大标题“文件”，支持滚动收缩（34pt -> 17pt）。
2. 常态按钮：搜索、上传、新建文件夹、更多。
3. 上滑收缩后仅保留：搜索、更多。
4. 目标目录上移到 Toolbar（默认“/”），增强路径感知。
5. 选择相关能力上移到 Toolbar，并新增列表/图标视图切换入口。

### Content
1. 删除目录树（由 Toolbar 目标目录替代层级感知）。
2. 容器替换为 LazyVStack/LazyHStack，优化滚动性能。
3. 缩略图去边框，保持统一尺寸与边界裁剪。
4. onChange API 升级为 iOS 17+ 推荐写法（两参数或零参数闭包）。
5. Live Photo 文件角标规范：左上角 livephoto 图标 + “实况”文本（英文环境后续扩展为 live）。
6. 删除独立“选择按钮”，改为长按触发选择/操作。
7. 长按交互统一：
- 基础操作：contextMenu（复制、删除等）
- 照片项：contextMenu(menuItems:preview:)
- 文档项：QuickLook，使用 quickLookPreview

## 4.3 照片（新增模块）
### Toolbar
1. 左侧“照片”大标题，.primary 颜色，34pt -> 17pt 动画收缩。
2. 右侧增加排序图标与选择按钮。
3. 选择按钮状态切换：选择 -> x，支持多选；点击 x 退出选择。

### Content（列表与详情）
1. 列表页
- 图片显示使用 PHImageRequestOptions 获取静态帧。
- Live Photo 左上角叠加 livephoto 系统图标。

2. 跳转
- 列表到详情传递 PHAsset，避免二次定位资源。

3. 详情页
- 默认先显示静态图。
- onAppear 判定是否 Live Photo。
- 若是 Live Photo，则 requestLivePhoto 成功后替换为 LivePhotoView。
- 进入详情自动播放一次（.full）。
- 长按触发再次完整播放（在 updateUIView 调用 startPlayback）。

## 4.4 设置
### Toolbar
1. 左侧“设置”大标题，34pt -> 17pt 收缩。
2. 右侧搜索仅作用于设置域内，支持快速定位设置项。

### 管理员能力
1. 用户管理（管理员可见）
- 现有“直接添加新用户”控件改为 NavigationLink 进入子页面。
- 字段：用户名、密码、可访问路径、是否允许从根路径访问、权限（只读/读写）、角色（普通/管理员）。
- 若开启“允许从 / 访问”，则“可访问路径”输入禁用。
- 页面底部“创建用户”提交。

2. 速率高峰时段
- 改为 NavigationLink 子页面。
- 限速单位统一为 MB/s（文档中出现 Mbps，建议产品统一单位口径）。
- 使用 DatePicker（hourAndMinute + wheel）配置时段。
- 增加开关控制“是否启用高峰时段”。
- 启用后限速规则生效（文案给定上限 20Mbps，需与 MB/s 规则统一）。

3. 协作空间
- 改为 NavigationLink 子页面。
- 能力项：工作空间名称、添加成员、移除成员。
- 可查看该空间全部文件，并进入单文件权限配置（指定用户：只读/读写）。

4. 日志与审计
- 当前状态保持不变。

## 4.5 FRP
1. “设备状态”语义改为“连接状态”，聚焦 frpc 与 frps 的连接健康。
2. 新增“日志”按钮，支持实时查看 frpc 运行日志。
3. 保留“添加设备”按钮。
4. 将“新的 frpc 设置”改为“修改当前 frpc 设置”，保存后直接写入运行设备中的 frpc.toml。

## 4.6 全局改动
1. 所有浏览页新增显式关闭按钮“x”。
2. 同时保留下滑关闭手势，形成双通道退出机制（按钮与手势并存）。

## 5. 系统架构侧实现建议

### 5.1 组件抽象
1. 建议抽象统一的大标题导航组件（支持滚动收缩、按钮槽位、目录槽位）。
2. 建议抽象统一的文件/媒体缩略图组件（尺寸、裁剪、占位图、失败态）。
3. 建议抽象统一状态标签组件（颜色点 + 文案 + 状态映射）。

### 5.2 数据接口约束
1. 首页存储卡片需新增或对齐容量接口：
- totalCapacity
- usedCapacity
- usageByType（按类型聚合）

2. FRP 状态接口需可返回：
- connectionStatus（connected/disconnected）
- frpc device list（或当前设备）
- 实时日志读取能力（流式或轮询）

3. 文件元数据需支持：
- 文件类型映射
- 缩略图地址或可生成策略
- 文档首页预览能力
- Live Photo 标识

### 5.3 兼容性与平台约束
1. 目标最低系统版本需要与 API 使用保持一致（onChange 新写法、QuickLook、Photos）。
2. Live Photo 与 QuickLook 必须走系统原生通道，降低维护成本并保持系统一致体验。

## 6. 交互与视觉一致性规范（可作为验收基线）
1. 所有一级页面左上角标题均遵循：34pt 粗体 -> 17pt 导航标题收缩规则。
2. 颜色编码必须具备“语义一致性”：同一状态/类型在不同页面颜色不可漂移。
3. 缩略图均有固定尺寸与裁剪策略，不允许内容撑破边界。
4. 所有可浏览详情页均具备“x 关闭 + 下滑关闭”。
5. 管理员能力对普通用户完全隐藏，不可见不可达。

## 7. 风险与待澄清事项
1. 单位冲突：文档同时出现 MB/s 与 Mbps，建议统一为 MB/s 或明确换算规则。
2. Liquid Glass 控件在不同 iOS 版本可用性与回退策略需提前定义。
3. 文档首页缩略图（PDF/Office/Pages）生成链路可能涉及后台转码或本地快速预览策略，需确认成本。
4. FRP 日志实时查看的传输方案（WebSocket/SSE/轮询）需根据现有后端能力确定。
5. 英文化文案尚未落地，建议统一 i18n key 先行，避免后期批量替换。

## 8. 分阶段落地建议
1. 第一阶段（高价值低风险）
- Toolbar 收缩动效统一
- 首页信息精简与状态可视化
- 文件列表性能优化（Lazy 布局）
- 全局 x 关闭按钮

2. 第二阶段（核心体验增强）
- 照片模块完整链路（列表/多选/详情/Live Photo 播放）
- 文件长按菜单 + QuickLook 预览
- 文件类型图标与缩略图策略

3. 第三阶段（管理能力深化）
- 设置页三大管理员子模块导航化改造
- FRP 日志实时能力与 frpc.toml 配置写回
- 协作空间细粒度权限配置

## 9. 验收清单（摘要）
1. 新增“照片”Tab 并完成首页跳转打通。
2. 各页面标题可收缩，视觉表现一致。
3. 首页仅保留搜索与关键状态信息，不再出现被删除按钮组。
4. 文件页目录树已移除，Toolbar 显示当前目录。
5. 长按可执行复制/删除/预览，文档预览使用 QuickLook。
6. Live Photo 在列表有标记、详情可自动和长按播放。
7. 设置页管理员模块以子页面方式承载。
8. FRP 页可看连接状态、可看实时日志、可写回 frpc 配置。
9. 浏览页均可通过 x 或下滑退出。

---
本理解稿结论：原方案本质是一次“信息密度重排 + 导航结构补全 + 管理能力专业化 + 原生媒体体验增强”的中型重构。若按分阶段推进，可在不破坏现有主流程的前提下，逐步完成体验升级与架构收敛。
