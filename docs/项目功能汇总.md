# cloud nest项目功能汇总

## 基础功能
* 用户登录
* 注册由管理员用户决定
* 其他用户的权限由管理员分配，文件的访问权限以及限制可访问的文件范围如：是否允许从根目录开始就可以访问
使用jwt进行鉴权，redis存用户token，可以设置为7天，7天内可以不输入密码，直接登录


## 文件系统
* 目录与路径管理
	* 支持按树形结构展示目录（根目录/团队目录/个人目录）
	* 支持新建、重命名、移动、删除文件夹
	* 支持路径导航（面包屑）、返回上级、快速定位当前目录
* 文件基础操作
	* 支持上传、下载、重命名、移动、复制、删除
	* 支持批量操作（批量下载、批量移动、批量删除）
	* 支持文件压缩与解压（zip）
* 分片上传与断点续传
	* 大文件自动分片上传（分片大小可在设置中调整）
	* 断点续传：网络中断后可继续上传
	* 分片校验（MD5）防止分片损坏
	* 上传进度展示（总进度 + 单文件进度）
* 下载能力
	* 支持单文件下载与目录打包下载
	* 支持断点续传下载
	* 支持下载限速策略（与设置模块联动）
* 媒体与预览
	* 支持常见图片、文本、PDF在线预览
	* 视频支持流媒体播放（边下边播，拖动进度条）
	* 图片支持缩略图预加载，提高列表浏览效率
* 文件元数据与检索
	* 记录文件基础信息：文件名、大小、类型、创建时间、修改时间、所属用户
	* 支持按文件名、类型、时间范围进行筛选
	* 支持按关键字搜索文件/文件夹
* 权限与安全
	* 基于用户角色控制目录与文件访问范围
	* 支持文件级权限（可读/可写/可下载）
	* 非授权用户不可访问目录及其子目录
* 稳定性与一致性
	* 文件上传成功后再写入数据库元数据，失败自动回滚
	* 删除文件时同步清理存储和数据库记录
	* 关键操作保留日志（上传、删除、重命名、权限变更）

## frp
* FRP 接入目标
	* 让家庭/团队内多设备可通过统一入口访问本地文件服务
	* 将内网服务安全映射到公网，减少手动路由和端口映射配置
	* 与系统用户权限打通，避免“有地址就能访问”的风险
* 多设备接入与绑定
	* 支持一台账号绑定多台设备（iPhone、iPad、Mac、Windows 等）
	* 每台设备生成唯一 device_id，便于区分和管理
	* 支持设备重命名、禁用、移除、查看最后在线时间
	* 支持按设备维度限制可访问目录范围（如仅个人目录）
* 自动分配端口
	* 新建设备映射时自动从可用端口池分配 remote_port
	* 端口冲突检测：已占用端口自动跳过并重试
	* 支持端口回收策略（设备解绑/离线超时后回收）
	* 支持手动指定端口（管理员权限）并进行合法性校验
* 域名访问能力
	* 支持子域名模式（如 user-device.cloudnest.xxx）
	* 支持按用户/设备自动生成并绑定域名
	* 支持自定义域名绑定（管理员审核后生效）
	* 支持 HTTPS 证书配置（可选自动续期）
* FRPC 可视化配置
	* 在管理端提供 FRPC 配置页面（服务端地址、token、代理类型、端口、域名）
	* 支持配置项表单校验，避免错误写入
	* 用户保存配置后自动生成/更新 frpc.yaml
	* 支持配置预览与一键复制，便于手动排查
	* 支持版本记录，可回滚到历史配置
* 配置下发与生效
	* 支持配置下发到客户端后自动重载 frpc
	* 支持“先校验后生效”，校验失败时不覆盖旧配置
	* 支持灰度生效（先对单台设备验证，再批量下发）
	* 支持客户端上报生效结果（成功/失败原因）
* 安全与权限控制
	* 每个代理可绑定访问策略（仅本人/团队成员/管理员）
	* 支持 token 定期轮换与失效机制
	* 仅允许白名单协议与端口范围（如 tcp/http/https）
	* 审计日志记录关键操作：创建代理、修改配置、启停代理、删除代理
* 运行状态与监控
	* 可视化展示 FRP 在线状态、连接数、带宽、近 24h 流量
	* 支持心跳检测，异常离线自动告警
	* 支持错误日志检索（按设备、时间、错误码筛选）
	* 支持一键导出诊断信息（frpc 配置 + 最近日志）
* 与后端接口联动（Go）
	* 提供 FRP 设备管理接口：新增/编辑/解绑/查询
	* 提供端口分配接口：申请端口、释放端口、冲突检测
	* 提供配置管理接口：生成 YAML、校验 YAML、下发配置
	* 提供运行控制接口：启动/停止/重载 frpc（按设备）
	* 提供状态查询接口：在线状态、映射列表、流量统计
* 建议最小可用版本（MVP）
	* 第一步：实现设备绑定 + 自动端口分配 + frpc.yaml 自动生成
	* 第二步：实现域名访问 + 基础状态监控
	* 第三步：实现配置回滚 + 灰度下发 + 审计日志

### FRP 全部功能列表（按开发模块）
* A. 数据模型与约束（基于 cloudnest.sql）
	* A1. 设备模型：`device`（user_id、device_name、device_ip、status、create_time）
	* A2. 映射模型：`frp_mapping`（device_id、local_port、remote_port、domain、status、create_time）
	* A3. 配置模型：`frp_config`（device_id、config_text、create_time）
	* A4. 约束校验：`frp_mapping.remote_port` 全局唯一
	* A5. 级联规则：删除设备后自动删除映射（ON DELETE CASCADE）
* B. 设备管理功能
	* B1. 创建设备（绑定当前登录用户）
	* B2. 设备列表查询（支持按 user_id、status 过滤）
	* B3. 设备详情查询（含映射数量、最近配置时间）
	* B4. 设备重命名
	* B5. 设备启用/禁用（status 切换）
	* B6. 设备解绑（逻辑上删除或物理删除二选一）
* C. 映射管理功能
	* C1. 新增映射（device_id + local_port + remote_port/domain）
	* C2. 自动分配 remote_port（端口池范围可配置）
	* C3. 手动指定 remote_port（管理员权限）
	* C4. 端口冲突检测（数据库唯一约束 + 业务前置校验）
	* C5. 修改映射（local_port、domain、status）
	* C6. 删除映射（释放端口）
	* C7. 查询设备下映射列表
* D. FRPC 配置管理
	* D1. 根据设备与映射自动生成 frpc.yaml 文本
	* D2. 配置预览接口（返回 config_text，不落库）
	* D3. 配置保存接口（写入 `frp_config`）
	* D4. 配置历史记录列表（按 create_time 倒序）
	* D5. 配置回滚（将历史配置复制为最新版本）
	* D6. 配置合法性校验（必填项、端口范围、格式）
* E. 运行控制（预留）
	* E1. 启动 frpc（按设备）
	* E2. 停止 frpc（按设备）
	* E3. 重载 frpc（配置变更后）
	* E4. 获取运行状态（在线/离线、最近心跳）
	* E5. 失败原因回传（客户端上报）
* F. 安全与权限
	* F1. 仅设备所属用户或管理员可操作设备/映射/配置
	* F2. 禁止跨用户访问他人设备 ID
	* F3. 敏感配置脱敏返回（如 token 字段）
	* F4. 管理员接口统一走 `/api/admin/*`
	* F5. 关键操作写入操作日志（create/update/delete/reload）
* G. API 设计清单（建议路由）
	* G1. `POST /api/frp/devices`：创建设备
	* G2. `GET /api/frp/devices`：设备列表
	* G3. `GET /api/frp/devices/:id`：设备详情
	* G4. `PUT /api/frp/devices/:id`：更新设备
	* G5. `DELETE /api/frp/devices/:id`：删除设备
	* G6. `POST /api/frp/mappings`：新增映射
	* G7. `GET /api/frp/devices/:id/mappings`：设备映射列表
	* G8. `PUT /api/frp/mappings/:id`：更新映射
	* G9. `DELETE /api/frp/mappings/:id`：删除映射
	* G10. `POST /api/frp/mappings/allocate-port`：自动分配端口
	* G11. `POST /api/frp/configs/preview`：预览配置
	* G12. `POST /api/frp/configs/save`：保存配置
	* G13. `GET /api/frp/devices/:id/configs`：配置历史
	* G14. `POST /api/frp/configs/:id/rollback`：回滚配置
	* G15. `POST /api/frp/devices/:id/reload`：重载 frpc（预留）
	* G16. `GET /api/frp/devices/:id/status`：状态查询（预留）
* H. 异常与边界场景
	* H1. 设备不存在
	* H2. 设备已禁用但仍发起配置/映射操作
	* H3. remote_port 被占用
	* H4. domain 重复绑定
	* H5. 映射为空时生成配置
	* H6. 删除设备时存在历史配置
* I. 测试清单
	* I1. 单元测试：端口分配算法、配置生成、参数校验
	* I2. 接口测试：设备/映射/配置 CRUD 全链路
	* I3. 权限测试：普通用户越权、管理员放行
	* I4. 并发测试：并发申请端口不重复
	* I5. 回归测试：不影响现有文件系统与鉴权流程
* J. 开发规范（FRP 模块）
	* J1. 新增 Go 代码统一添加中文注释（结构体、核心方法、关键分支）
	* J2. Handler 返回统一错误格式（`{"error":"..."}`）
	* J3. 数据库写操作尽量使用事务保证一致性
	* J4. 关键操作必须记录操作日志，便于审计和排障

## Live Photo:
* 基础定义（严格按现有 SQL）
	* 使用 `live_photo` 表存储绑定关系：`id`、`image_file_id`、`video_file_id`、`create_time`
	* `image_file_id` 与 `video_file_id` 都关联 `file.id`
	* Live Photo 仅表示“图片文件 + 视频文件”的关系记录，不额外增加来源状态字段
* 可落地能力（基于现有字段）
	* 手动绑定：传入图片文件 ID 与视频文件 ID，创建 `live_photo` 记录
	* 解绑：按 `live_photo.id` 删除绑定关系，不删除原始文件
	* 详情查询：按 `live_photo.id` 返回 image_file_id、video_file_id 及文件基础信息
	* 列表查询：分页返回 Live Photo 关系（可按用户/目录通过 `file` 表关联过滤）
	* 反查能力：根据文件 ID 查询是否属于某个 Live Photo（匹配 image_file_id 或 video_file_id）
* 权限与安全（结合现有 file 表）
	* 绑定/解绑前校验两个文件的访问权限（读写权限）
	* 只允许文件所有者或具备授权的用户操作
	* 关键操作写入 `operation_log`（绑定、解绑）
* 自动识别（按现有表能力实现）
	* 可提供“同目录 + 同名主干 + 扩展名规则（heic/jpg + mov）”的自动匹配
	* 自动匹配本质仍是批量创建 `live_photo` 关系，不依赖新增字段
	* 匹配失败仅返回结果清单，不强依赖额外日志表

### Live Photo 全部功能列表（按开发模块）
* A. 数据层
	* A1. 使用 `live_photo` 表存储绑定关系（不改表结构）
	* A2. 通过 `image_file_id`、`video_file_id` 关联 `file` 表读取文件信息
	* A3. 去重策略先放在业务层校验（同一 image/video 重复绑定时拦截）
* B. 核心接口
	* B1. `POST /api/live-photos/bind`：手动绑定
	* B2. `POST /api/live-photos/auto-bind`：触发自动识别绑定（按目录或文件集合）
	* B3. `DELETE /api/live-photos/:id`：解绑
	* B4. `GET /api/live-photos/:id`：查询单个 Live Photo 详情
	* B5. `GET /api/live-photos`：分页查询列表（支持按目录/用户过滤）
	* B6. `GET /api/files/:id/live-photo`：根据文件 ID 查询是否属于 Live Photo
* C. 自动识别流程
	* C1. 从 `file` 表筛选候选图片/视频文件
	* C2. 按同目录、同名主干进行配对
	* C3. 校验权限后批量写入 `live_photo`
	* C4. 返回成功/失败统计结果
* D. 客户端联动（iOS）
	* D1. 文件详情接口返回 live_photo_id / image_file_id / video_file_id
	* D2. 支持一键播放 Live Photo
	* D3. 不支持场景自动降级为图片+视频预览
* E. 测试清单
	* E1. 成对文件自动绑定成功
	* E2. 非成对文件不误绑定
	* E3. 重复绑定在业务层被阻止
	* E4. 越权绑定/解绑被拒绝
	* E5. 文件被删除（逻辑删除）后，关系查询行为符合预期

### 建议 MVP（Live Photo）
* 第一步：手动绑定 + 解绑 + 详情查询
* 第二步：列表查询 + 按文件反查
* 第三步：自动识别绑定（同目录同名规则）

## 多人协作:
* 不做实时编辑，采用版本控制的方式，当一个用户保存后生成一个版本，下一个用户可以在新的版本基础上进行修改
* 可主动邀请指定用户来编辑文档文件包含word，excel，txt等格式文件
* 权限 读/写
* 创建团队空间（若使用场景不是家庭是小企业）

## AI:
* AI 引擎与接入方式
	* 对接本地 Ollama（默认模型 `qwen3-vl:4b`），由 Go 后端统一调用 `/api/generate`
	* 支持通过环境变量配置模型名、Ollama 地址、超时时间、项目引导文档路径
	* AI 调用失败时返回明确错误，并记录任务状态（success/failed）用于后续排查
* 图片 OCR 入库与增强索引
	* 支持对图片文件执行 OCR，提取可见文字并入库到 `ai_metadata.ocr_text`
	* 入库时优先读取 EXIF 信息（GPS、拍摄时间、相机品牌/型号、海拔）并写入可检索标签/描述
	* 支持用户补充 `location`、`landmark`、`tags`、`description` 与 EXIF 信息合并索引
	* 对“文档照片”额外生成关键点摘要（doc_summary），用于列表预览与快速检索
* 智能搜索（结构化）
	* 支持按关键字、文件类型、地点、地标、时间范围进行组合检索
	* 检索范围包含：文件名 + OCR 文本 + 标签 + 描述
	* 文件类型支持语义映射：
		* image/photo/图片/照片 -> 图片类型集合（jpg/jpeg/png/gif/webp/heic/heif）
		* document/doc/文档/票据/发票 -> 文档类型集合（pdf/docx/xlsx/pptx/txt/md/csv/json/xml/yaml/yml）
	* 检索结果返回 `ocr_snippet` 和 `has_ocr_index`，便于前端直接展示命中片段
* 智能搜索（自然语言）
	* 新增自然语言检索接口，可直接输入“我想看我在天津旅游的照片”“帮我找 MacBook 发票”
	* 流程：先由模型把问题解析为结构化条件，再复用统一检索逻辑返回文件列表
	* 解析失败时启用本地兜底规则（如“天津/旅游/照片/发票/MacBook”等关键词）保障可用性
* 文档摘要与多格式支持
	* 支持 `txt/md/json/xml/yaml/yml/csv/log/sql/go/swift/java/py/js/ts/html/css` 文本类文档摘要
	* 支持 `pdf` 文本抽取与摘要
	* 支持 `docx/xlsx/pptx`（OpenXML）文本提取与摘要
	* 摘要结果与正文索引回写 `ai_metadata`，支持后续按关键词直接命中文档内容
* AI 助手与设置联动
	* 提供项目问答接口：可加载项目操作文档，按“系统能力+文档内容”回答用户问题
	* 提供 AI 辅助设置修改接口（管理员权限）：可新增/更新 `system_setting`
	* 设置变更会写入 `operation_log`，保留审计记录
* 权限与安全控制
	* OCR/摘要/搜索均复用文件访问权限校验（文件所有者或被授权用户）
	* 非授权用户无法读取他人文件内容或其 AI 索引
	* AI 设置修改接口仅管理员可用
* AI 相关接口清单（当前后端）
	* `POST /api/ai/ocr`：图片 OCR + 索引入库
	* `GET /api/ai/search`：结构化智能搜索
	* `POST /api/ai/search/nl`：自然语言智能搜索
	* `POST /api/ai/summarize`：文档摘要与索引更新
	* `POST /api/ai/assistant/ask`：项目问答助手
	* `POST /api/ai/assistant/settings`：AI 辅助设置修改（管理员）

## 其他:
* 回收站（基于 `file.is_deleted`）
	* 删除文件/目录采用软删除：将 `file.is_deleted` 置为 1
	* 回收站列表：查询 `is_deleted=1` 的文件，结合 `filename/user_id/update_time` 筛选
	* 恢复文件：将 `is_deleted` 置回 0
	* 当前表结构可记录删除时间（`update_time`），但不能记录删除人/原始路径变更历史
	* 彻底删除可在业务层执行物理删除（数据库删除 + 存储删除）
* 文件分享（基于 `share`）
	* 支持创建分享记录：`file_id`、`user_id`、`share_code`、`expire_time`
	* 支持通过 `share_code` 访问分享资源，并校验 `expire_time`
	* 支持分享列表查询与手动失效（删除 `share` 记录）
	* 当前表结构未包含提取码、访问次数、访问日志字段
* 上传分片与断点续传（基于 `upload_task` + `upload_chunk`）
	* 上传任务初始化：写入 `upload_task`（`upload_id`、`chunk_size`、`total_chunks` 等）
	* 分片状态跟踪：写入 `upload_chunk`（`upload_id` + `chunk_index` 唯一）
	* 断点续传：根据 `uploaded_chunks` 与 `upload_chunk.status` 继续上传
	* 上传完成后更新 `upload_task.status=1`，并创建/更新 `file` 元数据
	* 当前库表主要覆盖“上传”链路，不直接覆盖下载分块任务管理
* 限速（基于 `system_setting`）
	* 支持配置系统级限速参数（如 `upload_speed_limit`、`download_speed_limit`）
	* 支持配置高峰时段限速参数（`upload_peak_speed_limit_kbps`、`download_peak_speed_limit_kbps`）
	* 支持用户自定义高峰时段（开始/结束时间），未配置时回落系统默认高峰时段
	* 支持配置分片阈值、默认分享过期时长等全局参数
	* 运行时按 `setting_key/setting_value` 读取并生效
	* 取消用户级限速策略开发（当前阶段不实现按用户差异化带宽）

### 其他功能清单（按开发模块，严格基于现有表）
* A. 回收站模块（`file`）
	* A1. 软删除：更新 `file.is_deleted=1`
	* A2. 回收站列表：按 `is_deleted=1` 查询
	* A3. 恢复：更新 `file.is_deleted=0`
	* A4. 清理：物理删除已软删除文件（业务定时任务）
* B. 分享模块（`share`）
	* B1. 创建分享：生成并写入 `share_code`
	* B2. 校验分享：按 `share_code` 查询并校验 `expire_time`
	* B3. 分享管理：按 `user_id` 查询我的分享
	* B4. 失效分享：删除 `share` 记录
* C. 上传任务模块（`upload_task`、`upload_chunk`）
	* C1. 创建上传任务与分片参数
	* C2. 分片上报与状态更新
	* C3. 断点续传与缺失分片补传
	* C4. 合并完成后写入 `file` 元数据
* D. 系统设置模块（`system_setting`）
	* D1. 设置上传/下载限速参数
	* D2. 设置高峰时段窗口（系统默认 + 用户自定义）
	* D3. 设置分片阈值与默认分片大小
	* D4. 设置默认分享过期策略
	* D5. 统一读取配置并下发到上传/分享模块

### 需新增表后再支持的能力
* 回收站删除人、原始路径快照、恢复冲突处理记录
* 分享提取码、访问次数限制、访问日志审计

### 建议 MVP（按现有库优先）

* 第三步：系统设置接入限速与分享默认策略（`system_setting`）

## 设置
* 基础设计（严格按现有 SQL）
	* 全局配置统一使用 `system_setting`：`setting_key`、`setting_value`、`description`
	* 文件访问权限读取 `file_permission`（read/write）
	* 用户角色与管理权限读取 `user_role` + `role`
	* 团队空间成员权限读取 `workspace_user.role`
* 可直接落地能力（基于现有表）
	* 分片阈值设置：如 `upload_chunk_threshold_mb`、`upload_default_chunk_size_mb`
	* 分享默认有效期设置：如 `share_default_expire_hours`（0 表示无限制）
	* 上传/下载全局限速设置：如 `upload_speed_limit_kbps`、`download_speed_limit_kbps`
	* 上传并发数设置：如 `upload_max_concurrency`
	* 回收站保留天数设置：如 `recycle_retention_days`
	* 权限展示聚合：在设置页统一展示角色权限 + 文件权限规则（数据来源为 `role/user_role/file_permission/workspace_user`）
* 建议接口（基于现有表）
	* `GET /api/settings`：读取系统配置（`system_setting`）
	* `PUT /api/settings`：批量更新系统配置（管理员）
	* `GET /api/settings/permissions`：聚合展示角色、空间、文件权限规则
	* `GET /api/settings/rate-window`：读取当前用户高峰时段配置
	* `PUT /api/settings/rate-window`：更新当前用户高峰时段配置
* 需新增表后再支持的能力
	* 配置变更历史（谁在什么时间改了什么）
	* 配置回滚与版本管理
	* 多环境配置（开发/测试/生产）隔离
	* 用户级个性化设置（如个人主题、个人默认分片大小）

### 设置模块清单（按开发模块）
* A. 系统配置管理（`system_setting`）
	* A1. 配置键白名单校验（仅允许约定 key）

	* A3. 批量读取/批量更新配置
	* A4. 启动时加载与运行时热更新
* B. 权限配置展示（`role`、`user_role`、`workspace_user`、`file_permission`）

	* B2. 展示用户-角色关系
	* B3. 展示协作空间成员角色
