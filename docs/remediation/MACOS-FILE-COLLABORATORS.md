# 原生单文件协作者

个人文件列表的「协作者」工具栏和右键入口可查看当前文件的授权。文件所有者可按现有账户用户名添加只读/读写协作者，确认后调整权限或撤销；其他可读账户仅能查看列表。空间文件沿用空间角色管理，不提供这个入口。文件夹授权不自动继承到子项。

文件响应新增读取已有的 `user_id` / `workspace_id`，不变更服务端表或文件协议。缺失所有者资料时不推定管理权。协作者记录绑定请求的文件 ID，旧文件选择不能被提交到另一文件。服务端仍在文件锁事务内重新检查当前所有者、有效空间范围和目标账户；本地控件不代替鉴权。

## 条件变更与兼容

- `POST /api/files/:id/collaborators` 支持可选 `create_only: true`；已存在的授权返回 409，不自动覆盖。
- 同一 POST 的权限调整及 `DELETE /api/files/:id/collaborators/:user_id` 支持可选 `expected_permission: "read" | "write"`，在文件锁中比较当前有效授权，再修改全部匹配行并写入审计。授权已变化或消失返回 409；无效条件为 400。条件不能与 create-only 同时使用。
- 旧 POST upsert 和无正文 DELETE 保留原行为；不需要数据库迁移。历史重复授权按 read/write 并集显示为一个账户，条件降级更新全部重复行，撤销删除全部重复行。无法识别的权限或同一 ID 对应不同用户名不会被客户端静默转换。
- 读写协作者可以修改内容，但不能邀请/改派/撤销其他协作者。条件比较的是当前权限值，不是变更历史版本；不承诺识别值已恢复原状的中间操作。

原生列表采用身份绑定、替换请求取消和响应代次检查；读取失败清除旧姓名，403 保留有效登录。保存发生 409 后锁定旧表单，须关闭、刷新、重新确认。没有成功回执的写入不自动重发；本窗口阻止盲目重复，重新打开后先核对服务器记录。这里没有持久写入意图，丢回执/崩溃后的完整恢复矩阵仍属 G10。
