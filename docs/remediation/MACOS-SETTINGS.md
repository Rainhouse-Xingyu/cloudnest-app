# 原生系统设置与个人高峰时段

侧栏设置页读取系统公开配置和当前账户高峰时段。普通账户只查看系统配置，管理员可逐项编辑；个人时段按服务器本地时间支持跨午夜和全天。关闭个人高峰不会取消系统高峰限制，也不是删除个人配置或恢复继承。速率仍按既有服务端规则叠加收紧，不提高管理员上限。

系统配置只展示已有 14 项允许的键，以明确的小时、天、MiB、KiB/s、字节和数值范围输入，不展示任意私有设置键或其他用户配置。未显式配置的键显示为空缺，不伪造数据库默认值；无效旧值可以由管理员核对并更正。设置由服务端与支持对应选项的客户端执行，不宣称原生分片/并发策略会动态使用所有历史选项。保留天数和配额编辑不会立即删除历史文件。

## 条件写入与兼容

`GET /api/settings?scope=system` 对管理员同样仅返回公开允许键，并明确 `conditional_writes=true`；原无查询的 GET 响应保持不变。未知 scope 返回 400。原生读取限制 64 KiB/14 项、拒绝重复或未知键；未确认条件能力时不开放编辑。

`PUT /api/settings` 新增可选 `expected` 对象，键集合必须准确等于本批写入键。值为读取时的原始字符串，JSON null 表示该键不存在。省略/null 保持旧无条件协议；空对象不是有效非空批次的基线。服务端在既有全局策略锁和写入/审计事务中比较，冲突 409，不写设置或成功审计。所有其他正常设置写路径继续使用同一个策略锁，比较不会先读后无锁保存。

`GET /api/settings/rate-window` 新增六键 `expected`，仅包含三项系统时段和本账户三项个人时段，包含缺失项的 null，不包含他人配置。一条 SELECT 提供一致快照，原 enabled/start/end/source 继续返回。PUT 可选携带这六键，服务端严格限制键集合并在同一锁事务内比较；相关系统时段改变也会使旧表单冲突。原不带 expected 调用仍兼容。无 schema/单调 revision 变更，这是内容比较，不能识别内容恢复为原值的 ABA。

原生保存前确认具体字段、原/新值、时段和作用。服务器/账户身份在提交时再次核对。409 锁住旧表单，须关闭、刷新和重新确认；未知回执不自动重发，同表单禁止重试。参数拒绝可纠正。无持久幂等 journal，崩溃后的未知写入仍需人工刷新核对，完整故障矩阵留 G10。
