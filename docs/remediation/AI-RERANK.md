# 有界重排与验证边界

2026-10-29：v1 六类实际评估中，电脑发票的 Recall@5 只有 0.75，采购合同和评测可排在已付款票据之前。新增可选重排后，该已暴露基准的发票 Recall@5 提升到 1.0；完整质量验收仍在进行，不能据此宣布 G04 完成。

## 实现

`AI_RERANK_MODEL` 默认为空，保留原混合顺序。显式配置已安装的 Qwen 兼容二分类模型后，成功取得查询向量且候选超过一条时，对已授权、已复核的前 20 个文件逐对评分。模型看到实际文件名和选中块正文；日期已由 SQL 过滤的套话使用与查询向量相同的分离规则。未评分尾部保留原顺序，200 条候选窗口及分页总数不因重排而缩小。

模型调用要求真实 yes/no 两个 token 的 logprob；缺少任一项、非法字节/分数、错误模型身份、未完成或多 token 输出均拒绝。使用稳定二项归一化，仅作为当前查询内的排序分数，不是经过校准的相关概率。输入控制 token 转义；不把文件内容或模型输出作为授权指令。

重排整批共六秒，与 OCR/图片分析共享两个无队列推理名额，嵌入原搜索二十秒总期限。成功后确认模型 digest；任意失败不发布部分分数，保持原 RRF 顺序并返回 `rerank_unavailable` 与有限的失败原因。请求自身取消/超时返回错误。无论成功还是回退，推理后再次复核所有候选的权限、文件身份、源及索引代次。

公开响应保留 `retrieval.mode=hybrid` 和原 RRF `score`。新增 `retrieval.rerank`：status（disabled/skipped/applied/fallback）、model、model_digest、evaluated_count、window_size、window_limited、failure_reason；仅成功评分的项新增 `rerank_score` 和 `match_sources=rerank`。没有统一 0.5 阈值，也没有移除低分结果。

## 全链路 v1 回归结果

[真实 API 报告](AI-RETRIEVAL-RERANK-20261029.json)，代码 `508a54ea01838c855fbca9565bd3aa66cff7d4b8`，清单未改变，Ollama 0.31.1 / qwen3-vl:4b；30/30 文件从实际上传重新索引，24/24 查询执行，**PASS 296.575s**（函数 294.58s）。15 条多候选查询全部实际 applied、无 fallback；三条单候选照片查询及六条空结果负查询无需重排。六项授权/共享/撤权/日历/回收/模型故障边界通过。

dev 与已暴露 heldout 的 Recall@5、MRR@10 均为 **1.0**，负例分别 3/3 为空。全部正例 Recall@1=0.45、Recall@3=0.85、Recall@5=1、Precision@5=0.60、MRR@10=1。发票族从前一轮 Recall@5=0.75 / MRR@10=0.8333 提升至 **1 / 1**：三种表述的四份票据均排在合同/评测之前。Precision@5 分母固定五，0.60 是本合成集相关文件数量决定的理论上限，不是全库准确率。

15 条实际重排 API 查询耗时 min/median/max 为 **1.344 / 2.576 / 5.722 秒**；这是整次查询时间，包括 embedding/SQL/重排，且在刚完成视觉索引的机器上串行测得，不能外推冷启动、并发或生产 SLA。18 对预检曾有冷调用超过六秒；默认仍关闭，部署须选择模型并测量。

**尚未解决的具体例子：**合同查询仍在末尾返回会议纪要（分数约 0.027–0.061）；发票查询仍在末尾返回合同/评测（约 0.023–0.078）；宽泛配置表述中含 IP 的扫描发票得分 0.967，仍插在两个真正配置之间。权限查询存在真实相关文件分数约 0.049，因此没有用统一阈值掩盖这些误匹配。每轮视觉模型重跑，跨轮提升不是固定视觉输出消融，也不是独立泛化证明。

先以 `3609763d0f023724fd455e79c1b948d0c0f4f45b` 冻结 48 文件/24 查询的 stress-v2 清单，再执行实际上传、索引和搜索；清单 SHA-256 `a60973d6b4b4d6ee7cab5fa1df732526e53af61f8a6669c18f4c9a70e2da9776`。它保留 v1 的 30 份输入并增加 18 份相近技术/状态/实体干扰；查询换成更具体的条件，原质量门槛不变。它是可见的合成扩展测试，不是盲测或新的独立视觉语料。

[完整失败报告](AI-RETRIEVAL-STRESS-V2-20261029.json)：**FAIL 340.159s**（函数 339.24s），completed=true / passed=false。48 文件与 24 查询全部实际执行，dev/heldout 的正例 R@5 和 MRR 均为 1，但负例空结果分别 **0/3、1/3**；此外首条 PostgreSQL 迁移查询重排六秒超时，按设计保留完整混合排序，评估器仍将其判为重排失败。共 19 applied / 1 timeout fallback / 4 单候选或空结果 skipped。六项权限/共享/撤权/日历/回收/故障降级边界通过。
