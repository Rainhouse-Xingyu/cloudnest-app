# 缩略图解码资源边界（G03）

2026-10-24。本批针对 FILE-025 中图片全像素解码无准入的问题；不是持久缓存磁盘预算，也不是 G03 全部验收。原实现对已授权且已校验源直接 image.Decode；小体积图片可以声明极大的像素尺寸，并发请求没有解码数量限制。修复前真实 API 对只有有效 IHDR 的超限 PNG 返回通用 500；现在在像素解码前返回明确 413，不需要为复现分配超大位图。

## 请求行为

沿用文件权限、对象 Pin、完整 SHA-256/尺寸校验和源摘要缓存键。权限先于资源错误；授权后的数据库尺寸已超过上限时，在完整源哈希前拒绝。已打开的源 FD 再检查实际尺寸，解析图片头并验证维度。不存在按扩展名选择不受控解码器的旁路：只显式调用 Go 标准库 JPEG、PNG、GIF 解码器，GIF 只解第一帧，不调用 DecodeAll。WebP 等仍没有缩略图解码支持，现返回 415；原始图片下载/预览能力不受此项限制。

| 边界 | 当前值 / 行为 |
|---|---|
| 完整源编码体积 | 最多 64 MiB；超过返回 413，不删除源文件 |
| 配置头读取 | 读取预算 1 MiB；耗尽预算返回 413 |
| 单边 | 最多 16,384 像素，宽高必须为正 |
| 总像素 | 最多 24,000,000，例如 6000 × 4000；先除法判界，避免乘法溢出 |
| 每进程活动构建 | 最多 2 个，共享于该进程中的所有 handler/router |
| 每进程估算工作集 | 最多 512 MiB；每项按宽 × 高 × 16 字节 + 16 MiB 计入 |
| 等待者 | 最多 16 个，等待最多 1 秒；容量/等待超限返回 503、Retry-After: 1 |
| 构建期限 | 15 秒协作式期限，覆盖头解析、准入等待、解码、缩放、编码与发布前检查 |

这些限制为服务端固定策略，请求 size 不能提高源输入限额。输出尺寸沿用已有 64–1024 范围及旧参数回退规则。24 MP 是当前服务处理边界，不表示更高像素的原文件不能上传或下载。新的 413/415/422/503 分别表示资源上限、不支持格式、损坏图片编码与暂时繁忙；源对象完整性失败仍为既有 409。

内存数值是**准入估算，不是 OS/RSS 硬上限**。两个最大图片不能同时占用预算；小图片可并发两个。GC、解码器内部临时对象、源哈希、HTTP 响应及其他业务内存没有因此获得统一硬上限。多进程/多副本各有独立预算，尚无全主机/集群内存预算或公平排队保证。

## 取消与缓存

读取源、缩放每一行、编码写入和最终发布前检查请求 context；不会为了超时而启动脱离请求继续运行的解码 goroutine。准入持有到同步构建结束，各错误路径释放。标准库解码器内部 CPU 循环、文件 Sync 以及阻塞系统调用只能在下一个检查点感知取消，15 秒不是强制杀进程/实时 CPU 上限。源的预哈希在构建期限前，受请求 context 和源体积限制，聚合 IO 准入仍待做。

先解析/检查源配置再查询缓存，旧缓存不能绕过新的输入边界。v3 唯一缓存代次确保同键只有一个生成者，其他请求在有界等待内重新查询结果。已采用 v3 登记/事务发布，见 THUMBNAIL-CACHE；输出算法和并发/同秒版本更新/强 ETag/条件请求回归继续保留。

后续已实现新缓存的持久磁盘/条目/变体共同预算、TTL/FIFO 淘汰、生成临时登记与受控生命周期，详见 [缓存协议](THUMBNAIL-CACHE.md)。旧未登记缓存仍不扫描删除、不自动认领，FILE-020 的历史文件/恢复范围继续保持未完成。

## 验证边界

新增单元覆盖维度/乘法边界、估算预算与活动数、16 等待者拒绝、取消/超时/释放、头读取上限、编码体积上限、取消不写缓存及解码后的几何不一致。真实 API 覆盖超限 PNG 头、损坏编码/未知格式、JPEG/PNG/GIF 实际解码和 JPEG 尺寸/摘要/304、源权限、旧缓存不能绕过以及实际 64 MiB + 1 字节稀疏源保留。另保留既有并发缓存与同秒版本更新测试。

全部执行结果记录在 TESTING.md。没有把小图片功能测试当作大图片吞吐或峰值 RSS 基准，也未执行故障解码器沙箱、实际 24 MP 峰值内存、进程强制隔离与多副本压力验收。本批不新增数据库字段、不引入第三方解码库；未合并 PR、部署服务或操作生产数据。
