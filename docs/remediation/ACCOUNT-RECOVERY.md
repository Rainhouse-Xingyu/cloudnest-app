# G01 账号恢复与会话撤销

本功能是服务端操作者维护能力和用户自身会话操作。没有开放匿名密码重置 API，也没有邮件找回流程。未对真实账号执行重置；以下部署操作由有目标环境权限的操作者审核后执行。

## 存储与认证规则

用户表新增 `auth_version BIGINT UNSIGNED NOT NULL DEFAULT 0`。新 JWT 携带账号当时的版本；每次请求同时验证签名、期限、Redis 会话归属、当前账号状态以及数据库当前版本。旧 JWT 没有该字段时按 0 处理，因此升级本身保持未撤销账号的旧会话兼容。

密码重置或退出全部会话在 MySQL 事务内递增版本，并写审计。版本不匹配返回 401，即使旧 Redis 键仍存在或旧登录请求在撤销之后才写入 Redis，也不能恢复访问。旧键按原 TTL 到期，无需全库扫描/删除 Redis。撤销以事务提交及后续认证检查为界；已通过检查的在途请求/下载不会被强制中断。公开分享链接也不是登录会话，需要单独撤销。

## 显式升级

1. 停止旧版本所有服务实例，备份数据库与必要配置，核对目标库，审核本次迁移。不要让不检查 auth_version 的旧实例继续接收请求。
2. 使用新程序执行 `./cloudnest migrate`。当前仍为显式 GORM AutoMigrate，包含全部模型，尚不是版本化迁移工具；本次新增字段为加法迁移。真实库结构与模型差异必须先在其备份副本演练。
3. 启动新版本。普通启动只检查认证字段，缺少 auth_version 会退出并提示显式迁移，不自动修改结构。
4. 需要恢复的账号逐个执行下述命令。已有数据、角色、禁用状态均保留。

隔离 MySQL 测试实际移除测试库 auth_version 来模拟旧结构，再显式迁移，核对用户数量、密码、状态保持及初始版本为 0；重复迁移不会清零已有撤销版本。这不替代真实数据库备份恢复演练。不能直接回滚到不检查版本的旧程序，否则会失去新撤销语义；任何应急降级需停服、审核且轮换签名密钥，保持现有数据字段。

## 操作者恢复密码

用 `./cloudnest reset-password <用户ID> <精确用户名>` 指定目标，从标准输入提供新密码。用户名在锁定账号后按字符串精确比较，避免数据库不区分大小写的排序规则造成误选。目标不存在/用户名不匹配/密码校验失败都非零退出。

新密码为 14–72 字节，不允许首尾空白、换行、NUL 或示例占位值。使用独立随机密码。程序拒绝直接从可回显的终端读取；只接受管道/受保护文件，不接受密码命令参数或密码环境变量。

例如在 **Bash** 中（将示例 ID 和用户名替换为核对后的目标；不在开启 shell tracing 的环境执行）：

```bash
read -r -s -p 'New password: ' cloudnest_recovery_password
printf '\n'
printf '%s\n' "$cloudnest_recovery_password" | ./cloudnest reset-password 42 alice
cloudnest_reset_status=$?
unset cloudnest_recovery_password
if [ "$cloudnest_reset_status" -ne 0 ]; then
  printf 'Password reset failed; inspect the non-secret error above.\n'
fi
unset cloudnest_reset_status
```

命令使用现有 MYSQL_DSN / JWT_SECRET 配置校验和 `.env` 加载规则，不需要 Redis 在线。事务中写入 bcrypt、递增版本、写 `operator_password_reset` 审计；任何一项失败全部回滚。日志/审计不记录新旧密码或散列。该命令不会启用禁用账号、添加管理员角色、删除文件或批量改写其他用户。操作者需自行核验身份并通过安全渠道交付密码。

不要通过直接 SQL 改 password 绕过会话版本和审计；泄露的 JWT 签名密钥、MySQL/Redis 凭据仍需单独轮换，本命令不能修复密钥泄露。

## 用户退出全部会话

`POST /api/auth/logout-all`，Bearer 当前有效 Token，无必需请求体。

- 200：当前用户全部登录会话已撤销，包含本次调用 Token；客户端清除本地登录状态并重新登录。
- 401：没有有效会话或账号不可用；不能用已经撤销的 Token 重试。
- 503：事务/审计失败，撤销未完成；保留可重试状态，不宣称成功。

该路由属于精确的自身会话能力，自定义业务权限不会阻止它。请求体中的 user_id 等字段不会选择其他用户；管理员 Token 也只撤销自己。`POST /api/auth/logout` 仍只注销当前 Token。重复退出全部会话不会扩大作用范围，已失效 Token 再次调用返回 401。

## 验证与后续范围

覆盖真实多会话、无 JTI/无版本的历史 Token、模拟延迟 Redis 写入、其他用户隔离、自定义路径权限；实际编译并运行维护命令；目标不匹配/弱密码/不存在账号失败；恢复后旧密码/旧 Token 拒绝、新密码可用、文件和角色保留、禁用状态不变；审计写入故障时密码及版本事务回滚；历史明文账号受控恢复；旧结构加法迁移与重复迁移。

后续账号自助改密、逐会话列表/撤销、认证异常告警及设备凭据撤销需要独立实现。本轮不把账号会话撤销视为已完成 G05 设备身份管理。

G02 版本另需审计后显式执行 `migrate-file-names`，启动会验证活动名称约束与迁移记录；这是首个独立版本化迁移，基础 `migrate` 仍为 AutoMigrate。见 [升级边界](FILE-NAME-MIGRATION.md)。
