# G01 首批安全整改

日期：2026-10-21。基于 G00 分支，保留 MySQL/Gin/GORM 架构。此批次是安全基础修复，G01 的全部验收、G02–G11 和生产上线尚未完成。

## 修复行为

- 启动必须提供非占位 JWT 密钥和数据库配置；JWT 必须携带有效过期时间及一致的用户身份。无密钥时在数据库连接和创建数据目录之前退出。
- 普通启动不再 AutoMigrate 或播种默认管理员。新增显式 `migrate` 与仅空用户表可执行的 `bootstrap-admin`；事务创建 bcrypt 密码及角色，不提升或覆盖既有用户。
- 拒绝明文密码及旧 admin/admin 登录；不静默改写旧密码。注销的 Redis 错误返回 503，不再伪报成功。
- 每个请求检查 Redis 会话归属、当前用户状态和管理员角色；禁用、删除用户、撤销管理员权限即时生效。路径权限以数据库当前值为准，不接受旧缓存授权；普通用户仅允许显式方法/路由模板，未知 API 默认拒绝。
- 文件版本事务锁定目标，重新检查写权限，并要求 storage_id 对应调用者拥有的未删除普通文件。共享只读来源、孤立对象、已删除来源不构成上传能力。仅允许编辑者发布自己已上传的对象；后续用范围受限的版本上传票据替代旧协议。
- 版本大小来自存储对象，客户端不一致 size 被拒绝；旧 base_version 返回 409，跨用户来源返回 403，禁止错误分支落库。
- MySQL 日志参数化并抑制常规 not-found 噪声；登录 JSON 限制 16 KiB，HTTP 请求头超时 10 秒、空闲连接超时 120 秒。大文件读写总时长不在此批统一限制，分片资源预算留给 G03。
- Go 升级到 1.26.10，x/net 0.60.0、quic-go 0.59.1；按 x/net 的最低依赖同时升级 x/text 0.42.0、x/crypto 0.57.0、x/sys 0.48.0。没有无关全量依赖升级。

## 运维兼容性与待审事项

本批没有操作实际数据库、实际账号或实际文件。已有 JWT 必须更换签名密钥才能整体失效；已有泄露的数据库/Redis 凭据必须由操作者轮换。拒绝历史密码可能使旧账号无法登录，需要备份后由有数据库管理权限的操作者审核重置方案，不能删除用户再 bootstrap。部署步骤见 [后端启动指南](../../cloudnest_go/docs/部署打包与命令行启动.md)。

`migrate` 只是将原有 AutoMigrate 改为显式执行，尚未提供版本化迁移和真实数据升级/回滚演练。此批未修改已有表结构。按请求读取身份/角色/路径权限增加数据库查询，性能压测在 G10；不能为了缓存性能退回陈旧授权。

FRP 独立设备身份、配置加密、登录限流、密码自助重置/会话管理、完整存储引用/配额/上传幂等、协作权限矩阵仍未完成。生产安全不因本次扫描无可达漏洞而被保证。PR 需人工审查上述兼容性变化；不自动合并或部署。
