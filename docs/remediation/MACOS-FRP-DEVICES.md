# 原生 FRP 设备管理与退役

设备列表新增添加、编辑、右键退役与退役筛选。新增默认为启用，名称和地址只是管理资料，不代表 Agent 在线、已注册或隧道启动。编辑可更名、修改/清空地址以及启用/停用；原有设备详情、映射、配置和命令入口继续调用真实 API。

## 并发与旧客户端

原生编辑请求带已读取的 device_name、device_ip、status 内容基线。后端在同一授权/设备写事务内取得锁后核对当前三字段，不同则 409，既不覆盖更新也不新增审计。客户端要求关闭、刷新后重新编辑，不自动重试。该基线是字段内容比较，不是数据库单调版本号；未提供 expected 的旧请求保持原有行为，不宣称所有旧客户端都获得并发保护。

新增 clear_device_ip=true 明确清空地址，与非空 device_ip 同时提交会拒绝。旧请求中的空 device_ip 仍是忽略该字段，不改变既有协议语义。没有新增表/列、隐式迁移或放宽权限。名称、地址、状态、基线及返回身份有界校验；用户/服务器确认在写前检查，既有原 token 封装拒绝旧会话迟到结果。

新增设备没有持久幂等键，保存结果不明需关闭并刷新核对，当前表单不允许盲目重发。参数/权限/限流明确拒绝可纠正后重试。退役同一窗口防重复提交，结果不明需核对在用及退役列表，不将无回执当成未执行。

## 退役和保留

原生确认框标明设备名/ID，解释撤销凭据、取消未完成命令、保留配置/历史/资源占用。退役不自动释放端口，也不证明离线 frpc 已停止；重新接入须创建并注册新设备。继续使用已有后端退役事务和触发器，不增加物理删除入口。

退役筛选调用已有 retired=1 API，切换、离页取消原请求，以请求代号和会话身份拒绝迟到结果。响应错误清空旧列表；退役记录只提供详情，不能在客户端重新启用或发运行命令。保留详情展示实际退役时间、映射数和最近配置时间，明确只展示元数据，不冒充完整历史正文浏览。
