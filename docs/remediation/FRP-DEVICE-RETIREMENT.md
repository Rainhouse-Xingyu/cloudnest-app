# 设备退役、历史保留与写入授权

原 `DELETE /api/frp/devices/:id` 只删除设备行，注释却宣称存在关联级联删除。它会留下映射/配置/命令记录，原设备所有者又无法通过设备归属检查访问这些记录；设备更新/删除的权限判断也在写事务之外。本批将设备删除定义为**退役**，不会物理清除关联数据或假定远端端口已经释放。

## 对外行为

- `DELETE /api/frp/devices/:id` 返回 200 和 `{"message":"retired","retired":true,"reservations_retained":true}`。HTTP 成功状态保持兼容，响应明确告知预留尚未释放。
- 默认设备列表、详情、映射/配置列表和执行入口不再返回退役设备。对已退役 ID 再次删除、更新或重新注册失败，不能通过 `status=1` 恢复旧身份。
- `GET /api/frp/devices?retired=1` 仅列出调用者可见的退役设备；管理员仍按既有权限查看全部。`GET /api/frp/devices/:id?retired=1` 返回归属授权后的退役元数据、保留映射数量和最新配置时间。`retired` 只接受 0/1；不传或 0 保持默认行为。
- Device JSON 新增 `retired_at`（活动设备为 null）。退役配置正文和命令历史不会通过上述元数据 API 公开，仍保留在原表。完整归档历史读取与预留释放工作流后续完善。

## 事务与身份

设备创建、更新、退役使用与映射相同的数据库池行锁及五秒事务期限。锁顺序为池 → 所有者 → 设备；取得锁后重新核对归属/账号状态。名称、IP 展示字段限制长度及控制字符，设备状态仅允许 0/1。创建绑定认证调用者，不接受外部 owner 字段。

设备变更和 `frp_device_create/update/delete` 审计同事务。退役同时写 `status=0` 和服务端 UTC `retired_at`，数据库触发器清空凭据和待兑换 enrollment，并把 pending/leased 命令改成 cancelled、记录完成时间。已完成命令的回执和诊断快照不改动。审计失败时，设备状态、退役时间、凭据撤销、命令取消全部回滚。

`retired_at` 使用 GORM 删除作用域，常规查询默认排除退役设备。Agent 所有者/设备加锁查询也受该作用域保护。特殊心跳 JOIN 另外明确过滤退役时间，只有显式归档元数据查询使用 Unscoped。直接 GORM 软删除同样触发数据库撤销，不能只依靠 HTTP handler 的清理。

## 显式迁移

停旧写实例、备份并在副本演练后执行现有 `migrate`。新增 `device.retired_at`、第五个生命周期触发器 `cn_agent_device_retire_v1`，以及只读校验例程 `cn_agent_trigger_check_v2`。原四个触发器保持定义不变；已有 v1 校验例程保留，不静默覆盖。

运行账号需获 **v2** 例程的 EXECUTE 权限；v1 权限不能替代它。维护账号/definer 权限要求沿用 [设备身份迁移](G05-DEVICE-IDENTITY.md)。启动只读验证新列的类型/精度/可空性，以及五个触发器的实际定义；缺少或篡改的对象不能通过。已有设备迁移后仍活动，重复迁移不恢复退役设备。没有自动恢复旧已物理删除的设备，也不猜测孤立记录应归属于谁。

旧程序不了解退役作用域，因此本次不能与旧实例混跑。没有执行生产迁移、清除历史表、撤销真实设备或加载用户服务。

## 远端与预留边界

退役会让在线 Agent 的下一次认证请求收到 401，并进入已有停止/进程回收路径。但断网的 frpc 可能仍连接 frps，**撤销后端身份不等于远端端口已经释放**。因此退役保留映射的端口和域名唯一预留，也不删除加密配置；其他设备不能立即复用这些预留。

真实官方 FRP/编译后端/Agent 的退役关闭隧道测试与原凭据撤销测试分别运行；结果见 [测试记录](TESTING.md)。多服务器注册/作用域、在用配置的占用台账、离线退役及确认后回收、既有孤立记录治理仍在 G05，不能以本批软退役宣称 FRP 生命周期已完整验收。
