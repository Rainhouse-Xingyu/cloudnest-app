# 原生 FRP 配置流程

设备的配置历史新增“生成新配置”和“从此历史追加新配置”。生成窗口使用真实服务器游标列表，显式选择已启用服务器和已读取版本；只提交 device_id、server_id、server_revision_id，不在该流程输入或读取认证 token。

预览调用生产 HTTPS API，必须返回所选设备且明确 config_text_redacted=true 才能显示，响应和文本大小有界。更换服务器、重读或离页清除预览并取消旧任务；请求代号和身份检查拒绝迟到响应、旧 401 或其他服务器结果。未经可信预览不能保存。网络/权限/版本错误不保留旧预览。

预览是当前启用映射的采样，不是保存事务的映射 CAS。保存明确告知将重新读取当前启用映射，并在事务内核对所选服务器版本及端口策略，追加新配置；并发映射修改可能使保存内容与先前预览不同。成功显示新配置 ID，关闭后从历史核对、另行确认部署。客户端不自动推断已部署，更不自动创建 Agent 命令。

历史回滚调用既有追加接口，保留原历史及服务器版本，确认框提醒核对旧端口/认证是否仍可用。成功只表示追加记录，部署仍使用独立持久命令意图。保存和历史复制各在当前窗口防止重复提交；丢回执或坏响应要求关闭、刷新历史核对，没有持久幂等保障，不能把命令 journal 的保证套用到它们。真实故障和跨窗口并发矩阵仍留 G10。
