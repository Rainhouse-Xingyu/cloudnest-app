# 下载写入期限与连接释放

G03 / PR #4。此前限速等待可取消，但底层 ResponseWriter.Write 可能因客户端停止接收而长期阻塞，持有读取租约或派生文件 FD。真实 TCP 复现中，客户端收到响应头后保持连接但停止读取，45 秒后服务仍未退出该下载。本批为统一传输出口补齐写入期限，不新增数据库结构或修改冻结的 iOS 工程。

## 运行行为

每段最多 16 KiB。限速等待结束后，在底层写入前通过 Go ResponseController 设置 **30 秒写入期限**，写入并刷新该段缓冲后清除期限。单个操作期间即使有少量网络进展，仍受这次 30 秒期限约束；这不是逐字节重置的空闲计时器。下载没有新增固定总时长限制，正常的长文件和 1 KiB/s 限速等待可以超过 30 秒。

实际写入期间，读取作用域或请求上下文取消会立即将期限设为当前时间，唤醒阻塞 IO。结束时先停止取消回调，若回调已启动则等待它结束，再清除期限；回调不会延迟到另一个请求或复用的 HTTP/2 ResponseWriter 上执行。没有为每次 IO 启动无法回收的后台写协程。

每段均在期限内刷新缓冲，空文件和条件响应也在返回 handler、释放读取作用域前提交/刷新响应头。Gin 的旧 Flush 不返回传输错误，本批增加错误可见的刷新路径；读取租约 wrapper 在刷新前仍校验作用域，最终缓冲刷新失败会返回错误，不能成为下载成功或成功审计。已提交响应的失败仍通过 ErrAbortHandler 终止原流，不追加 JSON。

该路径覆盖当前/历史/分享原文件、Range/multipart、ZIP、视频/原始预览、缩略图和文本 JSON。原 SHA-256 校验、强 ETag、限速策略和读取租约规则保留。HTTP/1.1 的失败流关闭连接；HTTP/2 超时仅终止对应流，同一连接的其他请求仍可工作。客户端必须检查正文读取错误、完整长度和摘要，并按原续传身份协议恢复。

标准 Go HTTP/1 和 HTTP/2 实现支持这些期限。生产中的 Gin、租约和传输 wrapper 已提供 Unwrap/FlushError 链；不支持连接控制的内存 recorder 保留兼容。自定义网络 adapter 若屏蔽 Unwrap/期限或刷新能力，不能声称具有此写入保证；需要接入相同控制契约。普通 JSON API 的全部响应并未因此获得全局写入期限。

## 验证入口与证据

- `scripts/test-transfer-network.sh` 或 `make -C cloudnest_go network`：复用既有全新 MySQL/Redis 容器、临时目录和测试账号；启用 `integration,network`，独立三分钟期限。两个测试函数包含真实 HTTP/1.1、TLS HTTP/2 阻塞子例，以及 1 KiB/s、超过 30 秒的正常 HTTP/2 下载。CI 明确执行该入口，不仅编译标签。
- 阻塞测试在收到成功头后不读取/关闭正文，不取消客户端，等服务器自行终止；确认读取租约先被释放，再读取剩余数据并验证它是截断的原始前缀、没有 JSON。TCP 断流断言拒绝把测试客户端自己的读取超时当作服务端终止。HTTP/2 必须实际协商协议，并在同一连接上继续完成 Range 请求。
- 新单元测试覆盖 Gin 下最后缓冲刷新错误不能被吞掉，以及真实 HTTP/2 在已确认阻塞于底层 Write/Flush 后，服务端作用域取消在一秒内结束 IO（测试写入期限为十秒，排除靠自然超时通过）。
- 普通套件保持 237 项、race、六分钟期限，网络测试单独执行，不挤占或放宽原回归预算。完整最终结果见 TESTING。

本轮 HTTP/2 通过 httptest TLS 服务运行真实 handler/协议；生产 cmd/server 仍使用原 ListenAndServe，没有新增 TLS/HTTP2 部署配置。该验证不替代生产代理链路、多流压力、聚合带宽/公平性、动态速率或整文件预校验 IO 准入验收。30 秒期限约束 HTTP 写入和刷新，不是磁盘读取/预哈希/数据库访问的总期限。大文件基准单独运行并记录，不能用这些网络阻塞测试的耗时冒充吞吐指标。
