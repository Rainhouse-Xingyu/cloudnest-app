# 上传暂停、继续与代次隔离

2026-10-23，G03 / PR #4。新增真实暂停/继续协议，冻结 iOS；macOS UI 与完整下载恢复/性能验收仍待做。本轮仅使用新建 disposable MySQL/Redis、临时文件和测试 HTTP 服务，没有操作生产数据。

## 客户端契约

新增 POST /api/files/upload/pause 和 POST /api/files/upload/resume。原 init/progress 响应新增 transfer_epoch（非负 int64，初始 0）；已有字段与非空/空文件上传协议不变，旧客户端忽略新增字段即可。新控制请求最多 16 KiB，必须同时提供 upload_id 和数值 expected_epoch；缺少/null/负数/溢出为 400。新路由需要有效当前会话、业务路径权限及任务所有者；不是无需业务授权的会话管理能力。

```json
{"upload_id":"原任务ID","expected_epoch":0}
```

初始上传中为 status=0/epoch=0；pause 成功变 status=2/epoch=1，resume 携 expected_epoch=1 成功后变 status=0/epoch=2。响应包含 upload_id/status/transfer_epoch/expires_at。客户端应保存最新代次，409 后刷新任务进度/完成回执再决定下一步，不盲目重传或创建同名文件。

严格的状态/代次 CAS 和审计在同一事务。相同状态且期望等于当前代次为无写入确认；原成功控制请求若仅落后一次、且仍处在该请求的目标状态，可幂等返回当前确认，不重复增加代次/审计。已经发生更新意图后，旧命令返回 409：例如 pause(0)→resume(1) 已到 epoch=2，延迟的 pause(0) 不能再次暂停。int64 上限处不能再增加，不回绕。

数据请求也携 `X-Upload-Epoch`（匹配 init/progress/resume 的当前代次）。从未控制过的 epoch=0 任务仍兼容旧客户端省略该头；任务一旦暂停/恢复，chunk 与尚未完成的 complete 必须显式匹配代次，否则 409，空/重复/非法头 400。这样元信息在恢复之后才解析的旧网络请求也不能隐式获得新代次。已完成任务的原始回执重放仍无需该头。旧 iOS 不增加暂停界面；已被新客户端控制的任务需由懂代次的客户端继续。

只有未过期的上传中/暂停任务可控制。完成、取消或过期不能暂停/恢复，返回 409；已完成上传继续使用原 complete 回执确认。pause 不延长原始 24 小时期限，不改变固定目录/尺寸/片数，也不释放逻辑预留或已确认分片的临时额度。init 带原 upload_id 只是查询/核对，不隐式恢复暂停任务。

resume 再查当前目录写权限及当前逻辑配额/计量，撤权 403、额度不足 507、异常计量/配置 503，失败状态/代次保持暂停。pause 不新增内容，可在额度配置损坏或降低时冻结有效任务；元数据本身无可信契约的旧任务仍拒绝，应按既有取消/审核流程处理。暂停后仍可取消释放逻辑预留，物理清理继续异步受控。

## 在途写入和恢复

upload_task 和 transfer_artifact 新增 transfer_epoch。候选分配必须匹配元信息预检时的代次；文件身份登记、Seal、续约、分片挂接及最终发布均验证该候选仍属于当前代次。因此暂停后立即恢复也不能使旧请求重新获得提交资格，不依赖它是否刚好看见 status=2。

已确认 chunk 是不可变检查点，可以来自旧代次；暂停保留其路径/摘要/进度。恢复后只传缺片，同索引相同字节重试仍复用原片，合并独立验证每片实际内容。旧代次的 writing/ready 合并不能作为新发布，只有完成回执确认原操作；旧候选清理不能删除新发布对象或清除不同 token 的合并占用。

同一 Manager 在控制事务确认后取消旧代次活动句柄，新代次不受延迟取消影响。其他容器通过现有 20 秒续约检查状态/代次并取消句柄（单次 DB 操作五秒期限）；实际 HTTP body 在句柄取消后收紧读取 deadline 并关闭，以唤醒阻塞 Read。测试观测约 20 秒，不承诺过载环境的硬实时中断。客户端暂停时仍应取消自身网络任务，并保留本地源和 upload_id。

暂停确认表示提交边界已隔离，**不表示所有进程和磁盘 IO 在返回瞬间停止**。在途私有文件仍持 FD 锁/临时额度直到关闭，不能凭暂停/期限抢删；若最终发布事务先获得任务锁并提交，控制请求会看到完成并拒绝暂停。原有长事务/大文件性能边界仍待验证。

回收器保留暂停任务的已确认分片；对已暂停/代次落后的未挂接候选，即便租约仍新鲜也可列入检查，但必须取得排他 FD 锁、验证登记 inode/引用，再按 deleting→unlink/Sync→done 释放额度。正在创建文件时发生控制变化，成功登记自身 inode 后转为 discard，不能把一次正常暂停变成无身份文件认领。未知提交或身份不明继续保留。旧合并占用只有其对应候选最终回收才释放，恢复后可短暂 409/Retry-After 等待。

## HTTP 读取保护

取消受控 body 的 deadline 可能同时让 net/http 取消请求上下文。句柄保留明确取消原因，暂停/过时代次返回 409，租约数据库故障可 503，总请求期限仍 408。全局 blob 响应保护仅在从未 Pin 且未发生 Pin 错误时允许元数据回复；实际持有租约、已失败 Pin 或已关闭 scope 仍严格拒绝不安全写入。未放宽物理文件读取或使失效租约继续输出。

## 显式升级

停全部旧写实例及回收 worker，备份并在副本演练后执行显式 migrate，新增两表的 transfer_epoch BIGINT NOT NULL DEFAULT 0。普通启动检查字段/默认值/有符号类型，缺字段或漂移拒绝。已确认分片及原进行中的协议 1 任务代次默认 0，不重写路径、不自动认领旧协议 0 字节。旧二进制不检查代次，不能混跑或直接回滚，否则无法保证暂停/恢复隔离。

本批没有新增 file/storage 引用外键，回执/已发布对象保留语义不变。迁移只在隔离测试库演练，真实副本升级/回滚和生产凭据操作尚未执行。
