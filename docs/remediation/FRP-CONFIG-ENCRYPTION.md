# FRP 配置加密与显式迁移

G05 新配置保存使用 AES-256-GCM，配置正文包含 frps 凭据。密钥与 JWT、Agent 凭据分开管理，数据库只保存封装后的文本。封装格式为 `cnfrp:1:<key-id>:<base64>`，每次加密使用 Go 标准库生成的随机 96 位 nonce，附加认证数据包括协议版本、device_id、config_id 和 key ID。密文搬用、内容改写、未知版本、丢失或不匹配的密钥均拒绝解密。

新保存事务先分配配置 ID，再加密正文并写入审计。任一步失败都回滚，空的占位记录不会提交。回滚读取经过授权的历史版本，解密后以新的版本 ID 和 nonce 加密，同时写入审计。用户及来源 IP 保留在保存/回滚审计中，正文和凭据不进入审计。历史列表和用户响应继续只返回脱敏元数据。

## 密钥文件

设置 `CLOUDNEST_FRP_KEY_FILE` 为绝对路径。文件格式如下，`key` 必须是 32 个随机字节的标准 Base64 编码。

```json
{"version":1,"active":"key-2026-11","keys":[{"id":"key-2026-11","key":"<32 random bytes encoded as Base64>"}]}
```

最多保留 16 个密钥，ID 由 1–32 个 ASCII 字母、数字、下划线或连字符组成。ID、密钥内容不得重复，active 必须存在。文件不超过 16 KiB，必须是当前服务运行用户拥有的普通文件，禁止组/其他用户访问、符号链接及硬链接。推荐 0600 权限，父目录也应仅由可信运维人员访问。程序在连接数据库前加载指定文件，格式或权限错误会阻止启动。密钥在进程内加载一次。更新文件应先在同一受保护目录写完新的私有文件，再原子替换，随后重启实例。

可在受保护目录中生成一个新文件，下面的命令不会覆盖现有文件，也不会将密钥输出到终端。将路径换成部署方选定的绝对路径，以服务用户身份执行。

```sh
python3 - /absolute/private/directory/frp-keys.json <<'PY'
import base64, json, os, sys
path = sys.argv[1]
if not os.path.isabs(path):
    raise SystemExit('absolute path required')
document = {'version': 1, 'active': 'key-2026-11', 'keys': [
    {'id': 'key-2026-11', 'key': base64.b64encode(os.urandom(32)).decode('ascii')}
]}
fd = os.open(path, os.O_WRONLY | os.O_CREAT | os.O_EXCL, 0o600)
with os.fdopen(fd, 'w') as output:
    json.dump(document, output)
    output.flush()
    os.fsync(output.fileno())
PY
```

没有指定密钥文件时，其他后端功能仍可启动，配置预览和历史元数据可用，但配置保存及回滚返回 503。已有明文配置不会由正常请求自动升级，也不能通过回滚进入新版本。配置正文最大 32 KiB，封装后仍可存入原有 TEXT 列，本批不新增数据库字段。

## 历史迁移

1. 备份数据库及密钥，确认备份可恢复。停止旧实例和配置写入方，不能让会写明文的旧版本与新版本混跑。迁移不会替代旧凭据轮换。
2. 配置 `MYSQL_DSN` 和 `CLOUDNEST_FRP_KEY_FILE`，执行 `cloudnest audit-frp-configs`。命令只读配置，验证现有密文并报告 scanned、legacy、old_key、current 数量。不会输出正文或密钥。退出非零表示扫描不完整，不能只看计数判断成功。
3. 审核结果后执行 `cloudnest encrypt-frp-configs`。明文和旧密钥记录逐行加密到 active 密钥，每行与审计在同一事务提交。配置 ID、设备 ID、创建时间和内容保留。
4. 再执行 audit，确认 legacy 和 old_key 均为零，且扫描成功。然后启动使用相同密钥环的新实例，并验证业务操作。

命令使用 100 个 ID 一页的有界扫描和两分钟上下文。未知密钥、损坏密文、空配置、超限正文、缺失设备 ID 或审计故障都会停止迁移，报告已提交数量及停止的配置 ID。修复原因后可重新执行，已使用 active 密钥且验证通过的行不会再次改写。迁移是逐行提交，失败不会撤销此前已经成功转换的行。审计会短暂取得行锁，但不改写配置或审计表。

测试只在一次性数据库执行以上命令。生产迁移和真实备份恢复演练仍需部署方提供受控环境与授权。

## 密钥轮换与恢复

停配置写入后，生成新的独立随机密钥并增加新 ID，将 active 指向新 ID，同时保留旧条目。用包含新旧密钥的文件执行 audit、encrypt、audit，确认全部行已使用新密钥，再启动相同密钥环的新实例。密钥文件也必须安全备份。多实例不能使用不一致的 active 设置继续写入。

旧密钥只有在所有实例停止使用、全部在线记录迁移完成、旧备份与恢复需求已经评估后才能移除。单个密钥的累计加密次数必须在 2^32 次之前轮换，计数范围包括多个实例及历史写入。程序不自动销毁旧密钥或备份。

丢失密钥时不能恢复密文，系统不会回退为明文。错误密钥或损坏记录必须从已验证的备份恢复，或由所有者创建新的有效配置。此批没有自动降级至旧后端的方案，旧后端无法解释新封装。历史数据库备份、二进制日志和快照可能仍含旧明文，本次逻辑字段更新不构成物理擦除。

Agent 专用配置领取、受限落盘、官方 frpc 校验及命令租约仍在后续 G05 工作中。加密现存文本不等于确认该文本能安全用于 frpc，部署前仍须按 Agent 白名单校验配置。
