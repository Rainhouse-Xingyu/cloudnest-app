## 已复现的问题

旧生成 helper 只检查 HTTP 和 response 字段。七项新回归全部先失败：缺少 done、错模型、length 截断、空输出、超过32KiB正文、超过2MiB JSON 均被接受，HTTP错误正文还能进入错误信息和失败任务。旧路径允许重定向，未验证推理前后模型digest。

真实私有 MySQL/Redis 与 HTTP 路由竞态中，源版本替换、单文件读取授权撤销、文件回收三个场景全部先失败：旧请求仍200，分别留下摘要元数据和成功历史。不是以模拟仓储代替真实事务。

## 实现

摘要/助手统一使用 `aiindex.Ollama.Generate`，复用 embedding/视觉的禁止重定向、有界响应、UTF-8原字节检查和模型digest读取。仅HTTP200、模型名准确、done=true、done_reason=stop、无error、非空/无NUL/有效UTF-8且不超过32KiB的结果可返回；length为专用拒绝错误，推理前后digest变化拒绝整份结果。HTTP/解析错误不含提供方正文。

共享两槽生成准入，与图片/PDF视觉及重排共用；超过即拒绝，不积压请求。请求think=false、temperature0、4096输出/8192context、keep_alive1m，整个生成包括digest核对最多120s；较短的原AITimeoutSec设置继续生效。原生成模型配置优先，默认值变化如有实际模型验证则另记，不把视觉评估冒充摘要测试。

生成输入最多256KiB；摘要只提交前24000个UTF-8字节以内的完整字符，实际截断通过原有truncated字段告知。纯文本源先在30s内使用同一已校验FD，校验完整SHA/长度再最多读取2MiB；源上限32MiB，超过返回413。已有Office/PDF继续使用统一parser及原限制。元数据最多保留100000字节的完整UTF-8前缀；无新schema。助手文档只读普通文件的最多24001字节，取有效24000字节前缀，拒绝损坏文本；不再先把整个文档读入内存。两条HTTP请求体限制16KiB。

摘要提交复用手动OCR的源/授权事务：锁定仍活动的文件，核对所读storage、文件名、源hash和当前访问权。个人文件读取者兼容原手动分析行为；空间仍要求写角色。源改变/回收409、撤权403，均无元数据或成功历史。摘要元数据、独立document_summary成功历史、ai_summary操作审计同事务提交；审计失败全部回滚。失败任务只写固定generation_failed或generation_output_limit，不写提供方错误或半份摘要。正常OCR的事务行为与任务类型保持原值。

删除handler中未被路由调用的旧检索规划/生成副本，以及service中的旧规划、无源授权的元数据upsert和仓储CRUD入口。生产自然语言检索仍走原混合检索实现。内部构造器移除无使用者的HTTPClient参数；公开客户端协议不受影响。模型更换不会自动迁移或重建旧数据。
