# 下载身份、校验与续传约定

2026-10-23，G03 / PR #4，代码完成待审；服务端基础已实现，完整客户端断点续传与 G03 整体验收未完成。未操作生产库、删除历史文件或修改冻结 iOS。

## 实际输出与身份

普通、历史版本、公开分享、视频及二进制预览先执行现有认证/当前 ACL/分享创建者权限和速率检查，再持读取租约打开对象。打开后检查普通文件、实际尺寸和完整 SHA-256，校验后 rewind，并通过**同一文件描述符**交给 ServeContent。路径被替换后不会重新打开成另一个对象；历史版本不再先校验后重开。持租约的服务端不可变对象约束仍是前提，不能把保留 FD 说成可防外部进程原地改写的文件系统快照。

完整响应和 206 使用强 `ETag: "sha256-<64位小写十六进制>"`，`Repr-Digest: sha-256=:<原始32字节摘要的base64>:` 表示**完整选定表示**；206/multipart 不是只对片段或 multipart 封装求摘要。因此没有用完整文件哈希冒充 Content-Digest。空文件也使用真实 SHA-256。ZIP 和派生 JPEG 从最终实际发送的 FD 计算摘要，不能沿用源文件摘要。ZIP 重建字节可能不同，只有实际 ETag 相同才允许继续同一个表示。

所有这些响应使用 `private, no-store, no-transform`，不再公开缓存缩略图。文本预览仍是最多 1 MiB 原始内容的 JSON，经过相同响应限速，但它不是原文件表示，不携原文件 ETag/Repr-Digest。JSON 转义后的响应可能大于原始内容上限。

损坏/尺寸不符/不是可验证 SHA-256 的存储元数据在发送前拒绝（完整性错误 409），包括条件请求，不能返回误导性的 304。MD5 等旧元数据不自动升级或覆写数据，保留给既有审计/修复流程；这会让以前未经完整校验的当前/分享/预览请求暴露原有不一致。物理文件不存在仍按现有错误映射处理。错误正文清理文件摘要/ETag/Last-Modified/Disposition；416 保留标准 `Content-Range: bytes */size`。读取租约失败、限速等待取消或输出故障不能继续发送文件，正文开始后断流，不附加 JSON。

## 条件请求与客户端职责

`Range` 配合**精确匹配当前强 ETag** 的 `If-Range` 才保留部分响应。弱标签、日期、重复字段、列表、尾随文本或旧标签均回退完整 200；文件 URL 可在同一秒内更新，不能用秒级 Last-Modified 作为强续传依据。没有 If-Range 的 Range 仍按标准返回当前内容的 206，旧调用兼容，但不能据此安全拼接旧片段。标准 If-Match/If-None-Match、multipart、304 和 416 继续由 ServeContent 处理，权限与完整性检查先于条件成功。

新 macOS 客户端须持久化目标临时文件、已确认偏移、强 ETag、总尺寸及完整表示 SHA-256；向原 URL 发送 Range 和强 If-Range。收到 206 时核对 Content-Range 起点/总长、ETag、完整读取及偏移，再写入受控临时文件。收到 200 时从零重建，不能向旧片段追加；412/不匹配应刷新计划，不能忽略。304 仅是服务端条件响应，不证明任意本地文件已经正确。最终校验完整尺寸/SHA-256 后再发布目标文件，网络读取失败仅保存可靠检查点，不标为成功。这些客户端功能尚未实现。

语义依据：[RFC 9110 §13.1.5](https://www.rfc-editor.org/rfc/rfc9110.html#section-13.1.5) 的 If-Range 强比较及 [RFC 9530 §3](https://www.rfc-editor.org/rfc/rfc9530.html#section-3) 的表示摘要。哈希用于一致性，不能代替可信 TLS、认证或签名。

## 缩略图缓存与兼容

旧键含秒级 update_time，同秒切换图片可能返回旧 JPEG，直接创建固定路径也可能暴露未完成写入。新键为 `thumb-v2_<fileID>_<sourceSHA256>_<size>.jpg`；使用已校验的源 FD 解码，0600 私有随机临时文件编码/Sync/Close 后非覆盖 hard link 发布，竞争请求只读取完整获胜文件。旧缓存不采用、不删除。返回的摘要属于实际 JPEG，源摘要仅用于缓存键。

本批不新增数据库字段；整个 PR 仍要求按 UPLOAD-CONTROL/TRANSFER-REGISTRY 等既有文档停旧写实例并显式迁移。路由/下载字节与原 File DTO 保持，新增条件头语义及错误拒绝必须被新客户端识别。视频、二进制/Office/文本预览和缩略图现统一应用 download 策略，非法/坏配置不再绕过。

## 测试与尚未验收

修改前真实测试分别复现空 ETag/Repr-Digest，以及同秒更新后日期 If-Range 返回新版本尾部的 206（可能与旧前缀混合）。修复后新增 10 项真实 MySQL/Redis/文件/API 集成，覆盖强条件/弱条件/尾随标签/同秒更新、历史/分享/ZIP/批量、损坏拒绝、视频/预览限速、八请求缩略图并发发布与源切换、撤权/禁用、真实 TCP 中断后重新获取匹配片段、multipart 和空内容替换。完整 206 项 race 回归通过（278.936s），专项 10 项通过（15.153s）；另有 FD 路径替换、旧 MD5 拒绝且数据不变和错误头清理单元测试。完整工具证据见 TESTING。

预校验使用 64 KiB 缓冲，每次下载/Range/条件请求仍须 **O(N) 整文件读取**，ZIP/派生文件也要哈希。没有将低内存算法冒充大文件首字节延迟/吞吐/RSS 证据；校验 IO 的并发准入、缓存信任与一致性优化、大文件实测留在 FILE-025。缩略图解码仍可能占用全像素内存，ZIP/缓存容量/数量预算、崩溃临时文件治理、淘汰策略尚未实现（FILE-020/022）。每次请求限速不是聚合治理（FILE-021），慢下载写入期限、HTTP2、主机断电及真实升级恢复也未验收。此次未测试 1 TiB 文件，macOS 续传 UI/任务持久化/目标发布校验待 G07/G08。

ZIP 后续已补齐逐项源对象的实际复制摘要/尺寸校验、共享临时卷及持久增长/回收，所有源成功后才发出归档；生成后的同一 FD 再核对归档摘要后消费，见 [归档协议](ARCHIVE-TRANSFERS.md)。本文前述 ZIP 临时预算待做属于早批次范围，缓存、大文件、预校验成本和客户端恢复仍未验收。
