# 原生 FRP 管理界面

G09 的“远程连接”已接入设备列表/添加/编辑/退役和保留元数据、服务器登记/版本编辑，以及设备详情的运行状态、映射、配置历史和命令记录。支持脱敏配置预览/保存/历史复制及单独部署、启动、停止、重载、诊断和持久原键回执恢复。映射编辑与 Agent 注册仍继续实施，不能将本批视为整个 FRP 原生功能完成。

服务器分段后续增加[登记与版本编辑](MACOS-FRP-SERVERS.md)，独立游标分页、token 保留/替换/清除和冲突核对均调用生产 API，实际 GUI 与服务器回执有独立报告。

后续已接入[原生配置预览/保存/历史复制](MACOS-FRP-CONFIGS.md)，确认生成后从历史另行部署，真实 Agent/官方 FRP 已验证生成和历史复制后的两次部署、三种隧道及停止。设备/映射 CRUD 和 enrollment 仍继续实施，整个 G09 未结束。

列表使用服务器授权后的可见设备，支持本地名称/地址筛选和刷新。设备启用状态单独显示，不表示在线。详情显示查询时间，Agent 最近心跳与版本；仅在线且存在实际 runtime 时显示注册采样、逐映射状态与本地 TCP 探测。明确提示心跳、隧道注册、本地 TCP、应用协议健康的不同含义，不从空状态制造成功。

映射显示实际本地端口/远程端口或域名、服务器和启用状态；配置历史只解码 ID、服务器版本及创建时间，不持有或展示配置密文/明文。命令只显示最近 20 条、原始命令 ID、实际 action/status/attempts/result_code 和服务器返回的诊断采样，排队/送达均不当成执行成功。端口和资源 ID 使用字面字符串，避免 8080 被本地化为 8,080。

Core 通过 SessionState 原 token 封装访问 API；详情切换/关闭取消旧请求，并以本地请求代号拒绝迟到结果。服务器/账户改变后旧详情拒绝继续读取；403、坏响应或失败清空旧元数据，403 不撤销登录。列表体积与项数有界、响应 ID 去重，映射/配置/命令核对返回 device_id。现有设备/映射/配置列表 API 尚无分页，客户端遇到超过响应/项数上限时拒绝显示，不能静默截断后冒充完整列表；服务端分页仍需补齐。

## AI 模型资源复测

用户已明确授权下载 AI 验收所需模型；本机已恢复原 embedding 与视觉模型。视觉模型与优化编译/多个隔离服务/完整传输套件并发时，8 GiB 主机出现明显内存压力，视觉处理返回 model_unavailable、另一套上传完成返回 500。Ollama 当时显示 qwen3-vl:4b 驻留约 4.8 GB、38%/62% CPU/GPU、8192 context；失败及系统观测见[资源失败记录](MACOS-AI-RESOURCE-FAILURE-20261121.json)。这仅支持资源竞争的推断，未从日志确认 500 的内部根因。

已待模型测试结束后卸载其驻留内存，关闭 GUI/私有服务，再串行执行完整套件和 Release 构建；原断言不变，两者通过。4B 视觉像素/EXIF/OCR 检索单独复跑仍失败（测试 122.39s，Go 包 124.079s，model_unavailable），不能只归因于并发负载，也不能将其计为通过。随后按[官方模型列表](https://ollama.com/library/qwen3-vl:2b)恢复并串行测试 2B，使用同一像素/OCR/拍摄日期/权限断言，不延长原超时；生产默认模型未修改。8 GiB 下模型与传输/编译的同时峰值仍是 G10 资源门槛，不因串行通过而关闭。

2B 真实模型测试通过（用例 46.18s，Go 包 48.104s），实际从海边图片像素及合成 EXIF 得到语义检索/拍摄时间，从发票图片得到 Laptop、5999 和 192.0.2.42 的 OCR，并验证无拍摄日期不编造、其他用户不可见及回收后移除。`qwen3-vl:2b` digest 为 `0635d9d857d497aeadba3d7d27485746c50554446f9f6ec01ef39788221adbe8`；每秒观察 54 次，Ollama 报告的最大模型占用/VRAM 为 2,654,197,512 字节，不代表全系统 RSS 峰值。模型、图片摘要与采样见[原始报告](MACOS-AI-VISION-2B-20261121.json)。仅两组合成图片通过，不替代完整检索质量评估、原生照片界面或并发资源验收；4B 失败历史不改写为成功。
