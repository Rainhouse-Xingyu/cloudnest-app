# macOS 文件管理

G08 在独立的 `cloudnest_macos/` 中接入 Go 文件 API。原生 Table 支持多选、名称/大小/修改时间排序及当前目录筛选，目录以双击或右键打开，路径栏可返回祖先。工具栏提供新建文件夹和刷新，右键支持重命名和移入回收站，回收站支持选择单个项目恢复。检查器显示当前项目的大小、版本及修改时间。每个窗口独立保存导航和选择，共用经过 Keychain 恢复的会话。

文件操作遇到 401 会使当前会话失效。权限拒绝、名称冲突、容量不足及服务不可达分别显示错误，失败目录读取清空旧列表。批量删除读取服务端的 `deleted_ids` 和逐项 `failed`，成功后重新读取目录，保留失败选择并提示未完成数量。

真实后端联调通过临时 MySQL、Redis 和 HTTPS Go 路由验证客户端，入口为 `python3 scripts/test-macos-backend.py`，依赖 Homebrew 的 `mysql@8.4`、`redis` 和项目 Go/Swift 工具链。数据库使用随机本地端口、独立临时目录和专用测试账户，进程在测试结束时退出。TLS 测试客户端使用本次服务器证书作为独立信任锚。

## 原生传输队列

传输界面已接入真实分片上传、普通文件及目录 ZIP 下载、已确认字节进度、暂停/继续、取消及失败重试。上传可通过原生文件面板和文件拖入入队，下载可为单项选择目标文件，或为多项选择目标目录。队列按服务器源地址和账户 ID 显示，窗口共用同一队列，当前同时运行两个任务。

上传预先记录完整 SHA-256 和各分片摘要，每次发送前验证实际读取分片；恢复会查询服务端进度，并以真实 transfer_epoch 执行 pause/resume，完成使用原任务回执。任务、文件 bookmark 和检查点保存在用户 Application Support 的独立目录，会话凭据仍由 Keychain 管理。传输目录持排他文件锁，防止多个应用进程并发写同一队列；恢复运行中任务时先转为待用户继续。

下载使用 Range 和强 If-Range，核对 Content-Range、完整表示摘要、ETag 及实际长度。完整 200 响应会清空旧前缀重新下载。每个完成分段同步到磁盘并保存摘要，恢复时校验前缀并截去未确认后缀。最终完整 SHA-256 校验后，在目标目录中以硬链接原子发布文件。遇到同名现有文件时使用带序号的新文件名，最终名称显示在传输界面。发布意图先写入检查点，恢复时可识别属于同一个临时 inode 的已发布文件。

本批新增真实上传/下载的暂停、队列重建、检查点恢复、空文件及取消回归，结果待本批精确提交 CI 验证。当前为显式继续/重试，重启后的自动重试策略、断电与多卷演练、极大文件资源基准、Quick Look 和完整界面交互仍待验收。若初始化上传的响应在取得 upload_id 前丢失，客户端无法查询该次初始化的结果，服务端临时预留按现有期限回收。
