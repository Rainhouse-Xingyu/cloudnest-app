# G05 设备注册与心跳

分支从 G03 的 `a34ba25` 建立，包含 G01 的账号和会话整改。G04 的 AI 索引改动在独立 PR 中审查。此检查点覆盖设备身份和配置保护，G05 的隧道验收仍在进行。

| 接口 | 身份 | 行为 |
| --- | --- | --- |
| POST /api/frp/devices/:id/enrollment | 所有者 JWT、路径权限及当前密码 | 发放绑定到该设备的注册码，有效期十分钟 |
| POST /api/agent/enroll | 请求体中的注册码 | 一次兑换设备凭据，成功兑换后旧凭据立即失效 |
| POST /api/agent/heartbeat | Bearer 设备凭据 | 从凭据确定设备 ID，保存服务端接收时间和客户端版本 |
| POST /api/frp/devices/:id/credential/revoke | 所有者 JWT、路径权限及当前密码 | 撤销设备凭据及待兑换注册码 |
| GET /api/frp/devices/:id/status | 有资源权限的用户 JWT | 从最近一次认证心跳计算在线状态，90 秒后离线 |

注册码和设备凭据各有独立的类型前缀、128 位随机查找 ID 和 256 位随机秘密。服务端保存查找 ID 与 SHA-256 摘要。申请、兑换、撤销及相应审计在同一 MySQL 事务内提交。并发兑换只有一个请求能得到凭据。申请新注册码时，设备可继续使用当前凭据，直至新码兑换成功。兑换响应丢失时，所有者需要重新申请注册码。

身份接口要求 HTTPS，凭据响应带 Cache-Control: no-store。服务读取 `CLOUDNEST_TLS_CERT_FILE` 和 `CLOUDNEST_TLS_KEY_FILE` 两个绝对路径后启动 TLS 监听。证书和密钥由部署方提供。反向代理需要通过 HTTPS 连接后端。访问日志省略查询字符串。注册/再认证及设备调用各自按实际 TCP 对端限流，代理后的多个设备会共享相应额度。

设备第一次申请注册码后，旧 JWT 上报状态、取命令、提交结果接口对该设备返回 403，包括管理员会话。该限制与首次注册使用相同的设备行锁，撤销凭据后仍然生效。尚未注册的历史设备仍有旧协议兼容路径。配置历史的旧明文风险及未登记设备的兼容路径仍列在 SEC-009/010。

## 部署与迁移

停旧实例并备份后，使用维护账号执行现有 `migrate` 命令。它新增 `agent_binding`、唯一查找索引、四个生命周期触发器和只读例程 `cn_agent_trigger_check_v1`。当账号或设备被禁用、删除，或设备所有者改变时，触发器在同一事务内清空当前凭据和待兑换注册码。重新启用设备后需要重新注册。

维护账号须有表、触发器和例程的创建权限。例程和触发器使用的 definer 账号需要保留。运行账号使用业务 DML 权限，并需获得对本库 `cn_agent_trigger_check_v1` 的 EXECUTE 权限。例程只返回本库四个指定触发器的定义。启动时校验实际触发条件、动作及索引，缺件或定义漂移将阻止启动。显式迁移遇到同名但不同定义的触发器或例程会报错，需要操作人员检查。DDL 中途失败后可重新执行迁移。

## 配置输入与输出边界

配置预览和保存要求实际 HTTPS，忽略转发头，并返回 `Cache-Control: no-store`。请求只接受一个不超过 4 KiB 的 JSON 对象，未知字段、查询参数和尾随数据返回 400。预览中的非空 token 替换为 `[redacted]`，该文本仅供检查映射。保存、历史和回滚响应保留 ID、设备及创建时间，返回空的 `config_text` 和 `config_text_redacted: true`。历史查询不从数据库读取配置正文，配置模型默认 JSON 序列化也排除正文。旧客户端仍可解析字符串字段，无法再从这些接口导出完整凭据。

生成器将字符串编码为 YAML 引号标量，按原值保留 token 的空格、冒号和井号，避免 YAML 类型转换或注入。FRP 在解析 YAML 之前处理模板，因此输入另行拒绝模板双花括号、控制字符、非法 UTF-8、过长 token、非法主机/域名和端口。配置最多 512 条映射，最终文本不得超过 32 KiB。服务端端口只有省略或零值时默认 7000，负值会被拒绝。

新保存和回滚已接入版本化 AES-256-GCM 及事务审计。历史明文需要显式迁移，缺少密钥不会回退。活动设备租约的配置领取已实现。SEC-010 保持开放，生产历史迁移、备份治理及运行中 frpc 明文配置仍需处理；Agent 持久状态已加密，macOS 默认密钥保存在 Keychain。普通用户 API 不会通过新增接口得到明文配置。

2026-11-03 最终普通 race 集成按完整清单分两批通过 92 + 151 = 243 项，无跳过；其中新增配置 TLS 用例通过 3.89s。单次六分钟完整套件的本机超时和重跑方法保留在 [测试记录](TESTING.md)。

加密批次最终 245 项普通 race 集成分批全部通过，实际迁移 CLI 完成明文转换、密钥轮换和失败恢复验证。具体证据及首次夹具失败记录见 [测试记录](TESTING.md)。
