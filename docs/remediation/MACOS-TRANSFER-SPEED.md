# 原生传输速度与确认进度

G08 的传输页按每次运行显示速度及准备、状态核对、传输、上传结果确认、下载校验保存阶段。进度条保留服务端已回执的上传字节或已落盘并写入检查点的下载字节，明确标为“已确认”；正文已流动但尚未确认时，速度可以大于零而进度仍为零。收到全部正文后仍须完成服务端发布或本地摘要校验、原子发布，才显示已完成。

上传只观察分块请求的 `URLSessionTaskDelegate.didSendBodyData` 增量，包含 multipart 正文开销；初始化、查询、控制、完成回执等元数据请求不计入。Apple 对该回调的增量定义见 [官方文档](https://developer.apple.com/documentation/foundation/urlsessiontaskdelegate/urlsession(_:task:didsendbodydata:totalbytessent:totalbytesexpectedtosend:))。该数值表示客户端发送的 HTTP 正文，不是远端磁盘确认、TCP 重传/包头或链路带宽。下载在既有有界流的消费端统计通过响应/长度检查的正文块，跳过一字节身份探测；保留原背压和完整文件 SHA-256 验证，不增加整文件缓存。

计量使用 ContinuousClock 和最近五秒的有界滚动窗口：200 ms 桶，最多 27 桶，边界误差小于一个桶；不足 250 ms 显示正在测量，连续五秒没有新正文后降为零。UI 每秒读取一次，不为每个数据块安排主线程更新。每项任务独立计量，暂停立即停止接收迟到回调，重试/继续/重建队列重新开始。服务端已经上传的块、本地已确认前缀、源文件哈希和历史检查点不会被当成本次流量；下载改换完整表示时重置窗口。速率不写入持久记录。

任务级上传观察代理仍转发原证书校验，拒绝重定向。没有更改生产 TLS、下载身份、传输配额、代次或资源限制。

## 回归证据

- 四项无休眠的时钟/并发回归覆盖元数据阶段排除、初始测量、五秒停顿衰减、表示重置、停止后迟到回调、新运行隔离、有界内存、极大计数/格式化及并发回调。
- 本机普通 Swift：19 项实际通过，8 项条件跳过（7 项真实后端、1 项 Keychain），共注册 27 项；没有把跳过项计为实际通过。
- 新真实 TLS→Go/MySQL/Redis 用例使用内存会话，9 MiB + 173 字节内容。测试包装层延迟真实分块回执，证明首块正文已发送而确认值仍为零、次块正文已发送而只确认 4 MiB。暂停重建后从服务器核对到旧 8 MiB，本轮仅发送剩余约 1 MiB；下载在 4 MiB 后放行 32 KiB 再阻塞，暂停重建后新计数不包含旧前缀。完成下载与源 SHA-256 相等，暂停/完成均不再提供运行速度。新增观察代理携带登录正文访问真实 307 时拒绝跳转，测试服务没有收到跳转后的请求。最后一轮新 Swift 用例 9.797s，Go 包装测试 26.285s；受限账户按开关跳过此用例。
- 初次测试包装层误读生产流式 MultipartReader 未填充的 Request.Form，导致未放行；已改为最多 5 MiB 的测试专用副本解析，真实处理器仍处理原完整请求。随后将 Testing 宏的算式右值提为明确 Int64 常量，保留全部字节断言后通过。测试门控与限速均只存在 integration/darwin 测试中，生产没有测试控制接口。
- Go 普通 race、vet/build、原生验收入口编译/签名及仓库检查通过。精确发布提交的双平台原生与完整后端 CI 另按 SHA 核验。

独立手工验收可设置 `CLOUDNEST_NATIVE_UI_SLOW_TRANSFERS=1` 启动既有 Native UI fixture，会生成 9 MiB + 173 字节的 `Speed acceptance.bin` 并只在该临时服务器放慢读写。该开关不进入产品。实际 GUI 已通过上传/下载速度、确认值分离、停顿归零、暂停/继续重测及最终完成，下载字节/SHA-256 和持久任务也已核对；正常退出应用与独立服务。完整结果记录在 [G08](G08-MACOS-FILES.md)。本批不替代大文件/RSS/功耗基准、弱网资源预算、全部异常 GUI 或整个 Goal 的验收。
