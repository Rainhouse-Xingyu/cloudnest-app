# 停止并清除 Agent 恢复配置

`stop` 关闭当前受管进程，但保留配置供 `start` 和 `reload` 再次使用。它不能证明某个历史端口以后不会再次被该设备使用。G05 新增 `forget_config`，提供后续端口占用账本需要的明确停止边界。后续已接入[运行占用账本](FRP-RUNTIME-RESERVATIONS.md)：首次有效成功回执原子释放相同凭据代次的运行占用，保留配置历史与映射。服务器级分配和旧历史对账仍待完成。

## 调用

先升级后端，再升级 Agent 为 0.3.0，并等待其认证心跳。所有者通过已有 HTTPS 命令接口提交：

```http
POST /api/frp/devices/12/commands
Authorization: Bearer <用户会话>
Content-Type: application/json

{"request_id":"b85bc275f0db41cb932c93a607bd2bec","action":"forget_config"}
```

示例 request_id 必须替换为客户端生成并持久保存的独立 32 位小写十六进制值。config_id 省略或为零。HTTP 200 只表示入队，必须查询命令历史，确认该命令以 `succeeded`、`result_code=ok` 结束；不能把 pending、超时、设备离线或普通 stop 成功视为清除完成。

首次入队要求：设备当前已注册；最近 90 秒有认证心跳；报告版本恰为当前支持的 `cloudnest-agent-0.3.0`；心跳不超过数据库时间未来五秒；设备没有其他 pending/leased 命令。后续 Agent 版本需要在后端明确加入该能力，不能通过字符串前缀猜测能力。旧版本、未知版本、过期心跳或队列冲突返回 409；队列达到既有 32 条上限时仍返回 429。相同 request_id 和相同参数的重试始终返回原命令，不因心跳过期重复入队。

该命令 pending/leased 期间，其他新命令均返回 409。身份心跳和只读状态/历史仍可用。检查、入队及审计采用全局 FRP 池→所有者→设备→绑定的数据库锁，覆盖多后端并发；并发清除请求只能有一个成功。命令终态或超时后解除队列排他，不据此自动释放资源。

## Agent 的持久顺序

1. 领取并保存待处理命令，验证当前租约。
2. 持久保存 `running=false`，待处理命令仍在执行记录中。
3. 停止监督进程及真实 frpc；未知监督进程状态继续拒绝成功。
4. 清空当前恢复配置、原始配置正文和配置 ID，并持久保存。
5. 保存该 command_id 的成功结果，再发送认证回执。

任一步失败都不能产生成功证明。重启时，未完成命令必须先对账，不能恢复不确定意图。成功后回执丢失，Agent 只重发持久结果；不会恢复旧配置，也不会重复副作用。当前配置清除后，start/reload 返回 config_invalid；需要新的认证 deploy_config 才能再建立隧道。重新部署历史版本仍需正常的服务器归属及配置完整性检查。

这只清除当前 Agent 状态中的恢复配置，不是文件系统安全擦除，也不删除备份、旧快照或服务端配置历史。设备身份和完成命令记录继续保留。

## 释放边界与剩余工作

成功回执关联原 command_id、设备及凭据代次。已接入的资源释放只使用匹配代次的首次成功证据，保留映射约束，重复回执不能影响后续部署；不能拿新设备注册后的清除回执释放旧设备实例的未知占用。失联、过期命令、凭据撤销、设备退役都不等价于远端端口释放。

本批已在实际后端、实际编译 Agent 和官方 frpc/frps 上验证：TCP/HTTP/HTTPS 正常运行；清除后实际 TCP 关闭、加密状态不再包含恢复配置；重启后 start/reload 拒绝、诊断配置 ID 为零；重新部署后三条隧道恢复。原重启、断网恢复、监督进程故障、凭据撤销及退役场景保留。测试证据见 [TESTING](TESTING.md)。配置占用登记与回执原子释放已追加验证；按服务器分配、历史占用受控对账和真实升级演练仍未完成，整个 Goal 保持进行中。
