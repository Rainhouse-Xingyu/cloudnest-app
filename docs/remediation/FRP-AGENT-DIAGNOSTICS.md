# G05 隧道注册诊断

`diagnose` 现在读取固定版本官方 frpc 的实际代理注册状态，不再把进程存在作为成功条件。只有预期的全部 TCP/HTTP/HTTPS 映射都报告 running，且没有错误时，回执才是 ok。管理端通过既有 HTTPS `GET /api/frp/devices/:id/commands` 查看该条命令的 `diagnostic`。

## 含义与返回值

| state | 含义 |
| --- | --- |
| registered | 所有预期映射已向 frps 注册 |
| starting | 尚未出现全部映射、正在等待注册，或未配置映射 |
| degraded | 至少一个映射被拒绝、检查失败或关闭 |
| stopped | 当前没有受管进程 |
| unavailable | 本机状态查询失败或状态无法可信解释 |

返回值还包含 expected、registered、failed、pending 数量，config_id 和 Agent 的 observed_at（UTC）。数量各不超过 512；正常注册类状态的数量必须与 expected 一致。只有 registered 对应 success=true/code=ok，其余诊断对应 diagnostic_failed。监督进程丢失时不能证明 frpc 已停止，绝不把它报告为 stopped。

这是**注册状态快照**，不是所有上游应用的健康检查，也不是持续更新的实时流。frpc 注册成功后，上游应用仍可能拒绝连接；后续断线也不会改写已经完成的诊断。展示时应同时显示 observed_at 与服务端 completed_at。设备观察时间依赖设备时钟；后端接收/完成时间由服务端确定。旧 Agent 没有 diagnostic 字段的历史记录应显示“没有诊断快照”，不能从其 ok 推断全部映射已注册。

服务端只保存固定枚举、时间、配置 ID 和计数；不保存代理原始错误、名称、地址、配置正文或凭据。只有当前设备的配置 ID 可进入其报告。仍由设备身份提供观察数据，后端不把这些值作为授权依据。

## 持久化与兼容

新增 `agent_command.diagnostic_data`（varchar(512)、非空、空串默认值）。先在维护窗口用已有显式 migrate 更新后端，再启动新后端和 Agent；启动检查会拒绝缺列或列定义不匹配。迁移对旧行填空值，不编造诊断。没有操作现有生产库。

新 Agent 的心跳版本为 cloudnest-agent-0.2.0；发送诊断快照需要本版后端。新后端继续接受不带 diagnostic 的旧回执，但不为它补造报告。新 Agent 不应先于后端升级：旧后端会拒绝未知字段。

观察结果先随加密的本地命令结果保存，再提交到服务器。回执丢失、Agent 重启或同命令换租约重领时发送同一观察时间和数量，不重新探测并替换历史。服务器将状态、摘要和审计在同一事务提交；完全相同的终态可重试，变更观察时间/数量返回 409。非 diagnose 动作不能附带报告，额外字段、计数矛盾或跨设备配置被拒绝。

## 本机状态通道

官方 0.71.1 的管理接口支持 [代理状态](https://github.com/fatedier/frp/blob/v0.71.1/client/http/controller.go) 和配置修改等操作，不能把它当作只读接口。CloudNest 只调用 GET /api/status，端口固定绑定 127.0.0.1，每次启动分配回环端口并生成独立的随机 256-bit Basic 凭据与 TLS 证书。HTTP 客户端只信任该次证书，不使用宿主代理、不跟随重定向，单次查询上限两秒、正文上限 512 KiB。远程配置仍不允许 webServer 或任何文件/命令加载器。

[官方 HTTP 服务](https://github.com/fatedier/frp/blob/v0.71.1/pkg/util/http/server.go) 没有在此处启用客户端证书验证，因此本实现使用证书校验加 Basic 鉴权，不宣称双向 TLS。TLS 私钥通过继承的 fd 5 提供，FRP token 仍通过 fd 4 提供；两者不进入文件、参数或环境。

随机 Basic 凭据在启动阶段短暂写入 0600 的 active.json；公共证书写入 diagnostics.pem。Agent 成功通过可信状态 API 读取后立即删除这两项，映射未注册时也会删除。正常停止、异常进程回收、下次启动与显式旧状态迁移继续清理遗留缓存。状态只在内存中保留本次本机访问凭据，后续诊断不重建明文文件。CloudNest 的 reload 是生成新的运行配置并重启，不调用 frpc 的管理 reload。

这种启动交接不能擦除瞬间生成的磁盘快照/历史版本；双故障在交接完成前也可能遗留短暂凭据。运行设备和备份仍需保护。同一用户能控制 Agent 私有文件或进程时，本机管理端口不是额外的权限隔离边界；端口不会发布到远程映射、命令结果或用户 API。

## 验证与剩余范围

实际官方 frpc 测试覆盖：进程活着但没有 FRP 控制连接时报告 starting；未认证或错误凭据被拒绝；假冒回环 TLS 被拒绝。真实 Agent/后端/frpc/frps 测试将一个 TCP 映射改为 frps 不允许的端口，进程仍存活，但用户命令历史中显示 degraded、两条注册成功、一条失败；恢复配置后重新显示三条已注册。

隔离 MySQL 测试覆盖已有命令行的列迁移、启动缺列拒绝、无效报告、跨设备配置、不可变回执与单次审计、旧无报告回执；本地恢复测试覆盖重启/新租约后仍重发原始观察。精确执行结果见 [测试记录](TESTING.md)。

逐条映射的持续状态、上游可达性与脱敏故障原因、长期离线/睡眠、Linux 服务部署及真实公网部署仍在 G05 待办中，本批不把注册快照推广为这些能力。
