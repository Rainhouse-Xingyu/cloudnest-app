# FRP 映射分配、并发写入与升级

本批修复旧映射 API 的数据库并发语义。`frp_mapping` 仍是一个全局命名空间，**不是按 frps 服务器隔离的资源注册表**。数据库中的预留也不证明远端端口已释放或隧道已注册；真实进程状态见 [注册诊断](FRP-AGENT-DIAGNOSTICS.md)。

## 写入协议

创建、修改、删除统一进入最多五秒的 READ COMMITTED 事务，锁顺序为 `frp_mapping_pool(id=1)` → 设备所有者 → 设备 → 映射。数据库行锁覆盖不同后端进程；运行时不创建缺失的锁行，也没有不加锁的回退路径。设备归属的首次读取只用于确定锁顺序，取得锁后重新核对归属和启用状态。旧所有者不能借助等待前的检查继续写入；禁用设备仍允许所有者删除映射。账号禁用时拒绝写入。

自动端口范围保持 20000–20999，一次有界查询取已占用端口，选最小空位，插入和审计提交后才释放锁。固定端口仍支持 1–65535；禁用映射仍占用其端口。显式重复端口或域名返回 409，自动池耗尽返回 409。锁等待超时、死锁或缺失锁行返回 503，不自动重放写入。网络失联导致提交结果不明时，调用方应先查询映射列表再决定重试创建。

每次成功写入与 `frp_mapping_create/update/delete` 审计同事务。审计只含映射 ID、设备 ID、操作者及客户端 IP；失败全部回滚。修改响应取自该事务的结果，不在提交后重新查询可能被其他请求改写的记录。

创建/修改校验端口范围、状态只能为 0/1、域名长度和 DNS 标签；拒绝路径、端口后缀、用户信息、模板、域名内部控制字符、非法标签。明确传入 `status=0` 保持禁用，避免 GORM 的旧 `default:1` 标签把零值改成启用。

## 域名键

`cn_domain_key_v1` 是数据库生成列，`uq_frp_domain_v1` 是完整唯一索引。空域名生成 NULL，允许多个 TCP 映射。HTTP 的裸域名与 `http://` 前缀共用一个键；大小写和末尾 DNS 点不产生不同预留。HTTPS 使用独立协议键，支持 HTTP/HTTPS 各自监听相同主机名。通配域名保留 FRP 原有语义，通配符与其覆盖的具体域名不是同一个键。

新写入将 HTTP 域名保存为小写裸主机名、HTTPS 保存为小写 `https://主机名`；历史 `domain` 原文不重写。数据库生成列同时约束直接 SQL 和旧程序写入的常见域名别名。自动分配的串行语义要求所有写实例升级；旧程序不持有池锁，不能混跑。

## 显式升级

1. 备份并停止旧后端写实例；在备份副本中演练。普通启动不修改结构。
2. 使用已有服务端 `migrate` 命令，新增 `frp_mapping_pool`、锁行及域名生成列/唯一索引。新增列与索引由同一个 MySQL ALTER 原子安装，不删除或重写历史映射。
3. 若历史映射存在规范化后的重复域名，迁移失败，原有行保留。操作者必须先确认映射归属、在用配置和远端占用，再决定如何处置；迁移不自动选择“保留哪一条”。失败后可以重新执行。
4. 启动只读核对生成表达式、列类型/排序规则、完整唯一索引、InnoDB 表和池主键/锁行。缺失、篡改、部分结构都不能作为已完成升级。已有但不符合定义的对象不会被本迁移静默替换。

本批仍使用项目已有显式 `migrate` 流程，未宣称整个旧模型 AutoMigrate 已转为版本化迁移。生产数据、生产结构和真实 FRP 服务器均未操作。

## 验证与未完成边界

隔离 MySQL/Redis 测试覆盖 24 并发自动分配、跨所有者域名竞争、真实 HTTP 固定端口竞争、1000 端口池耗尽/空位复用、直接 SQL 唯一性、创建禁用状态、非法修改、三种写入的审计故障回滚，以及设备转移发生在归属读取与加锁之间的确定性交错。另覆盖锁等待取消、修改冲突、删除后预留释放、缺失/篡改结构拒绝、历史重复数据迁移失败且保留所有行、恢复及重复迁移。执行结果见 [测试记录](TESTING.md)。

FRP-004 继续开放：多 frps 服务器注册与作用域、配置版本/在用进程占用的预留生命周期、已有孤立映射治理及退役后预留释放、周期离线策略及生产升级演练仍未完成。删除数据库映射不会立即撤销已下发配置或停止正在运行的 frpc。后续必须结合配置/命令/诊断协议完成这些生命周期；本次事务分配不能替代真实隧道验收。

设备删除现保留原身份行、配置历史和映射预留，见 [退役协议](FRP-DEVICE-RETIREMENT.md)；这避免继续产生无设备归属的历史映射，不自动修复既有孤立行。
