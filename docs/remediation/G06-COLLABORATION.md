# G06 协作权限

空间所有者可以新增、改派或移除普通成员和空间管理员。空间管理员只能管理 member、viewer、editor。空间所有者身份由 workspace.owner_id 确定，成员接口不能转让所有权。viewer、editor 和旧版 member 可以查看所在空间的成员列表。站点管理员使用同样的空间成员规则。

成员写入先锁定空间记录，再复核操作者和目标角色。创建空间时，空间、所有者成员记录和审计一次提交。新增、改派、移除成员也与审计同事务提交。

只有文件所有者可以授予或撤销文件协作者权限。已有 write 授权继续用于文件内容操作。若历史上为同一人保留了多条授权，新的授予或降级操作更新全部匹配记录，撤销删除全部匹配授权。授权变更和审计使用同一事务。

新空间在创建事务中分配根目录。创建和列表响应返回 `root_file_id`，客户端用它作为 `/api/files?parent_id=…` 的目录 ID。根目录不出现在个人根目录列表，且不能重命名、移动、复制或删除。目录创建、上传完成和复制继承目标目录的空间归属。

| 角色 | 空间文件访问 |
| --- | --- |
| owner、admin、editor | 列表、搜索、下载、建目录、上传、空间内移动和复制、重命名、移入回收站和恢复 |
| viewer、member | 列表、搜索、下载与读取已有索引 |
| 非成员 | 无访问权，即使此前上传过该文件 |

空间文件使用空间成员角色。单文件转授权、公开分享、跨空间移动及复制出空间均拒绝。编辑者可从个人目录复制已获读权限的文件到空间。永久删除仍要求文件记录所有者身份和有效的空间写权限。已发出的下载使用原有读取租约，成员变更影响后续请求。

运行显式 `cloudnest migrate` 新增可空的 `workspace.root_file_id` 和唯一索引。旧空间保持空根 ID，既有文件继续使用文件所有者和显式授权。历史空间转换需另行定义数据归属和授权预检。
