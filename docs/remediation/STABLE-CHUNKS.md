# 不可变分片与上传入口预算

2026-10-23，G03 进行中。本批在独立 disposable MySQL/Redis 与临时文件验证，不操作生产数据，不将固定文件前缀当成旧数据清理授权。

## 不覆盖已确认内容

此前 upload/chunk 在任务校验前完整解析 multipart，直接覆盖 `<upload_id>/<index>.part`；错误 MD5 还会删除同一路径。并发重试因此可能改写或删除已确认的内容。现在新增 task.chunk_protocol=1；新任务使用独立 256-bit 随机路径 `storage/.chunks-v1/chunk-<token>.part`，Root/O_EXCL 创建，0600 文件、0700 新目录，拒绝越界、符号链接或组/其他用户可写组件。客户端文件名不参与路径。

流式写入时计算 SHA-256 和兼容旧客户端的 MD5，核对精确分片长度与 MD5，再 Sync 文件、关闭文件、Sync 目录/存储根及父目录，之后才进入元数据事务。服务端 SHA-256 保存在 upload_chunk.sha256，MD5 保存在 md5；不会以客户端 MD5 代替服务端完整性判断。

元数据仍先锁策略/用户、再锁任务，并重查归属、状态、期限及固定形状。同一任务/索引只有一行：没有行时发布本次独立路径；已有行时只接受相同长度、SHA-256 和 MD5，并重新校验其原路径。相同内容重试返回 200 且原路径/进度不变；不同内容 409，错误长度/MD5 为 400，损坏的已确认分片为 409，不自动覆盖修复。取消或完成后到达的写入不能再提交，已接受的字节也不会被它删除。

只在确定未提交或确定未采用本次候选时清理本次路径；未知提交保留候选供后续对账。本报告首批没有持久日志；后续新任务已追加 [候选登记/回收](TRANSFER-REGISTRY.md)，旧未登记文件仍不自动认领。

## 不可变合并清单

完成预检读取按索引排序且有界的数据库清单，验证每个索引、精确长度和 SHA-256；不再按猜测的固定磁盘路径合并。合并从锚定 Root 打开每个清单文件，检查普通文件/长度，流式校验每片 SHA-256，同时计算最终对象 SHA-256。长度不符 400，同长度字节损坏或路径不可信 409；不发布部分内容。

完成事务与回执/初始版本/额度核销/审计保持同一边界。确认提交后由持久登记回收器验证清单的任务/引用/FD 锁，再记录删除意图、unlink/Sync 与释放额度，不再 RemoveAll 上传目录；其他进行中请求有独立候选，不被整目录清理误删。并发完成仍通过原始回执处理清单/物理文件已被另一完成者清理的窗口。回执复用不重复清理或分析。

## 入口资源契约

| 限制 | 当前值/行为 |
|---|---|
| 单片声明 | 最高 64 MiB，实际必须等于声明的正常片大小或末片余数 |
| 单任务分片数 | 最高 16,384；初始化仍做无溢出的 ceil 及显式数量一致性检查 |
| 单文件声明 | 最高 1 TiB；同时满足分片数/大小约束，不代表已经实传 1 TiB |
| 元数据/封装 | 任务确认前最多读取 64 KiB，之后全请求最多为精确片长 + 64 KiB；有/无 Content-Length 都适用 |
| multipart | 先三个元信息字段（次序可变），再唯一 chunk 文件；字段各最多 1,024 字节；重复/未知/空字段、多文件、截断体拒绝 |
| init/complete/cancel JSON | 最多 16 KiB；超出作为无效请求拒绝 |
| 活动请求体 | 共享 Redis 原子准入：每用户最多 2 个、全局最多 16 个；超出 429/Retry-After: 1 |
| 请求期限 | 分片读取/写入/限速等待总计最多 4 分钟，超时 408；服务本身请求读取超时 5 分钟、请求头 10 秒 |

multipart 使用流式 Reader，不借 ParseMultipartForm 在系统临时目录完整缓冲/落盘。先验证身份/业务路由和准入，再有界读取元信息；冻结 iOS 本来就先写三字段再写文件、分片为 5 MiB，无源码修改。客户端需结合文件大小选择分片，使片数不超限；低速下还需保证单片能在期限内传完。macOS 继续按实际服务端错误区分 400/408/409/413/429/503。

Redis 时间负责过期准入 token，单 token 比请求期限多保留 30 秒，正常结束仅移除自身 token；释放失败记录通用日志并等待过期，不扩大额度。脚本失败 503，不能静默放行；部署 ACL 需允许本入口脚本的 TIME/ZSET/PEXPIRE 操作及对应键空间。嵌入式 HTTP writer 必须支持 ResponseController 读取期限，不支持时拒绝 503。完整合法请求读取 HTTP envelope 到 EOF 后保留连接复用；HTTP/1 处理结束时仅对未读完的 body 收紧期限，阻止后台继续等待，不能清空期限。net/http 在下一请求/空闲阶段自行重设。HTTP/2 保留流期限；专项验证仍待 G10。

限速写入用可取消 timer，不再无条件 Sleep。当前速率选择仍沿用旧 query 优先语义；管理员上限不可被请求参数提高、峰时策略和下载 Range 限速仍需后续统一整改，不能据可取消等待就宣称全部速率策略已闭环。

这些是**活动请求和单任务清单的预算**，不是全局持久磁盘预算：已确认分片、取消/过期后的分片、未知提交/崩溃候选仍可能积累。用户逻辑容量预留也不是临时空间预留。后续已追加新上传候选登记、合并预留、FD 锁/租约及临时卷预算，详见临时对象报告；ZIP/缓存预算和主机恢复仍待做。没有按年龄/前缀删除未知旧文件的命令。

## 升级

停旧写实例并备份、在副本审核后显式 migrate 增加 chunk_protocol（默认 0）和两个摘要字段（默认空）。普通启动核对字段与 (upload_id,chunk_index) 唯一索引，不隐式迁移。新任务为协议 1；旧未完成任务不自动获得已验证分片来源，继续/完成/进度查询返回 409，所有者仍可取消以释放逻辑预留，原物理文件保留。旧已完成任务的有效回执仍可复用；没有回执仍明确提示已完成/结果不可恢复。不能同时运行会覆写旧路径的写实例。

## 验证与限制

本批新增 16 项真实集成，覆盖相同/不同内容跨路由并发、错误重试不删除原片、精确长度/末片/有序字节、multipart 歧义与截断、同长度篡改/越界/符号链接、元数据故障回滚、旧结构不认领/回执兼容、声明/JSON/有无长度体积预算、共享/过期/全局准入、真实 TCP 正常 Content-Length/chunked 上传、慢体超时/错误请求不后台等待、取消时中断限速、实际 Redis 脚本权限拒绝，以及晚到写入与取消/完成竞争。最终完整 140 项开启 race 通过（144.943s），go mod verify、make check、make test 通过；结果见 [TESTING](TESTING.md)，远端按最终 SHA 核验。

前两轮定向发现截断 multipart 被映射成 500，已改成 400；第一次完整回归另发现大头部夹具少了 boundary 前的换行，提前 400 而非进入 413 预算检查，修正后已用真实 chunked TCP 和受计量的 Reader 验证。没有通过放宽产品限制迎合夹具。内存 Recorder 的期限适配仅用于已经在内存的测试请求；真实 TCP 测试使用标准服务器 writer，验证实际 deadline。

后续已实测登记对象持锁子进程 SIGKILL 和真实服务慢体 SIGTERM；尚未实测主机断电、HTTP/2、多主机/网络文件系统、大文件性能或峰值内存；显式 Sync 及有界缓冲不是这些验收的替代品。候选的已确认错误清理、成功清单清理已验证，新登记候选已接入受控对账，半登记等不能证明归属的对象保留收费；旧未登记对象和主机恢复仍未完成。完整 G03 与 G00–G11 目标继续推进。
