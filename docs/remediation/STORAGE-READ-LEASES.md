# 物理对象读取租约

2026-10-22，G02 进行中。数据库引用约束不能代表正在读取：请求取得文件指针后，另一个请求可能永久删除逻辑文件/版本。因此在物理读取期间还需要独立保留记录。本批实现读取租约及活动状态前置，尚未实现物理回收。

## 结构与协议

显式 `migrate` 增加 storage.state（VARCHAR(24)，NOT NULL，默认 active）及内部 storage_read_lease 表。旧对象只补活动状态，不移动路径，不自动认领为可回收对象。租约包含随机 256-bit token、storage_id、微秒精度 expires_at，索引覆盖对象和到期时间；到 storage.id 的外键为 DELETE/UPDATE RESTRICT。字段不加入客户端 DTO，也没有创建/续租的公开 API。

每个 HTTP 请求创建惰性的读取 scope，无物理读取则不访问租约表。授权仍由文件/版本/分享/AI 的既有规则完成；租约不是授权凭据。Pin 在短事务中对 storage 行取共享锁，确认 state=active，再创建租约；返回数据库中的新路径。同一 scope 同一对象复用 token 和第一次固定的不可变路径；不同请求独立 token。已校验上传修复只改指针并保留旧路径，不能删掉现有读者固定的旧对象。

生产默认租约 60 秒、每 20 秒续期，期限由数据库 UTC_TIMESTAMP(6) 计算，不依赖应用主机墙上时钟。应用使用从数据库往返前开始计算的单调时钟期限，最多使用 TTL 的 80%，给数据库往返和调度保留余量。续租再次共享锁定活动父记录，仅更新仍未到期且匹配 token/storage_id 的行；过期、消失或不活动时拒绝，不复活旧 token。单次租约操作最多五秒，短 TTL 集成夹具使用更短操作超时。

续租失败或本地保护期到期会取消整个 scope；后续 HTTP Write/WriteString/Flush 检查保护，不继续输出对象字节。首次响应尚未写出时返回通用 503，并移除文件 Content-Length/Disposition/Range；已输出字节时停止后续写入，不向文件正文追加错误 JSON。已经交给网络/系统调用的字节不能撤回，打开文件描述符也不是可由 Go 强行中断的普通文件读取。下载限速等待改为可被请求取消唤醒。

结束时取消并等待本 scope 的续租循环，再用独立短上下文删除自己的 token；不会清空租约表或删除其他读者。清理失败记录通用日志，留下有期限的行。提交结果未知时可能留下未纳入内存集合的 token，它仍会到期；不能据此解除保护。过期行的物理清理和 GC 协同仍待下一步实现，因此当前可能保守地多保留记录。

## 覆盖范围

| 消费者 | 读取边界 |
|---|---|
| 普通下载、Range/视频、预览、缩略图 | FileService 授权后 Pin；G03 输出以已校验同一 FD 消费，见 DOWNLOAD-INTEGRITY |
| 历史版本下载 | 先完成版本/来源/ACL 元数据快照，再 Pin；G03 在输出处校验 SHA-256/尺寸并复用同一 FD |
| 私有/公开目录 ZIP、批量包 | 一致快照验证全清单；释放事务后逐对象 Pin，刷新路径并检查普通文件；写包和传输共用请求 scope |
| 公开单文件分享 | 验证分享者当前身份和资源权限后 Pin |
| 前台 AI OCR/摘要 | GetReadableFileAndStorage 授权后 Pin |
| 上传后后台自动分析 | 独立三分钟上下文和独立 scope；HTTP 完成不取消它，分析结束释放 |
| 上传候选/版本发布中的完整性校验 | 候选属于当前请求；已发布对象由写事务的引用/行锁保护，不在写事务内另申请租约 |

元数据快照先释放连接再申请租约，支持连接池仅有一个连接，避免自己等待自己。快照完成到 Pin 之间对象已消失/开始退出活动状态时，读取失败，不拿旧路径继续传。取得读取资格后的权限撤销不即时中断现有请求，后续请求重新授权，沿用之前明确的行为。

中间件结束后还原 Gin 原始 Writer，防止其默认 404 在已关闭 scope 上被误改成 503。元数据接口、登录和不存在路由不创建租约。

## 升级及限制

停旧写实例、备份、在副本检查后显式执行基础 migrate，再按已有名称和引用迁移步骤升级。普通启动只读校验 state、租约列/主键/索引/RESTRICT 外键；缺失或漂移时退出。基础模型迁移仍未纳入全项目版本迁移框架（G10），不能把空库及 disposable 升级推断成真实库验收。不要混跑缺少租约的旧读实例。

后续 GC 必须锁定同一个 storage 父记录，检查全部 file/version 引用、活动租约及对象管理来源；不能仅检查 state 或年龄。过期租约外键仍保守阻止父记录删除，回收协议需在事务中校验期限并有选择地清理；当前没有回收执行命令。旧路径、孤儿候选、路径越界/符号链接、防误认领、隔离/恢复日志和数据库/磁盘崩溃对账仍未完成。

大量对象包逐个获取/续租的 SQL 成本未做规模压测。无法及时完成续租时会失败停止，不延长本地保护假装安全。进程退出后 token 可留到期；当前没有自动过期清理 worker。文件已打开后本地 CPU 提取/解码不一定即时响应取消；停止后续 HTTP 输出和上下文相关数据库/网络工作，不宣称能强制终止所有系统调用。

## 验证记录

新增 11 项真实 MySQL/Redis/API 集成：独立 token/复用与固定路径、租约外键保留父对象、超过原 TTL 的续租、取消/清理、过期不可复活/不活动对象拒绝、租约丢失停止已开始的响应、首次失败 503、当前/历史/Range/ZIP/批量/公开下载在实际输出时持有租约且完成释放、单连接池、权限拒绝不创建租约、前台 AI 缺 scope 拒绝、旧结构显式升级/expiry 索引漂移拒绝、清理故障保留带期限 token、默认 404/元数据不受影响，以及后台分析在 HTTP 结束后仍持有独立租约。AI 测试使用真实临时图片并注入明确失败的模型传输，只验证读取保留，不返回或宣称模型成功。

首轮定向包下载夹具写错路由，改为实际 download-zip；检查同时发现 Gin 默认 404 的 Writer 生命周期问题并补了回归。另将元数据事务内租约获取移到事务结束后，并在真实单连接池验证。最终完整结果见 [测试记录](TESTING.md)。全部改表、租约和文件验证均限 disposable 容器及临时文件，未操作生产数据。

后续已接入 [分阶段 GC 与有界过期清理](STORAGE-GC.md)：维护操作与读者锁定同一父记录，覆盖全部持久引用/有效租约；只删除明确登记的新对象，旧/未知对象仍保留。前文“无过期清理/物理 GC”为本报告初版状态，以此后续报告和 TESTING 为准。

G03 受控上传暂停会取消读取中的 HTTP body。响应保护现允许从未 Pin 且无 Pin 错误的纯元数据响应在请求取消后返回正确状态；持有租约、Pin 已失败或 scope 关闭仍严格检查，物理读取不放宽。真实暂停 TCP 与全部读取租约回归共同验证，详见 [上传控制](UPLOAD-CONTROL.md)。

G03 下载身份批次进一步移除“校验后重开路径”的窗口，条件响应也先授权/Pin/完整校验；首次保护失败同时清理 ETag/Repr-Digest/Content-Digest/Last-Modified。FD 路径替换回归通过，但这不保护外部原地改写，仍依赖服务端不可变发布约束；详见 DOWNLOAD-INTEGRITY。
