# 原生连续下载与 1 GiB 恢复验收

2026-11-21 UTC，G08 进行中。本批不改数据库协议、生产数据或后端下载实现。

## 问题与修复

原生客户端原来每个 4 MiB 磁盘检查点重新请求一个 Range；服务端每次请求都先校验整对象摘要，导致大文件重复全量读取。实际 9 MiB + 173 字节 Core→Go 回归在修复前发出 3 次下载请求，Go 请求预算断言失败（包 25.037s，`/tmp/cloudnest-native-stream-before.log`）。

普通下载现请求 `bytes=<confirmed>-`，维持一个连续响应。DownloadStream 的逐块确认/背压和 4 MiB 磁盘检查点保持不变；恢复仍携带原强 ETag 的 If-Range，先校验本地前缀、截断未确认后缀，最后校验完整 SHA-256 并原子保存。完成检查点仍用 0–0 探测；未知空文件与 416 的完整请求回退保持原规则。响应必须覆盖整个剩余表示，新单测拒绝被截短的 206。

修复后同一真实回归通过（22.520s）。追加严格计数后最终通过（包 24.006s，`/tmp/cloudnest-native-stream-exact-final.log`）：专用 transport 标记经 Go 包装器计数，Swift 通过真实认证 `/api/auth/me` 的测试响应头确认恰好 1 次；Go 另拒绝超过 1 次。此响应头仅存在于测试夹具，不进入产品路由。受限账户跳过该写用例，不计作执行通过。

## 可重复的四进程验收

在 macOS 上准备私有 MySQL、Redis 和 Go 后运行：

```sh
python3 scripts/test-macos-backend.py --large-file --report /tmp/new-native-large-file.json
```

报告必须是现有目录中的新文件；独占创建、不覆盖旧证据。可通过既有 `CLOUDNEST_TEST_MYSQL_PREFIX` / `CLOUDNEST_TEST_REDIS_BINARY` 选择依赖。该选项不能与 `--filter` 或手动 UI 服务组合，临时卷至少留 8 GiB。普通 CI 只编译该 opt-in 用例，不隐式进行 GiB 传输。专用 runner 管理 Go/Swift 子进程组，退出或中断时回收自己启动的工作进程。

测试使用真实路由、loopback TLS、隔离 MySQL/Redis，上传/下载策略均显式为 10,240 KiB/s。源为 1,073,741,997 字节（1 GiB + 173），以 1 MiB 有界块生成；每块 0…255 重复序列，前八字节写入递增 UInt64 小端块号。这是确定性数据，不声称不可压缩；下载请求使用 identity 编码。

四个独立 Swift 进程依次执行上传暂停、上传恢复、下载暂停、下载恢复；各进程重新登录，共享同一私有 journal。上传/下载在确认 541,065,216 字节后暂停并关闭 manager、退出进程。下载暂停后另写未确认尾部，下个进程必须核对前缀并截断。最终源、任务与下载 SHA-256 均为 `fdf61503926da9ee3a2d8ca59e1a8b3a798abef83ac8467ed381114cfa554c3c`，结果大小正确，无残留 part 文件。

每个进程均低于原定 512 MiB 门槛。上传两阶段合计 121.740s，按完整对象计算约 8.411 MiB/s；下载合计 105.009s，约 9.752 MiB/s。阶段包含清单/前缀/整文件校验、控制、合并或保存，不含进程启动、源生成与人工等待；这不是裸网络峰值或生产 SLA。Go 验收 240.51s，包 242.338s。

服务端独立记录恰好两次 206：初始 `bytes=0-`，恢复 `bytes=541065216-` 且 If-Range 等于原强 ETag。初次响应写出 541,294,592 字节，多于已确认检查点是取消前的在途数据；恢复从持久确认值起算。每个进程退出后，下载 handler 须在 5 秒内释放。

首轮验收失败也原样保留：[MACOS-LARGE-FILE-20261121-OBSERVER-FAILURE.json](MACOS-LARGE-FILE-20261121-OBSERVER-FAILURE.json)，`passed=false`。前三阶段通过后，测试观察器把产品取消响应的 `http.ErrAbortHandler` 当作未释放，因为计数只在正常返回路径减少。观察器现用 defer 记录并释放计数，未改生产行为、未放宽 5 秒阈值。完整同尺寸四进程重跑通过。

报告里的 `git_head=a50e762…` 是当时工作树的基线提交，连续下载改动当时尚未提交。报告另外保存全部 App/Core Swift 文件 SHA-256，已逐个与本批产品源码核对一致，不能把基线 SHA 单独当作新改动验收标识。

## 实际原生窗口

同日以当前 App/Core 构建独立验收入口，macOS 27.2.1 arm64，证书固定于私有 TLS 服务，会话仅存内存。专用应用可执行文件 SHA-256 为 `cad4b0ba44df0e07e20d0483c8a42de3533421f4c7bb91afc8b7ea77cd6dcda8`。GUI 仍操作实际 Table、文件面板、保存面板与 TransferManager，不用伪造进度。

上传在 549,453,824 字节暂停，正常 Quit 后重开、重新登录、继续完成；下载在 742,391,808 字节暂停，第二次 Quit/重开/登录后继续完成。最终两行均显示“已完成 · 1.07 GB”；两任务持久 phase=completed、confirmedBytes=totalBytes=1,073,741,997。CLI 以 1 MiB 块回读源与下载文件，摘要与上述完全一致，无 part 文件。应用最终正常退出，私有服务收到 stop 后退出 0。

[GUI 记录](MACOS-LARGE-FILE-GUI-20261121.json) 保存三个不同 PID、确认检查点、产品源码指纹和内存观察。只对确切私有可执行文件用 `ps -p <pid> -o rss= -o args=` 每 0.2 秒采样，退出或路径不匹配即结束；RSS KiB 转成字节。PID 41577 / 42240 / 43427 的采样峰值约 144.94 / 212.63 / 171.86 MiB。这些是采样最大值，可能漏掉间隔中的尖峰，与上面的 ru_maxrss 真实高水位分开报告；人工等待也不用于计算 GUI 吞吐率。
