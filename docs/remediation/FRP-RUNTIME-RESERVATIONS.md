# FRP 运行配置资源占用

本批把部署命令和 `forget_config` 回执接入持久占用账本。资源占用表示“该 Agent 可能仍能使用此端口或域名”，不表示实际隧道已经注册或上游可达。真实注册与连通性仍由 Agent 诊断和原生隧道测试验证。

## 登记与冲突

`deploy_config` 在入队事务内解密已授权配置，通过与 Agent 共用的严格 YAML 解码器提取 TCP 端口、HTTP/HTTPS 域名。正文最多 32 KiB、代理最多 512 个；模板、别名、文件加载器和未知字段不能被解释为无资源。无法可靠解析的输入记为 `unknown`，保守地与同一作用域所有资源冲突。没有代理的合法结构不新增监听资源，但不会删除已有占用。

`frp_reservation` 保存原所有者、设备、凭据代次、command_id、config_id、server_id 和资源键。一个命令中的重复键合并。命令、占用和审计一起提交或回滚；同一 request_id 的重试返回原命令，不重复登记。每次不同命令登记自己的可能占用，旧配置的占用继续保留。

托管配置使用稳定服务器 ID；历史配置没有服务器关联，使用作用域 0，并与所有服务器重叠。映射 API 现可显式提供正值 server_id 并使用服务器策略范围；省略时仍为全局作用域 0。映射与账本使用相同重叠规则，详见 [映射协议](FRP-MAPPING-RESERVATIONS.md)。

所有占用写入、映射分配和服务器配置写入先锁同一 `frp_mapping_pool` 行，再按所有者、设备、身份绑定的既有顺序执行。部署检查其他设备的映射与其他凭据代次的运行占用；同一设备当前代次可复用自身资源。创建映射、改换映射资源和自动选端口检查占用。修改本地上游或显示状态不会擅自删除历史运行占用。

删除映射不会释放运行资源；数据库中的配置、映射、设备历史被修改或退役，也不会级联删除账本。HTTP 与 HTTPS 是不同的虚拟主机资源；域名大小写及末尾点统一处理。未知占用使自动端口分配返回冲突，不会绕过不确定历史选择一个看似空闲的端口。

## 唯一自动释放证据

只有排他 `forget_config` 的**首次有效成功回执**会清除该设备、该凭据代次的运行占用。Agent 已先停止真实 frpc、持久保存空恢复配置及成功结果，协议见 [FRP-FORGET-CONFIG](FRP-FORGET-CONFIG.md)。回执状态、占用删除、审计在同一数据库事务；审计失败全部回滚，Agent 可重试。

重复回执在终态幂等检查处返回，不能删除随后新部署产生的占用。普通 stop 保留可再次启动的配置，因此保留占用；命令失败、租约/命令到期、设备离线、凭据撤销、重新注册或设备退役都不是释放证据。新凭据的清除回执不能解除旧物理 Agent 实例的占用。旧映射仍存在时，即使运行占用已释放，映射约束仍阻止别人取得该资源。

该协议依赖受信任 Agent 对自身状态的真实确认，不声称解决复制身份/备份后在多台机器同时运行的问题，也不把数据库端口可用视为远端 frps 已空闲。

## 查询

```http
GET /api/frp/reservations?device_id=12&after_id=0&limit=50
Authorization: Bearer <用户会话>
```

只接受 HTTPS，响应 `Cache-Control: no-store`。device_id 可省略，after_id 为非负 ID，limit 为 1–100。返回 `items` 和 `next_after_id`；空页游标为 0。普通用户只能查看原属自己的占用，管理员可查看全部。设备转移所有者或退役后，这一历史归属保持不变。响应不包含凭据 ID、Agent token、FRP token 或配置正文。

## 显式迁移与升级限制

后端连接和普通启动只验证结构，不自动迁移。`migrate` 新建两张账本表、增加映射 server_id 默认 0，并在共享池锁下把全部既有 frp_config 逐行保留为 `legacy-config:<id>` 的 unknown 记录。不得猜测旧配置属于哪台服务器、是否部署过或哪个凭据代次；不解密、不覆盖、不删除旧配置。无设备归属的历史行记 owner_id/device_id 为 0。回填与单例版本标记 1 原子提交，重跑不重复登记。结构检查验证 InnoDB、关键列、完整索引定义和版本标记。

升级需要先停止旧后端写入，再由运维在已备份环境显式执行迁移。旧版本后端不认识此账本，不能与新版本混合写入。测试仅在 disposable MySQL/Redis 中执行，没有迁移生产库。

存在历史配置的升级会阻止新的冲突分配和部署。新增的可空 `reconciled_at` 列通过显式 `migrate` 安装，已有占用保持有效。新版后端只接受带该列的结构。

## 维护人员对账

管理员可通过占用列表定位记录 ID，数据库维护人员可用以下命令检查单条记录：

```sh
cloudnest reconcile-frp-reservation 42
```

`legacy_execution_enabled` 表示设备尚未建立 Agent 绑定，仍能领取旧 JWT 命令。先建立绑定并确认旧执行端已停用。`current_generation` 表示该记录仍属于当前凭据，应使用正常 `forget_config`。`historical` 表示可进入人工核验，仍需在对应机器和 frps 确认旧进程已停止、可恢复配置已清除，或旧配置已无法通过服务端认证。把核验结果记录在维护工单中。主机失联或仅看到端口空闲不足以解除占用。

核验完成后，在明确选择的数据库上执行：

```sh
cloudnest reconcile-frp-reservation 42 --confirm-decommissioned CHG-42
```

命令再次检查当前身份和旧执行入口。在共享分配锁下标记指定记录并原子写入 `frp.reservation.reconcile` 审计，重复执行返回 `already_reconciled`。证据参数只接受工单编号一类的短标识。输出和审计只包含记录元数据，不读取配置正文或凭据。原配置和账本行均保留，查询通过 `reconciled_at` 展示已解除状态。命令记录的是维护人员提供的确认，不能自行验证远端状态。旧库的生产升级演练和离线设备逐条核验仍需完成。

## 验证范围

集成回归覆盖映射删除/改域名后占用保留、普通 stop/失败/超时/退役/配置删除不释放、并发部署冲突、入队及回执审计回滚、重复回执不清除新占用、旧身份代次保留、HTTP/HTTPS 区分、查询 TLS/归属/脱敏、结构漂移、显式迁移保留与重跑。原生测试同时检查实际三条隧道、stop 后账本保留、forget 后清空、重启不能恢复以及新部署重新登记。

实际执行结果、失败原因和 CI 以 [TESTING](TESTING.md) 为准。整个 G05 及 G00–G11 Goal 继续进行；G01/G02 正式 Review 的读取顺序保持 [DEFERRED-REVIEWS](DEFERRED-REVIEWS.md) 的约定。
