## 命名规则

| 范围/操作 | 规则 |
|---|---|
| 用户根目录 parent_id=0 | 按文件所有者隔离，不用当前编辑者代替所有者 |
| 非根目录 | 同一个 parent_id 共用名称集合，包括不同所有者创建的子项 |
| 新建目录、显式重命名 | 名称已被活动项使用时 409，原对象不变 |
| 上传完成、复制、跨目录移动、恢复 | 保留两份，选择首个可用的 `名称 (1).扩展名`、`名称 (2).扩展名`；文件夹后缀加在完整名称后 |
| 移动到当前目录 | 保持原名称，不制造额外后缀 |
| 回收站 | 已删除条目不占活动名称；恢复时重新分配 |
| 名称校验 | 单个合法 UTF-8 路径组件，最多 255 字符；拒绝空、点/双点、斜杠/反斜杠及控制字符 |

已有接口的首尾空白裁剪保持兼容。新建/重命名不会截断用户输入；自动后缀需要空间时只缩短主文件名，保留扩展名和完整 Unicode 字符。无法在上限内分配时返回 409。大小写、重音等相等规则遵循现有 MySQL 列排序规则；本批未改变排序规则或批量规范化旧名字。

根目录列表仍可能展示已显式分享给用户的其他所有者条目，它们不占调用者个人根目录的名称。移动他人的共享文件到调用者个人根目录被拒绝，避免更改父目录后悄悄落到原所有者根目录；需要个人副本时使用有读权限的复制。

## 事务与并发

新增 `file_namespace` 表，只保存 `root:<owner_id>` / `folder:<parent_id>` 锁键，不保存文件内容。应用通过主键行锁串行化同一个名称集合的写入；跨目录移动按排序后的锁键顺序获取锁。不同目录仍可并行。

新建、重命名、移动、复制、恢复、上传完成均在对应锁内检查/分配名称并落库。使用 READ COMMITTED，避免事务等待锁后继续用旧快照判断名称可用。重命名/移动重读被锁对象；位置变化返回冲突，不按旧作用域写入。元数据事务仅对 MySQL 死锁受害者重试，最多三次；上传完成包含已有磁盘副作用，未套入此自动重试。

删除文件夹同时锁住自身子项的名称集合，在事务内重查是否为空。创建子项在事务内锁定并检查父目录仍有效且可写。因此删除与新建竞争不会留下活跃子项指向已删除父目录。恢复到已删除/不存在父目录返回 404，条目仍保留在回收站。

在应用写入协议之外，新增 [版本化活动名称唯一约束](FILE-NAME-MIGRATION.md)，防止直接 SQL 绕过唯一性。配套 [只读重名审计](FILE-NAME-AUDIT.md)；历史重复数据不自动改名/删除，迁移遇到重名或异常标量会拒绝继续，审核修复流程仍由操作者执行，不能静默清理历史记录。大量同名分配的查询成本与目录锁争用也仍需性能验收。

## 递归操作与分享授权

第二批增加五项修复前失败的真实 API 复现：目录 ZIP 越权读取私有子项、批量下载跳过无权限选择仍返回 200、移动目录越过不可写子项、永久删除越过其他所有者，以及分享者失去读权限后链接仍可用。修复后均通过。

| 操作 | 逐项检查与失败行为 |
|---|---|
| 私有目录 ZIP | 根及全部活动子项均须所有者或显式 read/write；任一拒绝返回 403 |
| 批量下载 | 在同一个只读 REPEATABLE READ 元数据/ACL 快照收集所有根和目录清单；任何失败中止整个包，不返回缺项的成功结果 |
| 公开目录 ZIP | 使用分享创建者的当前权限检查每个子项，不用文件所有者代替创建者 |
| 分享详情/下载 | 创建者账户禁用/删除或根读权限撤销后返回 404；原有过期和撤销校验继续适用 |
| 目录移动 | 根及全部子项（包括回收站子项）均须所有者或显式 write，read 不足以移动；失败回滚全部根 |
| 永久删除 | 根必须在回收站，全部子项必须属于调用者且均已删除；其他所有者 403、仍活动子项 409，完整回滚 |

ZIP 保留合法原始空格和 Unicode 名称、空目录，拒绝非法路径组件、重复完整路径和超出 ZIP 头长度的路径。存储元信息/磁盘文件缺失返回失败；写包过程的打开、复制、关闭错误也会中止并清理临时文件。批量下载按完整最终条目名（含目录的 .zip）预留去重名称，已有数字后缀也参与冲突检查。

永久删除保留历史 operation_log，删除记录与同事务的新审计一起提交；审计失败时回滚子表和文件元数据，记录客户端 IP。物理对象仍保留，安全 GC 另行实现。若已有数据库具备本仓库模型未声明的外键，升级前仍需核对约束，不能直接按空库测试推断兼容。

## 目录树锁定与边界

移动、复制、永久删除先收集有限目录树，再排序锁定来源所有命名范围及目标范围，使用行锁重读；等待期间出现未锁的新范围时返回 409。移动/复制额外拒绝重叠选择根，避免把同一子树重复处理。并发互相移动目录时只有一个成功，另一个冲突，不能生成环。

复制拒绝目标为自身/后代，并限制深度 256、总节点 10000，循环或超限返回 409 并回滚。递归每个来源节点依据当前既有“所有者或显式 read/write”规则检查读权限，任一不可读子项导致整个复制事务回滚；不会凭顶层可读复制他人的私有子项。

所有遍历均有循环检测、深度 256 和节点总数 10000 的上限；元数据遍历查询也限制返回数量。批量下载同时限制累计清单节点数。只读下载在元数据快照完成后释放事务，再读磁盘生成临时包；正在进行的下载不会因后续权限撤销被即时中断，后续请求重新验证权限。磁盘内容本身不是数据库 MVCC 快照，传输/GC 期间的物理对象生命周期仍需后续引用/租约设计。

本批沿用既有逐项所有者/显式授权规则，未增加目录继承；共享顶层目录不会自动赋予子项权限。完整协作继承、跨文件系统名称兼容、超大目录查询性能及更多并发结构变更矩阵仍待后续验收。

## 升级与回滚边界

需停旧服务实例、备份并审核后，用新程序显式执行 migrate，创建 file_namespace。随后需审计并显式执行 migrate-file-names，再 audit-storage-references / migrate-storage-references 安装两条保留引用外键。正常启动检查名称约束完整定义及版本 checksum，不自动建表或安装约束。原 file/user/storage 记录不因本批迁移被删除或重命名；锁行按首次写入惰性创建，后续生命周期清理另行实现。

不能让不使用命名锁的旧实例混跑。回滚旧程序会丢失本批并发保护，应停服审核；无需删除新增表或用户数据。本轮所有 DDL、文件读写和错误注入均在 disposable 测试容器和 Go 临时目录完成，未触碰真实库和历史文件。
