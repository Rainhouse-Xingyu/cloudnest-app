# 原生 Agent 注册与凭据撤销

设备详情的「设备操作」提供申请 Agent 注册码和撤销设备凭据，沿用真实[设备身份协议](G05-DEVICE-IDENTITY.md)。两种操作均输入当前账户密码，并再次确认设备名称、ID 和影响。服务器仍负责所有权、路径权限、设备启用、TLS、限流及事务审计；客户端不提供管理员绕过所有者身份的入口，也不使用用户 JWT 充当 Agent 凭据。

申请返回一次兑换、十分钟有效的注册码；新申请替换待兑换码，当前 Agent 凭据直到新码兑换成功才失效。首次申请还会关闭该设备旧的用户 JWT 执行兼容入口。这些影响在确认前显示。界面只负责发码，目标电脑使用既有 Agent CLI 从 stdin 兑换和保存加密身份，不把码放进命令参数；原生客户端不会领取或展示长期 Agent 凭据。

成功回执严格核对设备 ID、码类型/规范编码及到期时间。设备码只保留在当前窗口状态，不加入 Codable、session vault、远程命令 journal 或日志；屏幕和 AX 均使用安全输入框遮罩。用户明确点击后才复制，关闭或到期后清除窗口持有的码，并仅在剪贴板 changeCount 未变化时清除此轮复制的内容，保留用户之后复制的内容。其他应用已读取的副本无法收回。密码在确认发出时从输入框清除，不持久保存；Swift 字符串不提供内存物理擦除保证。

撤销返回 204，客户端显式接受空回执，不尝试解码空 JSON；其余调用的成功状态仍保持各自契约。服务器确认撤销当前凭据和待兑换码后显示结果。Agent 后续认证被拒绝，不等于所有离线进程已停止或运行占用已释放，历史仍保留。

## 再认证与不确定结果

这两个接口同时用 401 表达当前密码错误和用户会话失效。客户端遇到 401 后，用同一原始 JWT 查询 `/api/auth/me`：查询成功才显示密码验证失败并允许纠正；查询也为 401 时沿用清除失效会话的行为。不会借用后续登录的新 token 做判断。SessionState 的原 token 比较、窗口捕获的服务器/账户身份、关闭/离页取消和迟到结果丢弃继续生效。

确认后的当前窗口只提交一次，密码、权限、参数、设备不存在或限流的明确拒绝可以纠正。网络或坏回执不会被当作安全重发的证明：锁住本表单，要求关闭后核对；需要时重新明确申请，新码替换旧的待兑换码。申请和撤销没有持久幂等 journal，不能借用[远程命令恢复](MACOS-FRP-COMMANDS.md)的保证。真实崩溃、到期前后网络故障等完整矩阵继续留在 G10。
