# 缩略图缓存登记、容量与回收（G03）

2026-10-24，代码完成待审。修复前，真实 API 在共享临时卷额度仅 1 字节时仍成功生成 JPEG；缓存写到未计量目录、无保留期限和回收登记。本批将新缓存纳入既有本机传输卷，保留源授权/完整性检查、解码资源边界和下载身份协议。不是 G03 全部验收，也没有删除用户原文件或旧缓存。

## 登记与发布

新文件位于 `DATA_DIR/storage/.thumbnails-v3/thumbnail-<random-token>.jpg`，不再读取或写入旧 `DATA_DIR/thumbnails/`。每项有 TransferArtifact，kind=thumbnail、task_id=0、transfer_epoch=0，不伪造 UploadTask。新增可空 `cache_key CHAR(64)`；其他类型/已退役记录使用 NULL。缓存键为 `SHA256("thumbnail-v3:<fileID>:<sourceSHA256>:<size>")`，唯一索引 `(volume_id,cache_key)` 限定每个卷同一键只有一个生成代次。格式选择、权限、当前源 Pin 和完整源校验先于缓存查询。

先提交 intent/最少 1 字节预留，再创建 0600 随机文件，记录实际设备/inode 并转 writing。生成期间沿用 90 秒写租约、20 秒续约、FD 排他锁，失败/取消留下的候选用 discard/受控回收处理；未知提交不假定额度已释放。JPEG 直接编码到受预算限制的 Handle，没有额外未登记临时文件。

完整编码成功后 Sync 和目录 Sync，Seal 固定实际尺寸/SHA-256、收缩预留到实际字节并转 ready。持卷 gate 将 FD 降为共享读取锁，再在事务内发布 cached、设置数据库时间起算的 24 小时期限及 `transfer_thumbnail_cache` 审计；审计失败不发布。写句柄停止时保留已发布缓存，后续续约不将缓存期限缩短到 90 秒。读取不续延 24 小时期限，源版本变化会自然产生另一个键。

## 容量与活动准入

| 资源 | 当前策略 |
|---|---|
| 整个临时卷 | 与分片、合并、ZIP 共用已有持久 LimitBytes/MinFreeBytes |
| 缓存字节子预算 | `min(512 MiB, LimitBytes/4)`；包含 thumbnail 的全部未完成回收记录 |
| 缓存条目 | 每卷最多 4096 个非 done/published 条目；blocked/discard/deleting 仍计数 |
| 单个输出 | 最多 8 MiB；先检查上限，拒绝时不写入或淘汰其他缓存 |
| 写前增长 | 64 KiB 量级按需增长，受剩余额度/实际空闲空间裁剪；事务提交后才写 payload |
| 生成活动数 | ZIP 和缩略图合计每卷最多 4 项、同一创建者最多 2 项；cached 不占活动生成槽 |
| 解码准入 | 沿用每进程最多 2 个构建与 512 MiB 估算工作集，见 THUMBNAIL-RESOURCES |

缓存保留期间持续收费；到期、丢失响应、unlink 已成功但 done 审计失败，都不先释放额度。它不增加逻辑用户文件配额，仍受创建者关联、事务锁和全卷限制。源文件通过共享授权访问时，每次都检查调用者对当前源的权限；缓存键不赋予读取原文件的能力。

缓存压力触发有界 FIFO 淘汰：按 CreatedAt/token 选择最多 16 个 cached 候选，逐项核对登记路径、实际 inode/尺寸，并尝试非等待排他锁。只退役已登记且当前无人读取的缓存；writing/未知文件/不确定身份不作为淘汰目标。退役事务清空缓存键、写 discard 和审计，再调用统一回收器。一次准入/增长最多尝试 16 次淘汰，仍受请求期限；无法安全腾出空间时返回 507。它不是 LRU 或公平调度保证，繁忙生成键最多等待 1 秒后返回 503/Retry-After: 1。

降低卷额度不会伪造已释放字节；旧占用仍计量，后续压力/到期回收后才能逐步回到新预算。无效卷策略或错配的 root binding 返回 503，不触发缓存淘汰。

## 读取与清理

命中必须匹配卷/数据库绑定、cache_key、kind、task/epoch、cached 状态和有效期限。打开严格登记的普通文件，持共享 FD 锁，核对设备/inode、实际尺寸和完整 SHA-256，再 rewind 同 FD 发送。JPEG 的强 ETag/Repr-Digest、限速、Range/条件请求沿用现有出口；304 也先检查当前源与缓存完整性。损坏或替换返回 409，不自动覆盖不确定的文件。每次命中仍有完整源预校验和最多 8 MiB 缓存校验成本。

共享 FD 锁持有到 HTTP 响应结束或取消，即使 cached 已到期，回收器也保留正在读取的文件。普通到期由既有 30 秒 worker/显式 reconcile CLI 处理；过期键查询也可触发该项受控回收。清理仍须完整元数据可见性、无未知触发器、受控卷/gate、已登记 inode、Storage/UploadChunk 无引用等既有约束；先提交 deleting/清空键和审计，之后 unlink/目录 Sync，最后 done/审计成功才释放字节。unlink 后失败可以从 deleting 恢复，保留历史登记与审计。

## 显式升级与证据

本批新增 cache_key 列和可见、非前缀、全列唯一索引 idx_transfer_cache。停旧写实例与 worker、备份并在副本演练后显式运行既有 migrate，再执行 schema 检查；普通启动不迁移。检查要求 cache_key 为可空 CHAR(64)、默认 NULL，索引顺序/唯一性/可见性必须正确。旧分片/归档/已退役记录保持 NULL，不认领任何历史缓存。旧二进制不认识 thumbnail/cached 和新列，运行实例、worker、维护 CLI 必须同步升级，不能混跑或直接回滚。没有执行生产库迁移。

新增 13 项真实 MySQL/Redis/磁盘/API 回归覆盖：1 字节卷限制、跨 Manager 复用、保留计量/到期读锁、压力淘汰与旧文件保留、重复/遗弃/过期生成者、坏摘要与路径替换、显式列/索引迁移检查、4096 个阻塞预留的数量准入、ZIP 共用活动准入、发布审计回滚、删除审计恢复、实际 TCP 取消释放锁、输出上限先于 IO/淘汰、缓存命中仍检查源授权/完整性和坏策略/root 拒绝。专项及完整结果另记 TESTING；旧测试未移除。

旧未登记缓存、旧随机临时文件、其他未知文件不采用、不删除，不计入新缓存 4096 条/字节子预算；需独立审计后治理。历史 done/审计元数据也没有数量保留上限。文件/上传任务/版本/操作日志全局数量配额、跨实例 CPU/IO、公平队列、真实大图/大文件吞吐/RSS、断电/主机恢复及生产副本升级仍未验收。缓存写进程 SIGKILL 没有另做专项，本批使用通用 FD 回收证据、真实 TCP 取消和遗弃候选回归，不能据此声称通过断电恢复。
