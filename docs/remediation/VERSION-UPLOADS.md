# 绑定目标的版本上传

G08 为本地文件追加版本提供专用初始化入口，复用经过验证的分片、代次、暂停/继续、完整合并、临时卷登记和持久完成回执。此前真实 API 复现 `POST /api/files/1/versions/upload` 返回 404；客户端没有通过先创建普通文件再引用任意 `storage_id` 绕过这一缺口。

## API 与授权

`POST /api/files/:id/versions/upload` 使用用户 Bearer 身份，必须带一个 `Idempotency-Key`（1–128 位 ASCII 字母、数字、`-`、`_`）。JSON 正文最多 16 KiB：

```json
{
  "filename": "local-source.txt",
  "total_size": 9437357,
  "chunk_size": 4194304,
  "total_chunks": 3,
  "base_version": 2,
  "comment": "更新说明"
}
```

目标取路径 ID，版本基线取用户确认时所见值。说明最多 255 个 Unicode 码点、拒绝 NUL；文件名/总大小/分片数沿用原上传校验。拒绝未知字段，客户端不能提交 `storage_id`、配额所有者、目标父目录或另一个上传 ID。服务端核对活动普通文件及写权限；读协作者不能初始化。新任务采用 `contract_version=2`，持久绑定目标文件、基线、说明和配额所有者，`parent_id=0` 是上传票据协议值，不表示移动文件到根目录。

初始化成功仍返回 `upload_id`、`transfer_epoch`、`status` 和已确认分片，另外包含 `kind=file_version`、`file_id`、`base_version`。进度及暂停/继续响应也返回同一绑定。原生客户端在发送正文前及恢复时验证类型/目标/基线，拒绝无绑定或错绑定响应。普通上传响应保持原格式。自定义 API 策略需要显式授予该初始化入口及既有 chunk/progress/complete/pause/resume/cancel 入口；资源写权限仍在后端单独检查。

分片仍使用 `POST /api/files/upload/chunk`、`X-Upload-Epoch` 和既有分片摘要协议。完成仍使用 `POST /api/files/upload/complete`，正文为票据 `upload_id` 与 `parent_id=0`。客户端从不通过存储 ID 发布新版本。分片预检、分片挂接、恢复和最终发布会重新核对文件写权限和版本基线；撤权或另一版本先发布时拒绝继续，不自动换基线。

## 配额、发布和回执

上传者拥有任务、临时对象及控制权限；逻辑保留字节属于目标文件所有者。配额快照分别统计普通任务的 `user_id` 和版本任务的 `quota_user_id`，初始化/取消/恢复/发布使用目标所有者账本。不同上传者竞争相同所有者额度时由同一账本锁串行预留。新内容以完整大小保守预留，不根据未验证的客户端摘要提前扣减或假定去重。

最终事务锁定任务及目标，检查当前基线、活动状态、写权限、实际合并大小及对象身份，保留旧版本并追加新版本。目标文件 ID、文件名、目录和所有者保持现有值。版本引用、当前文件、索引代次/任务、审计、配额核销、临时对象发布和原始回执同事务提交；失败回滚，不留下额外普通文件。新内容与已有版本相同仍可追加历史，容量依现有每文件/对象计量政策计算。

版本完成回执采用 `result_version=2`，保存当时完整文件响应。重复完成、响应丢失后重建、之后又出现新版本或撤权时，上传者只能取得自己原有的确认回执，不能再次发布或借回执取得当前文件读取权限。回执中的存储 ID不是能力；旧存储引用接口仍要求自己的活动授权来源。票据目标和回执不通过外键永久保留目标文件/物理对象。

## 尚无上传 ID 时取消

初始化响应丢失后重新初始化能恢复原票据，但如果请求尚未分配而文件已换版、被删除或撤权，重新初始化可能一直被拒绝。仅把本地任务改为取消也不能阻止迟到的初始化。

新增 `POST /api/files/upload/cancel-initialization`，使用用户身份及原 `Idempotency-Key`，正文为空或 `{}`，同样限制 16 KiB 并拒绝未知参数。任务已存在时核销真正的所有者预留；已完成则返回 `status=1` 与原 `item`，不能谎报取消。任务尚不存在时，在唯一 `upload_id` 上事务写入终态 `contract_version=3/status=3` 和审计，返回 `status=3`。该取消记录没有目标绑定、存储能力或额度。它与实际初始化的唯一键竞争：取消先提交则迟到初始化冲突；初始化先提交则取消真实任务或返回其原回执。

取消键按认证用户作用域生成，不能取消其他用户的同名键。取消记录与其他已取消任务一样保留，不能随意删除后让原请求键重新分配。任务/取消记录数量预算仍属于 FILE-022 的后续治理。无键的历史丢响应任务无法从此协议追溯，仍依原到期/受控对账机制处理。

原生客户端对“有源清单、尚无 ID”的取消调用这个入口，确认后才显示取消；网络或审计故障保留失败/取消意图以便重试。原服务器没有该入口时，仅普通上传保留原幂等初始化再取消的兼容路径；版本任务绝不回退为普通文件上传。

## 原生流程与检查点

版本窗口提供本地选择面板、可选说明和确认框，确认捕获目标及当时版本。队列类型为新的 `versionUpload`，持久保存目标 ID/名称、基线、说明、源书签/摘要和分片检查点。旧客户端必须因未知枚举拒绝该记录，不能忽略字段后创建普通文件。普通旧记录保持可读。

发布回执必须匹配原目标、大小和 `base+1` 才显示完成。基线或状态冲突时明确提示取消、刷新并重新选择，不以继续按钮悄悄更新基线。任务行区分源文件、目标文件、确认基线及已发布版本；窗口观察到完成后刷新版本列表和文件页。窗口关闭不丢失队列。

## 升级与验证

新增 `upload_task.version_file_id`、`quota_user_id`（可空有符号 bigint）、`version_base`（有符号 bigint，默认 0）、`version_comment`（varchar(255)，默认空字符串），以及目标和额度复合索引。正常启动只读校验完整类型/默认值/索引；显式 `migrate` 才添加结构。旧普通任务保留原值并由 NULL/0 默认表示原契约，没有自动认领旧任务或修改历史时间。

部署前须备份并审核迁移，停止旧写实例，同时升级服务、worker 和维护命令。旧服务明确拒绝 v2/v3 任务，但其旧配额 SQL 不认识新预留，因此不能混跑写实例。回退前须处理新活动任务并保留取消/回执元数据，不能直接删列或改成 v1。真实既有库升级、备份恢复及回退演练仍属 G10，未操作生产数据。

- 14 项版本上传真实 API race 回归，连同既有上传/配额/历史共 66 项顶层回归通过，最后一轮 50.530s。覆盖原始字节保留、固定目标/重放、跨用户/只读拒绝、协作者计入文件所有者、两个上传者 12 请求竞争仅一项预留、撤权前后拒绝且可取消、两项已上传票据竞争仅一次发布、审计失败完整回滚、空版本及暂停/继续、真实 TCP 初始化/完成响应丢失后容器重建、取消先提交阻止迟到初始化，以及显式增量升级保留旧普通任务。
- 本机 Swift 普通测试 20 项实际通过、9 项条件跳过，共注册 29 项；新检查点回归验证目标/基线持久化、旧枚举拒绝及不合法状态、说明码点超限、不匹配目标的完成记录被拒绝。
- 新真实 Swift→TLS/Go/MySQL/Redis 用例 12.609s：9 MiB + 173 字节分块上传在检查点暂停、队列关闭重建；期间另一窗口推进版本，原基线恢复被拒绝，取消后刷新确认新基线才能追加为版本 3。当前下载与替换字节一致，版本 1 与原字节一致，没有额外源文件；错绑定初始化响应在发送正文前被拒绝，未知 ID 仍可按键取消。受限账户按开关跳过此写用例；该用例使用内存会话。

- 新版本上传 GUI 本轮读取独立实例返回 `cgWindowNotFound`，未声称交互/视觉已通过；按确切 PID/路径停止旧构建与私有服务，版本列表/历史下载/恢复和速度的上一轮 GUI 证据不替代本轮新入口。最终提交 CI 和新 GUI 结果另按精确代码更新。
