# 原生协作空间

侧栏「协作空间」读取当前账户可见的空间，提供确认后创建、成员列表、添加/改派/移除，以及托管根目录中的真实文件操作。旧空间的空 `root_file_id` 明确显示尚未迁移，禁用打开文件，不推断或回退到个人根目录。空间文件继续由成员角色鉴权。

## 文件与角色边界

空间使用服务返回的根文件 ID。浏览器目录栈相对该根目录，回到第零层仍是空间根；标题、面包屑、上传目标和新建目录均使用该上下文。新根对象包含空间 ID 和已读角色的写入能力，刷新角色改变时重建浏览器，清除旧选择。角色是查询时的采样，服务器对实际请求重新鉴权。

owner/admin/editor 可写，viewer 和旧 member 只读；查看者仍可预览、查看版本和下载。上传、拖入、新建、重命名、移动/复制、删除及版本写入在只读界面中禁用或不提供，直接调用实际 API 仍受服务器角色检查。个人文件的复制目标可选择已读可写空间；空间文件的移动/复制选择器限定同一空间，不提供复制出空间的选项。实际后端继续拒绝跨空间移动/复制出空间，个人文件复制入空间继承目标归属。

沿用 G08 的同一传输队列、书签、Range/摘要验证和持久恢复；不建立另一套空间下载实现。成员撤销影响后续请求，已取得的读取租约按既有规则处理，不承诺收回已经下载的数据。成员自己上传的空间文件也不能在移除成员后继续读取，文件仍为空间保留。

## 成员写入

所有者可管理非所有者成员和管理员；管理员只能管理非管理员成员。成员接口不能转让所有权。界面按已读角色展示入口，真正的操作者/目标判断仍在服务端空间锁事务内重新执行，站点管理员不额外获得成员管理绕过。

新增可选协议字段，不改数据库：

- 添加请求 `create_only=true`：已存在的成员不被当作新邀请覆盖。
- 改派请求 `expected_role`：只在目标当前角色等于已读角色时写入。
- 删除请求可带 JSON `expected_role`：不存在或角色变化返回 409。

新客户端总是使用上述保护，原有未带字段的正常调用维持原行为。已读角色比较在原空间锁、权限检查与目标保护后执行，冲突不追加成功审计。它比较内容，不是单调版本号，也不消除修改后又恢复原值的 ABA 情况。

成员模型由读取接口绑定空间 ID，更改时拒绝混用另一空间的选中成员。确认框显示空间、账户与目标角色或当前移除角色；旧表单冲突后锁定并要求关闭、刷新、重新核对。明确拒绝的移除可以在刷新并重新确认后再试；未知结果保留本窗口提交锁，需关闭并重新核对。空间创建和成员写入尚无持久幂等意图，丢回执/真实崩溃的完整矩阵继续留 G10。

列表 API 目前未分页：客户端限制空间/成员各最多 5,000 项，响应体分别 4/2 MiB，校验 ID、重复项、角色、根和文本大小；超限拒绝显示，不静默截断。空间与成员读取支持请求替换/离页取消，迟到响应不能复活旧列表。403 清空旧项目/姓名并保留有效会话；操作继续核验原 token 及捕获的服务器/账户身份。
