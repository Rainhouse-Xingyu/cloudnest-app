# G03 传输引擎与完成回执

2026-10-23。基于 G02 文件/对象/配额基础继续开发；G03 进行中，尚未具备完整可靠传输验收。冻结 iOS，不修改其源码。本轮仅操作新建 disposable MySQL/Redis 与临时文件。

## 本轮结果

以前完成请求响应丢失后，重试得到 409；无法从任务确认发布了哪个文件。现在新完成操作把 result_version=1、result_file_id、原始文件 DTO 的 result_json 与 file/初始版本、任务完成/预留核销、审计和计量放在同一事务。失败全部回滚，不出现单独成功的回执或发布。读取数据库实际默认时间后保存回执，首次和重试响应均为原有 `{"item": File}` 结构。

POST /api/files/upload/complete 使用原 upload_id 和固定 parent_id。本人已完成且回执有效时返回原始 200 结果，不重新合并、创建文件/版本、核销配额、清理目录、触发 AI 或绑定 Live Photo。发布后任务期限过去或额度配置变化，不取消已提交的操作。进行中任务仍要求当前目录写权限、有效预留/期限，并在最终事务重查；新发布规则没有放宽。

回执是**原操作的确认**，不是当前文件状态、下载许可或内容仍存在的保证。文件后续可以改名、更新版本、删除及被 GC；重试仍返回原 DTO，不修改这些后续状态。客户端据 ID 确认上传完成，再刷新文件列表/详情；不能把旧 DTO 当作最新文件写回服务器。回执中的文件/存储 ID 没有新增外键和引用保留效力，不能作为创建新版本的来源能力。下载和版本发布继续独立检查当前文件/来源权限。

认证与业务路径权限每次仍运行；只有上传任务所有者能获取回执，禁用账号 401，其他用户 403，改变固定 parent_id 409。本人原目录写权限被撤销后仍可读自己的操作确认，不因此获得新写入能力或其他人的文件。丢失/损坏/不匹配的版本 1 回执返回 503，不根据文件名、时间或哈希猜一个成功结果。

## 并发窗口

1. 读取进行中任务后，另一请求完成并删除分片元数据：分片计数不足时重新读取任务回执。
2. 分片计数完成后，另一请求提交并清理物理分片：合并失败时重新读取已完成回执；没有可靠回执则保留失败，不伪造成功。
3. 临时登记协议下每任务只允许一个合并候选：活动竞争返回可重试 409，胜者完成后重试获取同一 200 回执；事务内再次发现完成也只复用结果，不重跑提交后的副作用。
4. 最初提交结果未知时继续沿用 G02 的保留策略，不因错误响应删除可能已提交的候选；重试可通过数据库回执确定原结果。新登记未提交候选已接入租约/FD 锁与受控对账；旧未登记路径仍保留。

完成回执之后已追加不可变分片与入口预算，解决固定分片路径覆盖/删除竞争，详见 [分片报告](STABLE-CHUNKS.md)。后续已追加分片/合并的持久临时预算与受控回收，见 [临时对象报告](TRANSFER-REGISTRY.md)，不能据此宣称 ZIP/缓存或断电恢复已完成。

## 进度与副作用边界

完成事务正常删除 upload_chunk 行。进度现在明确返回 status=1、progress=100、uploaded_count=total_chunks，uploaded_chunks 和 missing_chunks 都为空列表；空列表表示无需再传输，不表示丢失全部分片，且不会为已完成任务生成超大索引列表。进行中任务的缺片清单/预算仍需后续限制。

重试不会重复触发现有 AI/Live Photo 副作用。首次提交后、启动副作用前崩溃的补偿尚无 outbox；AI 持久调度属于 G04，不能将本轮“仅触发一次”误称为“保证最终分析完成”。现有分析失败仍如实保留，不返回假模型成功。

## 显式升级

停旧写实例，先备份并在副本演练，再执行显式 migrate 增加 upload_task.result_version（smallint NOT NULL DEFAULT 0）、result_file_id（可空有符号 bigint）、result_json（可空 text）。普通启动只核对结构，不隐式升级。结果字段不加 file/storage 外键，永久删除与 GC 不被历史确认记录阻止。

升级前的已完成任务没有可靠原始回执，保持 result_version=0/结果为空；重复完成返回 409，明确提示“upload already completed; original result unavailable”，不反查同名文件自动补记。客户端应刷新已有文件，不自动新建任务重传，避免重复文件。本文回执首批允许 G02 新协议任务完成；后续分片/临时登记升级已拒绝旧未完成任务自动认领，须按最新临时对象报告处理；更早 contract_version=0 任务仍按原约束拒绝。没有迁移、重写或删除真实库数据。本轮仍使用既有显式模型迁移；完整版本化升级/备份恢复验收属 G10。

初次测试编译暴露夹具调用参数/辅助函数名错误，修正后运行；定向回归另发现永久删除后的下载沿用既有授权拒绝 403，而非夹具假设的 404，已改为验证拒绝访问并查实不存在文件行，未修改产品授权来迎合测试。补充旧回执明确提示时，一轮断言误放在“改变固定目录”场景而失败，已移到真正的旧缺失回执场景并完整重跑。最终完整 124 项包含全部修正。真实 TCP 断开是实际网络响应丢失；重建服务容器不是杀进程/断电验证，尚未将其算作后者。
