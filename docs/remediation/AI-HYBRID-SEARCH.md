# 混合检索协议与当前向量索引选择

## 当前链路

`POST /api/ai/search/nl` 已从“LLM 解析条件后 LIKE”改为：确定性元数据约束 → 独立 embedding 查询向量 → 按当前文件权限流式扫描 → 每文件聚合关键词/精确 cosine → RRF 融合 → 再次核对权限与源代次 → 返回片段。当前已有文本索引可以实际参与语义搜索。原 `GET /api/ai/search` 关键词接口保留。

支持文件所有者及显式 read/write 文件授权，默认不把管理员或共享存储对象当作文件读取权限。扫描 SQL 使用 EXISTS 避免多条授权重复结果；内容必须来自当前 storage hash、done 任务、匹配 generation/pipeline 的 document/chunk。返回前再次核对文件未回收、当前授权、文件名、源 hash 和代次。并发撤权、重建、版本内容变更等使旧候选失效。目录继承权限仍按 G06 待办推进，此处不声称已经支持继承授权。

## 排序与接口字段

- 关键词：英文词/标识符、中文相邻双字，去除部分检索套话，最多 32 个去重词；单个有效汉字可检索。按命中比例计算，文件名权重为正文三倍。该算法不是 BM25，词法优化仍须评估。
- 语义：仅比较同 embedding 模型名、digest、维度的归一化向量；坏尺寸、非有限值或坏范数不参与。当前 cosine 候选门槛 0.25 是待完整评估校准的初始值，不是准确率保证或相关概率。
- 每文件只保留各通道最高块分数。两个通道各留前 200 个文件，使用 `1/(60+rank)` 相加（rank 从 1 开始），最终按分数和 file_id 稳定排序。扫描不按文件 ID 截掉输入前缀，靠后的高相关向量仍能胜出。
- 返回最多 200 个候选组成分页窗口，每页最多 100 个。`pagination.total` 是当前可返回窗口内的文件数量，**不是所有命中文件的库级总数**。超过窗口时 `retrieval.window_limited=true`，`retrieval.window_size=200`。
- 每项包含 `score`（融合分数）、`match_sources`（keyword/semantic）、可选 `semantic_score`、`snippet`、`snippet_start_rune`、`chunk_ordinal`、`index_generation`、`has_text_index`。片段最多 240 个 Unicode 字符，位置对应原文 rune 偏移，未伪造模型摘要。
- 为现有客户端保留原文件字段、空 tags/description、`ocr_snippet` 别名；文本片段不等同 OCR，`has_ocr_index=false`。`nl_plan.query` 现明确使用 snake_case，修复原 Go 字段名与既有客户端 DTO 不一致的问题。
- `retrieval.mode` 为 hybrid 或 keyword_fallback；模型端点/响应/身份不可用时提供 `embedding_unavailable` 警告并继续匹配现有正文与文件名。没有成功索引的文件仍能匹配文件名。模型故障不使旧关键词接口依赖模型。

上个月/本月/去年/今年按 Asia/Shanghai 日历转换 UTC，使用上传 create_time 范围（含起点、不含终点）；数据库时间仍应按部署契约使用 UTC。出现“拍摄”且需要时间范围时，当前明确返回空集合和 `capture_time_not_indexed`，**不拿上传时间代替拍摄时间**。EXIF 拍摄时间及图片链路仍待实现。这是已知功能空缺，不是该类查询已验收。

JSON 请求体上限 16 KiB、question 上限 4096 字节；非法请求返回 400。单进程最多同时两次混合检索，模型阶段最多六秒，扫描阶段十秒，总期限二十秒；忙或数据库/扫描失败返回 503，不把未扫描完的前缀冒充完整结果。该准入不是跨实例集群配额。

## 技术选择与范围

当前采用 **MySQL 持久 chunk 向量 + 流式精确扫描** 作为可恢复的初始索引实现。文件、任务、块与成功状态可以在已有数据库中原子更新，当前授权/代次可直接过滤，无额外向量服务的双写、ACL 同步与备份依赖；不迁移业务数据库。

代价是查询的 CPU、数据库 IO 和网络传输随被授权向量数量线性增长（O(N×D)），不是 ANN。请求内只保留各通道的有限候选，完整向量不常驻进程缓存；本批没有测峰值 RSS，因此不宣称特定内存上限。

Qdrant 具备带过滤的 HNSW，也会根据匹配集合大小选择精确扫描；这说明精确扫描可作为小集合策略，但不能据此推断本实现与 Qdrant 性能相同。参考 [Qdrant 过滤与搜索策略](https://qdrant.tech/documentation/search-patterns/vector-search-filtering/)。引入 Qdrant 时仍需保留本系统最后的 MySQL 权限/代次核对，并解决发布失败与索引对账；这是本项目的一致性要求。

选择依据是先有可测、可恢复的精确基线，再用真实语料规模和并发延迟决定是否引入 ANN。当前 10k 向量单次实测可用，不意味着百万文件、多实例或生产 SLA 已验证。若超出当前扫描期限，应增加经验证的索引后端，不能悄悄截断输入或只返回数据库前若干行。

## 实际证据

- 六项 `integration,aisearch` 专项在真实一次性 MySQL/Redis 上通过；覆盖无模型降级、跨用户/显式授权/撤权、过期代次/内容、返回前复核、215 文件中的尾部高相关文件、结果窗口、上传时间范围、拍摄时间未支持提示及请求边界。语义质量不使用该套件的词法夹具证明。
- 真实 `qwen3-embedding:0.6b` 检索查询“寻找数据搬迁与 MySQL 升级的执行步骤”，返回数据库迁移文档第一名，cosine=0.818942，来源 keyword+semantic，带原文片段；另一用户的近似私有文档被排除。模型 digest 不同的向量不参与 cosine，模型断开后已索引文本仍可通过关键词返回。
- 规模测试使用两份真实上传内容及其两个真实 embedding，构造 9,999 个干扰逻辑副本和最后一个相关副本，共 10,000 × 1024 维、40,960,000 字节向量。真实 MySQL/Ollama + 进程内 Gin handler（race）单次查询 1.510170792s，相关文件仍第一名。它是单用户、本机、重复内容的扫描实验，不是 10,000 次上传、10,000 篇独立文档评估，也不是生产网络延迟/并发性能。
- 最终真实模型三项测试通过（包 21.717s），包含独立生产服务自动索引/SIGTERM 测试；普通完整 250 项 race 回归通过（355.678s），新检索专项单独执行并纳入 CI，仍保留原六分钟普通套件期限。完整命令、失败记录与先后范围见 [TESTING](TESTING.md)。
