# G01 设备身份边界设计（G05 实施依据）

状态：设计已记录，尚未实现或完成真实隧道验证。2026-10-21 基于当前 `internal/app/container.go`、`internal/handler/frp_handler.go`、`internal/service/frp_service.go`、`model/models.go` 核对。此文件不授权连接生产 FRP 服务或迁移真实配置。

## 当前证据

所有 `/api/frp/*` 路由目前通过用户 JWT 认证。`ReportDeviceStatus`、`PullNextCommand` 和 `ReportCommandResult` 从用户上下文判断设备所有权，因此拥有用户会话就能扮演其设备。现有 Device 只有所有者、名称、IP、状态等字段，无独立凭据。`SaveConfig` 将包含 frps token 的完整文本写入 `frp_config.config_text`，历史列表返回该模型。上述风险分别登记为 SEC-009/010；设计文件不代表风险已修复。

## 身份与授权决策

用户、CloudNest Agent、frpc→frps 三类凭据分别管理。Agent 不保存用户密码、用户 JWT 或服务端签名密钥；其身份不能访问文件、AI、设置或其他设备。设备 IP 只作网络信息，不作为身份依据。

| 操作 | 所需身份 | 资源范围 |
|---|---|---|
| 创建设备、修改映射、请求部署/重载、查询历史 | 用户会话 + 显式业务权限 + 所有权检查 | 自己的设备；管理员操作单独审计 |
| 生成 enrollment、撤销/重新绑定设备 | 用户会话 + 最近重新验证密码 | 指定设备，不返回现有设备秘密 |
| 消费 enrollment | 一次性随机 enrollment secret | 只能登记该条记录绑定的设备 |
| 上报心跳、领取租约、获取部署配置、提交结果 | 独立设备凭据 | 凭据绑定的唯一 device_id |
| 用户文件、AI、设置、设备管理 | 设备凭据 | 一律拒绝 |
| frpc 连接 frps | 独立 frps 认证材料 | 指定服务器/映射配置 |

新设备接口使用独立路由组与认证中间件，例如 `/api/agent/heartbeat`、`/api/agent/commands/next`、`/api/agent/commands/:id/result`。device_id 从认证上下文取得，不能靠请求体改写。管理员用户会话也不能冒充设备调用此路由组。命令结果还需核验命令的设备归属、租约 ID、有效期及配置版本。

## 注册、轮换与撤销

1. 设备所有者重新验证密码后申请 enrollment；服务端生成至少 32 字节随机 secret，记录哈希、device_id、申请者、过期时间（初始 10 分钟）和消费状态。明文只返回这一次，放在 HTTPS 请求体中，禁止置于 URL、日志或常驻剪贴板。
2. Agent 在本机确认控制服务器身份后提交 enrollment。数据库事务锁定记录，检查未过期、未消费、设备及所有者有效，再标记消费并生成独立随机设备凭据。并发兑换只允许一个成功，不重发同一秘密。
3. 设备凭据由随机公开 ID 和至少 32 字节随机 secret 组成，数据库只保存 secret 哈希及绑定关系；中间件定时无关比较哈希，逐请求检查凭据未撤销、设备启用、所有者启用。macOS 使用 Keychain；其他 Agent 本地凭据文件权限 0600。
4. 轮换必须显式操作并审计。初版采用重新 enrollment 且原子撤销旧凭据；响应丢失需要再次注册，不继续接受已撤销凭据。之后才考虑受严格截止时间约束的双凭据过渡。
5. 删除/禁用设备、禁用所有者和所有权转移同时撤销设备凭据、未消费 enrollment 与未执行命令。用户普通退出登录不等同于删除设备身份；账号被盗恢复应提供明确的“同时撤销所有设备”操作。

注册/认证失败均限流，避免 username/device_id 枚举提示。数据库或凭据读取失败必须拒绝，不能回退到旧用户 JWT。服务端不能通过 Redis 缓存延迟撤销。

## 配置与命令边界

敏感配置采用有版本的密文封装，密钥与 JWT 签名密钥分离、不存数据库、不提交仓库。计划使用 AES-256-GCM，每次写入新 nonce，以 device_id、config_id、schema_version 作为附加认证数据。密钥 ID 支持受控轮换；密钥丢失时明确报错，不能回退明文。现存明文配置只在经操作者审核的显式迁移中转换，迁移和备份均不输出明文。

用户预览、历史列表、审计只返回脱敏结构；Agent 仅能领取分配给自身的配置，通过 TLS 传递，在受限临时文件完成校验后原子替换。不要将 frps token 塞进命令、日志或错误文本。回滚配置也产生新版本和审计事件。

Agent 仅执行结构化白名单动作 start/stop/reload/diagnose/deploy_config，以固定参数调用所固定版本的官方 frpc；不接受任意 shell、命令字符串、可执行路径或越界文件路径。部署先校验配置，失败保留最后可用版本；服务端派发采用持久化租约、ACK、超时重试与终态幂等，替代当前 Redis LPop 即丢失的队列语义。心跳在线时间取服务端接收时间，客户端自报时间仅作诊断。

## 兼容性与实施顺序

G05 实施时，新 Agent 路由先完成独立认证和端到端测试，再删除旧用户路由中的 status/report、commands/next、commands/:command_id/result 能力。保留用户管理、状态查询、部署与历史接口；旧 Agent 需要重新登记，绝不静默把用户 token 转换为设备凭据。冻结 iOS API 快照没有调用上述三个设备执行接口，但 G05 仍需重新跑完整契约测试。

依赖：受控账号恢复/撤权机制 → 明确的数据迁移 → enrollment/设备凭据 → 加密配置 → 持久命令/官方 frpc Agent → 真实 TCP/HTTP/HTTPS。G01 仅确定边界；G05 落地后才能关闭 SEC-009/010。

## 必须通过的验收

- 用户 JWT 调 Agent API、设备凭据调用户 API、A 设备读 B 命令/配置/提交结果全部拒绝；管理员会话也不能冒充 Agent。
- enrollment 过期、重复、并发兑换、目标设备/所有者失效均拒绝；数据库故障不发放凭据。
- 撤销/轮换/禁用后旧凭据立即失败；只影响绑定设备；错误响应、日志和数据库无秘密明文。
- 配置密文篡改、跨设备搬用、密钥缺失、版本冲突均失败且保留上次可用配置。
- 命令重复执行、ACK 丢失、过期租约、Agent/服务端重启可恢复；不重复启动失控进程。
- 在隔离环境启动真实 frps/frpc，验证 TCP/HTTP/HTTPS 连接、退出、重载、断线恢复；不得用模拟在线状态代替隧道证据。
