# 原生文件操作的账户身份边界

本批独立核对 G08 时发现并修复了账户/服务器切换边界，未读取延后的 G01/G02 正式 Review。

## 复现与行为

原文件面板只捕获目录 ID；批量循环在每次入队时读取当前连接。如果选择文件后换了账户或服务器，余下文件可能作为新账户任务登记。同一原生 SessionState 的旧网络请求在新登录后返回 200 时，仍会把旧结果交回调用方；旧 401 则可能撤销新会话。新旧服务器拥有相同数字用户/文件 ID 时，单凭资源 ID 无法隔离这些意图。

新增测试先运行旧行为：两项顶层测试均失败，五类旧选择均进入新服务器队列，旧成功响应被返回，迟到 401 清除了新会话；共 9 条断言/问题。此为 URLProtocol 的可控调度复现，不冒充真实后端端到端证据。最初测试登录响应漏了 token_type，被严格解码拒绝；补齐有效夹具后才得到上述业务失败。

修复后的约定：

- 文件面板打开、拖入及预览开始时捕获规范化服务器地址和用户 ID；批量所有项目使用同一身份，切换后停止余下入队。
- 普通/版本上传下载和预览在存储初始化、书签等异步工作前后重查身份。持久任务继续只归属最初账户；入队不能替换成新连接的身份。没有外部选择阶段的 Core 调用在首次 await 前捕获当前身份。
- FileBrowserState 固定创建时身份，读取返回及新建/改名/移动/复制/回收/恢复前核对。旧窗口闭包不能对新服务器上碰巧同号的资源发起操作。版本状态把其既有固定身份传入队列。
- 账户仍有效但选择已过期时提示“账户或服务器已切换，请重新选择文件或操作”；没有登录时继续报会话失效。
- SessionState 普通 API 请求按完整 SavedSession（含原 token）核对返回结果，旧响应以取消结束；旧 401 不清理取代它的新登录。
- 传输错误观察同时核对账户身份和实际请求 token。同一账户重新登录取得新 JTI 后，旧传输 401 也不能撤销新登录；当前 token 的 401 仍会清理失效会话。
- 调度器在取得请求上下文时核对其身份与任务一致，run 入口再次检查。暂停/取消在等待活动任务之前捕获原请求上下文，避免等待之后改取新连接。
- close 取消并等待所有旧工作任务，包含当前账户之外的任务；也等待已开始的入队、恢复/身份同步、调度和控制操作，拒绝关闭过程中新入队/继续，并合并并发 close 的等待，最后才释放 journal。旧任务保留原身份和暂停记录，新账户列表不显示它们。

已经送达服务端的合法旧账户请求可能在注销前完成；客户端不会声称本地切换能够撤回已经提交的事务。后端继续负责每次请求的会话与资源授权，客户端身份边界不能替代它。任务身份按账户/服务器固定，同一账户重新登录仍可明确继续原任务，不持久化 bearer token。

## 验证

五项原生单元/调度回归覆盖五类旧选择、旧窗口写入/读取、跨服务器及同账户重新登录的迟到 200/401、旧传输 401 与当前 401 区分、切换后 close 等待阻塞工作任务、已有控制请求未返回时 close 保持等待、关闭期间拒绝新入队、并发 close 共同结束、journal 重新打开及旧任务不可见。使用私有临时目录和内存会话。

新增真实 Swift→TLS/Go/MySQL/Redis 用例使用同一服务器的两个实际账户：切换后五类旧选择在入队前被拒绝，旧窗口写入被拒绝，新账户文件列表不变；重新选择后新账户上传/下载完成且字节一致。该用例本机 0.303s，完整默认账户 9 项真实联调 51.273s，受限账户实际执行 1 项会话、其余 8 项跳过，Go 包装 60.692s。测试用户名由隔离 Go 夹具提供，未增加产品身份切换后门或修改生产数据。

最终普通 Swift 注册 35 项，实际 25 项通过、10 项条件跳过（9 项真实服务及 1 项 Keychain）。验收入口使用最终源码编译并通过签名验证；精确远端 CI 在 PR 中按新提交核对。测试本身不证明所有磁盘/网络故障、所有窗口状态及大规模资源行为均已验收。
