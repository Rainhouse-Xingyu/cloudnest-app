# CloudNest iOS 页面优化方案（标准版）

## 1. 文档信息
- 文档名称：CloudNest iOS 页面优化方案（标准版）
- 文档版本：V1.0
- 编写日期：2026-04-19
- 适用范围：cloudnest_ios 客户端、cloudnest_go 配套接口
- 文档目标：统一产品、设计、研发、测试对 iOS 页面优化改造的范围、规则、实施路径与验收标准

## 2. 项目背景
当前 iOS 端存在以下共性问题：
1. 页面结构与操作入口分散，核心任务链路不够直接。
2. 页面视觉层次不统一，标题、工具栏、状态反馈规则不一致。
3. 文件与媒体预览链路存在性能与体验优化空间。
4. 管理员能力在设置页的信息组织方式可维护性不足。

本次优化目标是在不破坏现有核心流程前提下，完成导航结构补全、交互一致性重构、系统原生能力对齐和管理能力归位。

## 3. 设计原则
1. 层次感：采用大标题到导航标题的滚动收缩体系，建立清晰视觉层级。
2. 和谐感：颜色、图标、卡片、间距、动效遵循统一语义映射。
3. 一致性：同类场景使用相同交互模式，减少用户学习成本。
4. 原生优先：媒体预览、Live Photo、文档浏览优先使用 Apple 原生 API。
5. 性能优先：列表容器懒加载、缩略图边界控制、预览按需加载。
6. 局部渲染优先：输入类交互优先局部状态更新，避免整页重渲染。

## 4. 优化范围

### 4.1 导航结构
1. 在 Tab Bar 增加“照片”模块。
2. 保留并优化：首页、文件、照片、设置。

### 4.2 首页优化

#### 4.2.1 工具栏
1. 左侧标题“首页”：SF Pro，34pt，Bold，支持动态字体。
2. 上滑收缩为中间导航标题：17pt，平滑动画过渡。
3. 保留搜索按钮，移除其他工具按钮。
4. 工具栏与 Tab Bar 使用统一 Liquid Glass 视觉风格。
5. 搜索图标颜色为白色。

#### 4.2.2 内容区
1. 存储空间卡片
- 显示语义：已使用 x / 总容量。
- 总容量为设备真实硬盘容量。
- 使用多色分段进度条展示不同文件类型占比。
- 下方图例与分段颜色一一对应。

2. FRP 概览卡片
- 仅展示连接状态与设备信息。
- 状态分为已连接、断开连接。
- 状态点与文字颜色联动：绿色表示已连接，红色表示断开。
- “FRP设置”文案调整为“FRPC设置”，不显示右箭头。

3. 按钮区
- 删除上传、新建、分享、智能四个按钮。

4. 最近照片
- “查看全部”跳转到照片模块。
- 缩略图固定尺寸并裁剪，禁止越界。

5. 最近文件
- “查看全部”跳转到文件模块。
- 文件前置图标按类型显示。
- 图片显示缩略图，PDF 显示第一页缩略图，其他文档按规则展示语义图标或首屏预览。

### 4.3 文件页优化

#### 4.3.1 工具栏
1. 左侧“文件”大标题，34pt 到 17pt 收缩。
2. 常态按钮：搜索、上传、新建文件夹、更多。
3. 收缩态仅保留搜索、更多。
4. 当前目录上移到工具栏展示，默认路径“/”。
5. 选择能力上移到工具栏，新增列表视图与图标视图切换。

#### 4.3.2 内容区
1. 删除目录树区域，路径层级由工具栏目录表达。
2. 列表布局改用 LazyVStack、LazyHStack。
3. 缩略图取消边框，采用统一尺寸和裁剪规则。
4. onChange 调整为 iOS 17 推荐写法（两参数或零参数闭包）。
5. Live Photo 文件角标：左上角 livephoto 图标加“实况”文字。
6. 删除原独立“选择按钮”。
7. 新增长按操作：
- 通用项使用 contextMenu 展示复制、删除等操作。
- 照片项使用支持 preview 的 contextMenu。
- 文档预览使用 QuickLook 与 quickLookPreview。

### 4.4 照片模块优化（新增）

#### 4.4.1 工具栏
1. 左侧“照片”标题，34pt 到 17pt 收缩，颜色为 primary。
2. 右侧新增排序按钮与选择按钮。
3. 选择按钮点击后切换为 x，进入多选态；再次点击 x 退出。

#### 4.4.2 列表与详情
1. 列表页显示静态帧，来源于 PHImageRequestOptions。
2. Live Photo 缩略图左上角叠加 livephoto 图标。
3. 列表到详情传递 PHAsset。
4. 详情页默认静态图。
5. onAppear 判断是否为 Live Photo。
6. 若为 Live Photo，requestLivePhoto 成功后替换 LivePhotoView 并自动播放一次 full。
7. 长按时再次执行 full 播放。

### 4.5 设置页优化

#### 4.5.1 工具栏
1. 左侧“设置”大标题，34pt 到 17pt 收缩。
2. 右侧搜索仅检索设置域内条目。

#### 4.5.2 管理员模块
1. 用户管理
- 改为 NavigationLink 进入子页面。
- 字段：用户名、密码、可访问路径、是否允许从根路径访问、权限、角色。
- 开启根路径访问后禁用路径输入。
- 页面底部提供创建用户按钮。

2. 速率高峰时段
- 改为 NavigationLink 子页面。
- 限速单位统一为 MB/s。
- 使用 DatePicker，hourAndMinute 与 wheel 样式。
- 提供启用开关。
- 启用后应用高峰时段限速策略。

3. 协作空间
- 改为 NavigationLink 子页面。
- 子页面包含工作空间名称、成员增删、文件权限配置入口。
- 支持针对指定用户配置只读或读写权限。

4. 日志与审计
- 保持现有功能与展示。

### 4.6 FRP 页优化
1. “设备状态”改为“连接状态”，聚焦 frpc 与 frps 的连接健康。
2. 新增日志按钮，可实时查看 frpc 运行日志。
3. 保留添加设备按钮。
4. “新的 frpc 设置”改为“修改当前 frpc 设置”，保存后直接写入 frpc.toml。

### 4.7 全局改动
1. 所有浏览类详情页新增 x 关闭按钮。
2. 保留下滑关闭手势，形成双通道退出。

## 5. 技术实现规范

### 5.1 组件规范
1. 统一大标题导航组件
- 能力：滚动收缩、按钮插槽、路径插槽。

2. 统一缩略图组件
- 能力：固定尺寸、裁剪、占位图、失败态回退。

3. 统一状态组件
- 能力：状态点、语义色、状态文案映射。

### 5.2 接口规范
1. 存储能力接口
- totalCapacity
- usedCapacity
- usageByType

2. FRP 接口
- connectionStatus
- deviceInfo 或 deviceList
- logs stream
- frpc config read/write

3. 文件元数据接口
- fileType
- thumbnail info
- firstPagePreview capability
- isLivePhoto

### 5.3 平台与兼容
1. 最低系统版本与 API 使用保持一致。
2. onChange 统一新闭包写法。
3. 文档预览统一 QuickLook。
4. Live Photo 播放统一 Photos 原生链路。

### 5.4 输入框局部渲染性能规范
1. 所有输入框在键入时仅触发输入组件本身刷新，不触发页面根视图整体刷新。
2. 输入状态需隔离到独立子组件或独立 ViewModel，避免页面级状态被高频更新。
3. 禁止在输入框 onChange 中直接触发全量列表刷新、全页布局重算或全局数据重载。
4. 搜索类输入需使用防抖策略，建议 300ms 到 500ms 后再触发检索请求。
5. 需要在代码评审中验证输入性能路径，确保输入时主线程无明显阻塞。

## 6. 非功能性要求
1. 性能
- 首页首屏可交互时间控制在合理范围。
- 文件列表长滚动无明显卡顿。
- 输入框连续输入时无明显掉帧，且无整页闪动或重绘感。

2. 稳定性
- 缩略图、预览失败需有回退态。
- FRP 日志读取失败需有重试与错误提示。

3. 可维护性
- 模块化拆分，避免页面逻辑臃肿。
- 状态与类型映射集中管理。

## 7. 验收标准
1. 新增照片 Tab 并打通首页入口跳转。
2. 首页、文件、照片、设置均实现大标题收缩。
3. 首页仅保留搜索并完成存储卡片与 FRP 状态可视化。
4. 文件页目录树删除，目录展示上移工具栏。
5. 文件页长按可执行操作，文档支持 QuickLook。
6. 照片页支持多选切换、Live Photo 标识、详情自动播放。
7. 设置页管理员模块全部改为子页面导航。
8. FRP 页支持连接状态展示、实时日志查看、配置写回。
9. 浏览页支持 x 关闭与下滑关闭。
10. 输入框连续输入仅局部更新，不触发页面整体重渲染。

## 8. 风险与决策项
1. 限速单位 MB/s 与 Mbps 需产品统一，默认采用 MB/s。
2. FRP 日志实时方案需确定为 WebSocket、SSE 或轮询。
3. Liquid Glass 在低版本系统需定义降级策略。
4. 文档类首屏预览若依赖服务端能力，需明确后端提供范围。

## 9. 发布与回滚策略
1. 分阶段灰度发布：首页与文件先行，照片和设置管理员能力第二批，FRP 深化能力第三批。
2. 保留开关控制新入口与新交互，可快速回退到旧逻辑。
3. 关键功能发布前通过回归用例与冒烟测试确认。

## 10. 里程碑建议
1. M1：基础框架与视觉统一（1 周）
2. M2：文件与照片核心能力上线（1.5 周）
3. M3：设置管理员能力与 FRP 深化能力上线（1.5 周）
4. M4：联调收口与发布验收（0.5 周）
