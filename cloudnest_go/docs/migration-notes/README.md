# 分功能迁移记录规范

## 目标

该目录用于记录大模块（AI、File、FRP、LivePhoto、Collaboration）的分功能迁移进展。
每次迁移结束后，必须新增一份文档，记录本次“迁移了什么、保持了什么、验证了什么”。

## 文档命名规则

- 文件名格式：`YYYYMMDD-模块名-功能名.md`
- 示例：`20260408-collaboration-workspace-member.md`

## 每次迁移文档必填项

1. 迁移范围
- 模块名
- 功能名
- 相关接口（路由）

2. 本次改动文件
- 列出新增/修改文件

3. 功能不变性声明
- 明确写出：返回结构、状态码、错误文案、权限规则是否保持不变

4. 迁移策略
- 说明是“1:1 下沉”还是“局部抽取”
- 说明 handler/service/storage 的职责变化

5. 验证结果
- gofmt
- go build ./...
- 如有测试则附测试命令

6. 风险与后续
- 本次残留的耦合点
- 下一次迁移建议功能

## 工作约束

- 默认采用“功能不变”迁移，禁止在迁移过程中改变业务行为。
- 若必须调整行为（例如修复明确缺陷），必须先单独确认并在文档中显式标注。
- 每次迁移完成后先写文档，再进入下一个功能。
